## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

1. **How should a page that exists on only one side be represented?**
   - Answer: Empty missing-side content, with the missing side's page name set to exactly `[DOES NOT EXIST]`.
2. **What should happen when graph mutations produce no printable page differences?**
   - Answer: Skip the modal and report that there are no reviewable changes.
3. **How should multiple page diffs be ordered?**
   - Answer: Preserve the transaction tracker's first-seen changed-page order.

### 2.2 Final Summarized Requirements

- Replace the aggregate printer string with structured, ordered per-page snapshots containing stable identity metadata, existence, display name, and content.
- Pair the before and after snapshots into logical page changes, including aliases/renames and newly created, deleted, soft-deleted, empty, or unresolved pages.
- Render exactly one `DiffViewer` per changed logical page. Supply before/after page names through `oldFile.name` and `newFile.name`; do not include headings or missing-page markers in content.
- Represent a nonexistent side as `{name: "[DOES NOT EXIST]", content: ""}` so creation and deletion appear as all-added/all-deleted diffs.
- Keep page properties at the start of active-page content and block properties before block content.
- Correctly split and indent multiline property values, including CRLF input, at page and nested-block depths.
- Explicitly pass `language="markdown"` and `showStats={true}` to every viewer.
- Remove the modal's internal aggregate-string equality branch. Determine reviewability before opening the modal; if no paired page changes remain, do not open it, leave the graph reverted, clear the no-op tracker, persist the cleared artifact, and report that no reviewable changes are available.
- Preserve current commit, discard, modal-close, snapshot-failure, and revert-failure guarantees.

## 3. Existing System

### 3.1 Snapshot generation

- `src/core/logseq-reversible-transaction-tracker/LogseqPageDataPrinter.ts`
  - `print(PageIdentity[])` currently resolves identities, deduplicates active pages by UUID and unresolved pages by identity, then joins all pages into one string.
  - Missing pages become a synthetic heading plus `<Page not found>`.
  - `printPageTree` prepends `# ${page.originalName ?? page.name}` and reduces soft-deleted pages to that heading.
  - Page properties are emitted as the first bullet; block properties precede block content. Nested block depth uses four spaces and continuation lines use the depth indentation plus two spaces.
  - `getPropertyLines` returns one array element per property even when the formatted value contains embedded newlines. `printBullet` therefore cannot indent those embedded lines.
- `isPageSoftDeleted` identifies Logseq soft deletion through `:logseq.property/deleted-at`. A soft-deleted page can still resolve by UUID, which is important for correlating creation/deletion snapshots.
- The transaction tracker stores ordered string identities and preserves first-seen order. Commands can add aliases as separate identities; notably, rename records both the stable page UUID and the new name.

### 3.2 Review preparation and lifecycle

- `src/chat-app/tools/impl/LogseqCommitChangesTool.tsx`
  - `prepareReview` executes pending commands, captures the aggregate after string, reverts commands, then captures the aggregate before string from the same changed identity list.
  - After a successful preparation, the reverted tracker is persisted before opening the modal.
  - Modal result `true` re-executes and commits; `false` clears/discards; `null` leaves the reverted changes available.
  - A failure while taking the after snapshot attempts a revert. A failed revert is wrapped in `DiffRevertFailedError`, causes the tracker to be cleared, and reports that changes were discarded. Other preparation failures retain the reverted tracker.
  - Existing mutation-count and applied-mutation checks are not content-level no-diff checks. Consequently, equal printable snapshots can currently reach the modal.

### 3.3 Modal flow

- `src/ui/launchers/showAIChangesReviewModal.ts` currently accepts two strings and forwards them to the component.
- `src/ui/pages/AIChangesReviewModal.tsx` compares the strings, otherwise renders one synthetic `Before -> After` `DiffViewer` for the complete aggregate.
- `DiffViewer` accepts names inside `oldFile`/`newFile`; `showStats` defaults to true but is not explicit. Its inherited `language` prop is accepted, although the current custom viewer does not visibly syntax-highlight from that prop.

### 3.4 Tests and constraints

- `tests/src/core/logseq-reversible-transaction-tracker/LogseqPageDataPrinter.test.ts` asserts exact multiline printer output but currently assumes page headings and aggregate strings.
- `tests/src/chat-app/tools/impl/LogseqCommitChangesTool.test.ts` covers direct approval/cancellation only; it does not cover review snapshot preparation or modal dispatch.
- Vitest currently includes `**/*.test.ts`, not `.test.tsx`, and the project has no React Testing Library dependency. UI boundary tests should therefore use a `.test.ts` pure/helper or mocked-element approach rather than introducing a new test framework/configuration solely for this refactor.

## 4. Solution

### 4.1 Define a shared structured page-review model

Modify `src/core/logseq-reversible-transaction-tracker/LogseqPageDataPrinter.ts` and export its new types from `src/core/logseq-reversible-transaction-tracker/index.ts`.

Use an ordered observation type for each input identity:

```ts
interface LogseqPrintedPageSnapshot {
    identityKey: string;
    resolvedPageUuid: string | null;
    exists: boolean;
    pageName: string;
    content: string;
}
```

Use a UI-ready paired type:

```ts
interface LogseqPrintedPageChange {
    key: string;
    before: {pageName: string; content: string};
    after: {pageName: string; content: string};
}
```

Define and reuse `NON_EXISTENT_PAGE_NAME = "[DOES NOT EXIST]"`. A canonical absent side always has that name and empty content. Keep UUID metadata for a resolved soft-deleted page even though `exists` is false; that UUID is needed to pair it with its active state.

### 4.2 Return ordered snapshots from `LogseqPageDataPrinter.print`

Change `print` to return `Promise<LogseqPrintedPageSnapshot[]>`.

For every input identity, in original order:

1. Compute `identityKey` with the existing identity stringification rule.
2. Resolve the page with `LogseqPropertiesHelper.getPage`.
3. If unresolved, append a canonical absent snapshot with no UUID.
4. If soft-deleted, append a canonical absent snapshot while retaining its UUID; do not fetch blocks.
5. If active, use `page.originalName ?? page.name`, fetch its block tree, and append an existing snapshot with content only.

Retain one observation per input identity rather than independently deduplicating either snapshot. Add a per-call cache keyed by resolved UUID so repeated UUID/name aliases preserve their ordered observations but only fetch and print the same active page tree once.

An active empty page has `exists: true` and `content: ""`; existence must not be inferred from content or block count.

### 4.3 Print content without page headings and fix multiline properties

Refactor `printPageTree` to handle active-page content only:

- Remove the `# page name` line.
- Move soft-deletion handling to `print`; `printPageTree` is not called for absent pages.
- Keep page properties as the first top-level bullet, then root blocks in Logseq order.
- Preserve block properties before the block's content and preserve existing four-space child indentation.

Make `getPropertyLines` flatten each formatted property into physical lines using `/\r?\n/` after prefixing the first line with `${key}:: `. This allows `printBullet` to add its normal continuation indentation to every subsequent line. Continue excluding `uuid`, preserve property enumeration order, and retain current scalar/array/object serialization.

Expected shape:

```md
* apple:: line 1
  line 2
* blockprop:: value
  block content line 1
  block content line 2
```

At nested depth, each continuation receives that depth's four-space indentation plus two spaces, aligning with text after `* `.

### 4.4 Pair before/after observations into logical page changes

Add a pure `LogseqPageDataPrinter.createChanges(before, after)` function returning ordered `LogseqPrintedPageChange[]`.

- Require equal snapshot lengths because both captures use the same immutable changed identity list; throw a descriptive internal error on mismatch.
- Begin with one logical group per identity index.
- Merge groups whenever any before or after observation shares a non-null resolved UUID. A small union-find/disjoint-set or equivalent map-based grouping will handle UUID/name aliases and rename chains without state-dependent duplicate missing-page rows.
- Materialize groups by their lowest original identity index to preserve tracker order.
- For each side of a group, choose the first `exists: true` observation in changed-page order; if none exists, use the canonical nonexistent side.
- Use an index-derived stable React key such as `changed-page-${lowestIndex}`, never a mutable page name.
- Remove unchanged groups where both `pageName` and `content` are exactly equal. Do not trim, sort, or case-normalize at comparison time.

This produces:

- ordinary edit: `Page -> Page` with changed content;
- rename: `Old Name -> New Name`, even if content is unchanged;
- creation: `[DOES NOT EXIST] -> New Page` with empty old content;
- deletion: `Old Page -> [DOES NOT EXIST]` with empty new content;
- empty-page creation/deletion: retained because names/existence differ;
- missing identity on both sides: removed;
- UUID plus rename alias: one logical diff rather than an extra missing-page diff.

### 4.5 Refactor commit review preparation and no-diff handling

In `src/chat-app/tools/impl/LogseqCommitChangesTool.tsx`, replace the repeated inline string result with a discriminated internal result:

```ts
type PreparedReview =
    | {kind: "no-graph-mutations"}
    | {kind: "no-reviewable-page-changes"}
    | {kind: "reviewable-page-changes"; changes: LogseqPrintedPageChange[]};
```

Update `prepareReview` to:

1. Execute the tracker.
2. Return `no-graph-mutations` if no mutation was applied.
3. Capture `changedPages` once, then use that exact ordered list for both states.
4. Print after snapshots.
5. Revert all applied commands.
6. Print before snapshots.
7. Pair/filter them with `createChanges`.
8. Return `no-reviewable-page-changes` for an empty result; otherwise return the structured changes.

Update `reviewAndCommit` handling:

- Preserve the current `no-graph-mutations` approval/no-op path.
- Persist the reverted tracker before opening a nonempty review, as today.
- For `no-reviewable-page-changes`, do not call the modal and do not call `executeApprove` (which would silently reapply mutations that the user did not see). Clear the already-reverted tracker, persist the cleared artifact when a located tracker exists, and add a successful result such as `No reviewable page changes are available to commit.`
- Keep the current true/false/null modal semantics.
- Preserve snapshot/revert error recovery. A pairing invariant failure occurs after successful reversion and therefore follows the “uncommitted changes remain available” path. A failed revert still clears/persists the tracker and reports discard.
- Update local names/messages from aggregate “diff” terminology to “review snapshot” where this does not alter externally tested behavior.

### 4.6 Pass and display per-page changes

Modify `src/ui/launchers/showAIChangesReviewModal.ts`:

- Accept a nonempty `LogseqPrintedPageChange[]` instead of two strings.
- Forward `changes` to the modal unchanged.

Modify `src/ui/pages/AIChangesReviewModal.tsx`:

- Replace `beforeChanges`/`afterChanges` props with `changes`.
- Remove the aggregate equality branch and “No uncommitted changes” fallback; the caller guarantees reviewable input.
- Map over `changes` in order and render one viewer per page:

```tsx
<DiffViewer
    key={change.key}
    oldFile={{name: change.before.pageName, content: change.before.content}}
    newFile={{name: change.after.pageName, content: change.after.content}}
    language="markdown"
    showStats={true}
    viewMode="split"
    size="sm"
    showLineNumbers={false}
    showIcon={false}
    variant="ghost"
/>
```

- Retain the current visual style and scrolling behavior, applying spacing and border/background styling per viewer so pages are visibly separate. Keep modal footer actions and close behavior unchanged.
- Do not modify the custom `DiffViewer` as part of this task. `language` is passed explicitly as required, while visible syntax-highlighting support remains outside scope.
