### 3.2 Runtime, transactions, and persistence

- App renders inside an open ShadowWrapper and the real assistant-ui LocalRuntime with local history/thread-list adapters. Model follow-up after an automatic tool appends to the **same assistant message**.
- `executeFrontendToolPlan` awaits tools in emitted order. Fresh execution context messages include earlier completed tool results/artifacts.
- Registry construction binds tool execute methods. Install prototype spies **before mounting**.
- `ThreadStore.updateThread`, `loadThread`, `listThreads`, and `deleteThread` are the persistence APIs. Isolate the existing facade with a per-test `InMemoryStore`; do not duplicate reads with another store abstraction.
- `ExportedMessageRepository.fromBranchableArray(nodes,{headId})` is public. Supply parent-before-child nodes and an explicit **leaf** head: import/resetHead can prune descendants of a non-leaf head.
- Previous/Next changes runtime selection without persisting the selected head. Assert visible content/counters for selection; inspect persistence for unchanged topology and updated rollback artifacts. Do not claim a stored head represents the current selection after navigation alone.
- The branch guard reverts the **whole selected branch's latest cumulative applied tracker** after confirmation. Commands are retained, with applied count zero; it does not discard them or automatically replay on navigation.
- Successful commit boundary requires `success: true, outcome: "committed"`; failed/no-changes commits do not lock history. Boundary ends before the next user turn.
- Review preparation prints after state, reverts changes, prints before state, then opens review. Approval replays and clears the tracker. Closing leaves commit pending; reject clears; defer stops the turn.
- `LogseqClearUncommittedChangesTool.tsx` already has `display = "standalone"` and a ToolFallback renderer. Assistant grouping already recognizes standalone tools.
- DB deletion can be soft deletion; use `isPageSoftDeleted`, not only null checks.

### 4.2 Scripted model and controlled pauses

`mock-language-model/types.ts` is warranted because factory and builders share these unions. One step equals one provider call, not necessarily one UI message:

```ts
type ToolCallSpec = {toolCallId: string; toolName: string; input: Record<string, unknown>};
type WaitSegment = {type: "wait"; until: Promise<void>; onReached?: () => void};
type Segment =
  | {type: "text" | "reasoning"; chunks: readonly (string | WaitSegment)[]}
  | {type: "tool-calls"; calls: readonly ToolCallSpec[]}
  | WaitSegment;
type ModelStep = {segments: readonly Segment[]; finishReason?: LanguageModelV4FinishReason["unified"]};

textSegment(text: string | readonly (string | WaitSegment)[]): Segment;
reasoningSegment(text: string | readonly (string | WaitSegment)[]): Segment;
toolCallsSegment(calls: readonly ToolCallSpec[]): Segment;
waitSegment(until: Promise<void>, onReached?: () => void): WaitSegment;

createMultiTurnMockLanguageModel(steps: readonly ModelStep[]): MockLanguageModelV4 & {
  assertHealthy(): void;
  dispose(): Promise<void>;
};
```

- Builders return descriptions only. Tests use `{segments: [textSegment("response")]}`; two tool calls belong in one `toolCallsSegment`.
- Factory uses functional `doStream(options)`, creating each stream lazily. Emit matching deterministic text/reasoning start/delta/end IDs, stringify tool input, then exactly one finish event with V4 usage and `{unified,raw:undefined}`. Default finish is tool-calls when tools exist, otherwise stop.
- An async producer awaits each wait segment; `onReached` signals deterministic checkpoint arrival. No sleeps, string names, maps, gate-registration APIs or duplicate-gate machinery.
- Observe provider abort signal, reader cancellation, and factory-owned shutdown. Cancellation interrupts held waits and prevents further enqueues. Remove listeners on normal release, rejection, and abort.
- If the script is exhausted, record and throw an error identifying call index and step count. `assertHealthy()` fails teardown for unexpected model errors swallowed into error bubbles. Expected cancellation is not a fixture failure.
- Validate unique scripted call IDs and nonempty tool batches. Explicit step finish override is supported for unusual tests; unnecessary protocol abstractions are not added.

### 4.3 Generic passthrough method observation

`chat-scenario/createToolPassthroughSpy.ts` accepts any asynchronous method target, not a hardcoded tool class:

```ts
type AsyncMethod = (...args: any[]) => Promise<any>;
type ObservedCall<F extends AsyncMethod, Snapshot> = {
  ordinal: number;
  args: Parameters<F>;
  snapshot: Snapshot;
  state: "entered" | "fulfilled" | "rejected";
  result?: Awaited<ReturnType<F>>;
  error?: unknown;
};
createToolPassthroughSpy<T, K extends AsyncMethodKeys<T>, S>(
  target: T, method: K, options?: {
    snapshot?: (args: Parameters<T[K]>, receiver: T) => S;
    beforeCall?: (call: ObservedCall<T[K], S>, shutdownSignal: AbortSignal) => Promise<void>;
  }
): {
  calls: readonly ObservedCall<T[K], S>[];
  events: readonly {ordinal: number; phase: "start" | "end"}[];
  maxInFlight: number;
  dispose(): Promise<void>;
  restore(): void;
};
```

Use constrained generics/derived Parameters/ReturnType in actual implementation; no untyped result casts at call sites. Sketch uses `any` only to express an arbitrary callable.

- `vi.spyOn(target,method)` uses a normal function preserving `this` and calls the saved original with unchanged arguments. Exact original response is returned; actual errors are rethrown.
- Record entry before waiting; completion only after original settlement. Track original pending invocations separately from adapter cancellation.
- Snapshot is supplied by the caller (e.g. clone `context.messages`); generic helper never assumes argument positions or Logseq result structure.
- `beforeCall` supports controlled pauses. Callers combine context abort and helper shutdown when awaiting their release promise.
- `dispose()` aborts blocked waits and awaits underlying work; `restore()` occurs only afterwards. No automatic gate release on teardown.
- Fixture cleanup can register `dispose/restore` for any spy, including create page, commit review preparation, or another future async tool method. Install execute spies before mount because registry captures bound references.

Sequential scenario uses this generic helper with `LogseqCreatePageTool.prototype`, `"execute"`, snapshot of `args[1]?.messages`, and a checkpoint for ordinal 1. The helper itself imports no specific tool class.
