## 3. Existing System

- `vite.config.ts`: Vitest 5.0.1 browser project `e2e`, headless Chromium through Playwright 1.63, 1280x720; includes `tests/**/*.e2e.test.{ts,tsx}`. Poll timeout 10 seconds; files parallel by default.
- `tests/setup.ts` uses the HTTP Logseq proxy and initializes plugin storage. `LOGSEQ_API_SERVER` defaults to `http://127.0.0.1:12315`; token is optional via `LOGSEQ_API_TOKEN`. A live DB graph is required for these suites, including shared setup.

- `tests/helpers/mockLanguageModel.ts`: eager streams, one text or tool call per response; only the existing fixture consumes it. Migrate its caller, then remove the old file instead of maintaining an unnecessary compatibility shim.
- `createChatApp.tsx` dynamically imports App. `mountLauncher.tsx` mounts the actual launcher, resets UI between mounts, and returns the modal container, unmount function, and pending close-result promise. Reuse both.
- Vitest supports `page.viewport(w,h)`, locator nesting/filtering, `page.elementLocator(element)`, and **`toBeInViewport({ratio: 1})`**. The latter uses native IntersectionObserver; pair it with `toBeVisible()`. No external geometry dependency is necessary.

### 3.2 Runtime, transactions, and persistence

- App renders inside an open ShadowWrapper and the real assistant-ui LocalRuntime with local history/thread-list adapters. Model follow-up after an automatic tool appends to the **same assistant message**.
- `executeFrontendToolPlan` awaits tools in emitted order. Fresh execution context messages include earlier completed tool results/artifacts.
- Registry construction binds tool execute methods. Install prototype spies **before mounting**.
- `ThreadStore.updateThread`, `loadThread`, `listThreads`, and `deleteThread` are the persistence APIs. Isolate the existing facade with a per-test `InMemoryStore`; do not duplicate reads with another store abstraction.
- `ExportedMessageRepository.fromBranchableArray(nodes,{headId})` is public. Supply parent-before-child nodes and an explicit **leaf** head: import/resetHead can prune descendants of a non-leaf head.
- Previous/Next changes runtime selection without persisting the selected head. Assert visible content/counters for selection; inspect persistence for unchanged topology and updated rollback artifacts. Do not claim a stored head represents the current selection after navigation alone.
- The branch guard reverts the **whole selected branch's latest cumulative applied tracker** after confirmation. Commands are retained, with applied count zero; it does not discard them or automatically replay on navigation.
- Successful commit boundary requires `success: true, outcome: "committed"`; failed/no-changes commits do not lock history. Boundary ends before the next user turn.
- Review preparation prints after state, reverts changes, prints before state, then opens review. Approval replays and clears the tracker. Closing leaves commit pending; reject clears; defer stops the turn.
- `LogseqClearUncommittedChangesTool.tsx` already has `display = "standalone"` and a ToolFallback renderer. Assistant grouping already recognizes standalone tools.
- DB deletion can be soft deletion; use `isPageSoftDeleted`, not only null checks.

### 3.3 Existing patterns to follow

### 4.2 Scripted model and controlled pauses

`mock-language-model/types.ts` is warranted because factory and builders share these unions. One step equals one provider call, not necessarily one UI message:

```ts
type ToolCallSpec = {toolCallId: string; toolName: string; input: Record<string, unknown>};
type WaitSegment = {type: "wait"; until: Promise<void>; onReached?: () => void};
type Segment =
  | {type: "text" | "reasoning"; chunks: readonly (string | WaitSegment)[]}
  | {type: "tool-calls"; calls: readonly ToolCallSpec[]}
  | WaitSegment;
type ModelStep = {segments: readonly Segment[]; finishReason?: LanguageModelV4FinishReason["unified"]};

textSegment(text: string | readonly (string | WaitSegment)[]): Segment;
reasoningSegment(text: string | readonly (string | WaitSegment)[]): Segment;
toolCallsSegment(calls: readonly ToolCallSpec[]): Segment;
waitSegment(until: Promise<void>, onReached?: () => void): WaitSegment;

createMultiTurnMockLanguageModel(steps: readonly ModelStep[]): MockLanguageModelV4 & {
  assertHealthy(): void;
  dispose(): Promise<void>;
};
```

- Builders return descriptions only. Tests use `{segments: [textSegment("response")]}`; two tool calls belong in one `toolCallsSegment`.
- Factory uses functional `doStream(options)`, creating each stream lazily. Emit matching deterministic text/reasoning start/delta/end IDs, stringify tool input, then exactly one finish event with V4 usage and `{unified,raw:undefined}`. Default finish is tool-calls when tools exist, otherwise stop.
- An async producer awaits each wait segment; `onReached` signals deterministic checkpoint arrival. No sleeps, string names, maps, gate-registration APIs or duplicate-gate machinery.
- Observe provider abort signal, reader cancellation, and factory-owned shutdown. Cancellation interrupts held waits and prevents further enqueues. Remove listeners on normal release, rejection, and abort.
- If the script is exhausted, record and throw an error identifying call index and step count. `assertHealthy()` fails teardown for unexpected model errors swallowed into error bubbles. Expected cancellation is not a fixture failure.
- Validate unique scripted call IDs and nonempty tool batches. Explicit step finish override is supported for unusual tests; unnecessary protocol abstractions are not added.

Example shimmer checkpoint:

```ts
const reached = Promise.withResolvers<void>();
const release = Promise.withResolvers<void>();
model.respondWith([{segments: [textSegment([
  "Streaming prefix ", waitSegment(release.promise, reached.resolve), "complete."
])]}]);
await driver.sendMessage("Continue");
await reached.promise;
// Stream stays open while history/shimmer is inspected.
release.resolve();
```

`tests/helpers/waitForPromiseOrAbort.ts` provides only:

```ts
waitForPromiseOrAbort<T>(promise: Promise<T>, signal: AbortSignal): Promise<T>;
```

Reject immediately for an already-aborted signal; use AbortError and remove listeners on every settlement path. The model and generic spy share it. This is the necessary cancellation behavior that a plain promise lacks; it replaces proposed `gates.ts` rather than renaming that registry.

### 4.3 Generic passthrough method observation

`chat-scenario/createToolPassthroughSpy.ts` accepts any asynchronous method target, not a hardcoded tool class:

```ts
type AsyncMethod = (...args: any[]) => Promise<any>;
type ObservedCall<F extends AsyncMethod, Snapshot> = {
  ordinal: number;
  args: Parameters<F>;
  snapshot: Snapshot;
  state: "entered" | "fulfilled" | "rejected";
  result?: Awaited<ReturnType<F>>;
  error?: unknown;
};
createToolPassthroughSpy<T, K extends AsyncMethodKeys<T>, S>(
  target: T, method: K, options?: {
    snapshot?: (args: Parameters<T[K]>, receiver: T) => S;
    beforeCall?: (call: ObservedCall<T[K], S>, shutdownSignal: AbortSignal) => Promise<void>;
  }
): {
  calls: readonly ObservedCall<T[K], S>[];
  events: readonly {ordinal: number; phase: "start" | "end"}[];
  maxInFlight: number;
  dispose(): Promise<void>;
  restore(): void;
};
```

Use constrained generics/derived Parameters/ReturnType in actual implementation; no untyped result casts at call sites. Sketch uses `any` only to express an arbitrary callable.

- `vi.spyOn(target,method)` uses a normal function preserving `this` and calls the saved original with unchanged arguments. Exact original response is returned; actual errors are rethrown.
- Record entry before waiting; completion only after original settlement. Track original pending invocations separately from adapter cancellation.
- Snapshot is supplied by the caller (e.g. clone `context.messages`); generic helper never assumes argument positions or Logseq result structure.
- `beforeCall` supports controlled pauses. Callers combine context abort and helper shutdown when awaiting their release promise.
- `dispose()` aborts blocked waits and awaits underlying work; `restore()` occurs only afterwards. No automatic gate release on teardown.
- Fixture cleanup can register `dispose/restore` for any spy, including create page, commit review preparation, or another future async tool method. Install execute spies before mount because registry captures bound references.

Sequential scenario uses this generic helper with `LogseqCreatePageTool.prototype`, `"execute"`, snapshot of `args[1]?.messages`, and a checkpoint for ordinal 1. The helper itself imports no specific tool class.

### 4.4 Fixture design, mounting, and teardown

Extended test surface:


**Model fixture:** retain existing injection seam and `yield* runLocalAISDKChatModel(options,()=>languageModel)`. Record run entry messages/config and unstable thread/assistant IDs when supplied. Hoisted `generateTitle` mock returns an immediate deterministic title; saved title is verified with ThreadStore polling. No deferred-title API is needed for streaming shimmer.

**Storage fixture:** save old backing store, install uniquely namespaced InMemoryStore, seed through ThreadStore.updateThread. Read/list directly through ThreadStore in tests and assertion helpers. Restore only after all work is settled; clear only that store instance.

**Settings:** use LogseqSettingAccessor and production `formatSelectedModelId` to select the first enabled test provider/model from `src/tests/constants.ts` and medium effort. Existing two providers give two known options. Save and restore controlled fields after unmount and pending settings updates finish. Do not access logseq.settings directly.

**Live DB prerequisite:** automatic fixture asserts both availability globals and a fresh DB graph check. Include actionable server/graph guidance; no all-skipped green run.

**Mounting uses the existing helpers:**

```ts

```

Explicit mount allows data/model/spies configuration first. Wait for visible Message input and selected-model trigger; verify actual model config on the first recorded run. Never await `mounted.result` for readiness: it is the close result.

**Teardown order:** composition must explicitly depend on storage/model/cleanup before chat so chat shuts down first. Use try/finally from partial setup onward and accumulate cleanup errors so later restoration still runs.

1. Cancel open branch confirmation or close open review; never approve during cleanup.
2. Stop pending/active current thread via real Stop if available. If history is open, return to the known thread before stopping when possible.
3. Abort helper-held waits/model streams; unmount with `mounted.unmount()` so LocalRuntime detach also aborts background runtimes.
4. Await tracked adapters, original tool calls and review-preparation operations; review preparation is graph work outside the ordinary adapter. Observe preparation through the generic spy where necessary, and register its settlement cleanup.
5. Drain immediate title wrappers and already queued storage operations after producers stop. A per-known-thread `ThreadStore.updateThread(...type:"skip")` barrier waits for queued writes; it cannot substitute for stopping producers first.
6. Perform graph cleanup and restore spies. Restore viewport to 1280x720 and settings; clear/restore isolated storage last.

Do not resolve blocked tool checkpoints to finish teardown: that could start mutations after a failed test. Cancellation is necessary, and late release must not resume original execution.

```ts
  expandTool(message: Locator, name: string, occurrence?: number): Promise<Locator>;
  addAttachment(uuid: string, label: AttachmentLabel, expectedName: string): Promise<void>;
  confirmModal(choice: "revert-and-switch" | "cancel"): Promise<void>;
  reviewAndCommit(action?: "commit" | "discard" | "defer" | "close"): Promise<void>;
};
```

Driver scopes to `page.elementLocator(container)`, never generated IDs. Prefer getByRole/getByText/filter. Message roots use existing data-slot only because they are unnamed divs. Read counter text within the intended message; Previous/Next by name, not picker class. Hover exposes Edit; re-find edit wrapper after root replacement.

Send waits for the new user message/composer clearing, **not completion**, preserving streaming tests. openThread verifies destination-specific content and old content absence, not only composer readiness; active-row aria-current supplies a second switching check.

Dialog scope comes from exact confirmation text or review heading and corresponding panel; no `.ui__confirm-modal`, IDs or invented dialog role. Review action is a combobox, not getByRole(button). Branch/refresh/edit helpers never silently confirm; tests explicitly choose outcome.

Where CSS is needed for existing data-slot, use supported Vitest `locators.extend` selector helper, centralized in driver. Avoid deep structural selectors for ordinary interactions; minimal parent traversal is acceptable for unnamed layout containers. If genuinely useful accessibility labels are needed, add narrow semantic improvements with regressions rather than styling selectors; do not introduce roles without appropriate behavior.

### 4.7 Visibility uses installed browser matchers

```ts
await expect.element(target).toBeVisible();
await expect.element(target).toBeInViewport({ratio: 1});
```

Native intersection handles ordinary clipping; no custom composed-ancestor traversal, floating-library geometry oracle, or new library. Intersection is not an occlusion/pixel guarantee, so do not claim it proves every painted pixel is unobstructed.

For explicit modal containment or width compare getBoundingClientRect inside expect.poll (re-resolve locator each time), allowing ~1px rounding. Keep targeted comparisons inline initially. If repeated, extract a tiny assertion into assertions.ts, not a geometry subsystem.

Tooltip semantic role is on a hidden accessibility span. Assert its text semantically, then measure its enclosing painted `[data-side]` content: full intersection and top placement relative to Send. Menus/model popups are checked before actions that might auto-scroll them into view. Restore viewport after wide/narrow/short cases.

## 5. Verification

### 5.1 How actual execution is established

Use independent layers rather than trusting scripted model prose:

1. UI shows actual tool success/error and expanded result.
2. Persisted matching toolCallId contains actual response and transaction artifact; topology/follow-up shares one assistant message.
3. Live graph has the returned UUID/name active after creation/approval or absent/soft-deleted after rollback/clear. Built-in Page is unchanged on failure.
4. Next model request contains the actual tool result (success JSON object or error-text), showing automatic continuation used it.
5. Sequential scenario additionally instruments **execute entry**, not merely graph API mutations (tracker's own lock could mask concurrency), proves held-first/no-second-entry, exact start/end ordering, max concurrent entry=1 and fresh second-call context.

### 5.2 Infrastructure regressions

- Model: mixed reasoning/text, same-step multiple calls, lazy independent streams, release-before-arrival, abort before/during held wait, reader cancellation/dispose, no resumption after late release, script exhaustion with actionable failure, no outstanding listeners/unhandled rejections.
- Generic spy: preserves receiver/args/actual returned response and exceptions, supports more than one tool prototype/method, snapshots at entry, tracks overlap accurately, disposes held calls without invoking original, awaits actual work before restore.
- Histories: parent validation, unique IDs, leaf heads, deterministic sibling numbering/timestamps, attachment shapes generated by real factory.
- Fixture smoke cases: failure before mount/partial mount, unmount idempotency, model/title/storage settlement, graph cleanup despite failure, viewport/settings/store restored, no late mutation after held checkpoint abort.
