# AI Changes Review Action Selector Plan

## 1. User Requirement

Currently in AIChangesReviewModal.tsx, the footer contains 3 buttons that do three different things. This will be confusing for user. Instead, we should add a select box beside the Confirm containing:
Approve and Commit
Commit Later
Reject and Revert Changes

Instead of three buttons, we will have Confirm button only. Clicking the confirm button will do things based on the select box.

Notes: 
- Select box should open upwards. Check if there is an existing component.
- Approve and Commit will behave same as how it worked when Confirm was clicked before our changes. Commit Later same as COntinue (Commit Later). Revert and Reject Changes same as reject. [No change in what it does]
- The close icon on header should remain after changes for simply close the modal.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

1. **Question:** Which option should be selected when the modal opens (and therefore run if the user immediately clicks Confirm)?
   **Answer:** Approve and Commit.
2. **Question:** Which exact reject option label should be used?
   **Answer:** `Reject and Revert Changes`.
3. **Question:** Should the selector always open upward or prefer upward and flip when there is insufficient room?
   **Answer:** Prefer upward and collision-flip when necessary.
4. **Question:** What should replace `Commit Later` as option 3, including its internal result value?
   **Answer:** Use `Defer Commit` and rename the result to `"defer-commit"`.

### 2.2 Final Summarized Requirements

- Replace the three footer action buttons with one action selector beside one primary `Confirm` button.
- Present these options in this order:
  1. `Approve and Commit` (initial selection)
  2. `Reject and Revert Changes`
  3. `Defer Commit`
- Selecting an option only changes the pending action. Clicking `Confirm` executes the selected action.
- Preserve the existing result contract and behavior exactly:
  - `Approve and Commit` -> `"commit"`
  - `Reject and Revert Changes` -> `"discard"`
  - `Defer Commit` -> `"defer-commit"`
- Prefer opening the selector above its trigger and allow it to flip below when the available space requires it.
- Preserve the header close icon and its current simple-close behavior: resolve `null`, close the modal, and do not commit, defer through the Defer Commit pathway, or reject/revert changes.
- Preserve Escape-to-close when the selector is closed and outside-click protection for the modal.

## 3. Existing System

### 3.1 Modal and footer behavior

- `src/ui/pages/AIChangesReviewModal.tsx` defines `AIChangesReviewResult` as `"commit" | "discard" | "continue-later" | null`.
- `AIChangesReviewModalFooter` currently renders three `LogseqButton` controls and maps them directly to three callbacks:
  - `Continue (Commit Later)` -> `handleConfirm("continue-later")`
  - `Commit changes` -> `handleConfirm("commit")`
  - `Discard uncommitted changes` -> `handleConfirm("discard")`
- `AIChangesReviewModalComponent` uses `useModal`; `handleConfirm(result)` resolves the modal promise and closes it.
- The current `useModal` configuration enables document-level Enter handling with `defaultResult: "discard"`. This is incompatible with a custom keyboard-accessible selector because Enter could both select an option and invoke the modal default. Its Arrow Up/Down handling can also scroll the diff while a selector is being navigated.

### 3.2 Close behavior

- The visible header X is supplied by `src/ui/modals/core/ModalHeader.tsx`, not by the generic `Modal` close button.
- It invokes `handleCancel()`, which resolves `null` and closes the modal. This leaves the action unresolved rather than mapping the close to any footer action.
- Escape currently follows the same `null` path. Overlay clicks do not close this modal because `enableOutsideClickClose` is false.

### 3.3 Downstream result behavior

- `src/ui/launchers/showAIChangesReviewModal.ts` returns the modal result without translating it.
- `src/chat-app/tools/impl/LogseqCommitChangesTool.tsx` already implements all required behaviors:
  - `"commit"` approves and executes queued changes.
  - `"continue-later"` retains changes and stops the pending turn with the existing commit-defer message.
  - `"discard"` cancels the transaction and clears/reverts queued changes.
  - `null` returns without resolving the pending tool action.
- Preserve that branch's behavior while renaming its result discriminator from `"continue-later"` to `"defer-commit"` consistently in the modal and commit-tool switch. No transaction operations should change.

### 3.4 Existing selector/popover components

- `src/ui/components/LogseqSelect.tsx` wraps a native `<select>`. Native popup placement is controlled by the browser/OS, so it cannot meet the upward-placement requirement reliably.
- `src/ui/components/LogseqPopover.tsx` supports Floating UI placements and flipping, but is hover-only and lacks click, focus, listbox, and keyboard behavior.
- `src/ui/components/LogseqDropdownMenu.tsx` inherits those hover-only limitations and has no active production usage suitable for this modal.
- The UI guidelines direct dropdown positioning to `@floating-ui/react`, which is already installed. A local selector is the smallest safe scope; changing the shared hover popover would broaden behavior for unrelated consumers.
- `Modal` uses `focus-trap-react`, so keeping the selector popup inline in the modal subtree avoids focus-trap problems caused by a body-level portal.

### 3.5 Tests and constraints

- `tests/src/ui/pages/AIChangesReviewModal.test.ts` currently checks diff icons and inspects the old footer's three-button React tree directly.
- The footer will own selection/open state, so its tests should render into jsdom with `createRoot` and `act`, following existing interactive component tests such as `tests/src/chat-app/components/ThreadTopToolBar.test.ts`.
- Vitest discovers `.test.ts` files under jsdom. Pure UI tests should not require the live Logseq proxy.
- Project completion checks require focused/full tests, `npx tsc --noEmit`, a production build, and Biome `check:fix` limited to modified files.

## 4. Solution

### 4.1 Add a typed local action model

In `src/ui/pages/AIChangesReviewModal.tsx`:

- Derive a non-null footer action type from `AIChangesReviewResult`, for example `Exclude<AIChangesReviewResult, null>`.
- Add a typed, immutable option list as the single source of labels, order, and result mappings:

```ts
[
    {value: "commit", label: "Approve and Commit"},
    {value: "discard", label: "Reject and Revert Changes"},
    {value: "defer-commit", label: "Defer Commit"}
]
```

- Change `AIChangesReviewResult` to `"commit" | "discard" | "defer-commit" | null`. The launcher remains source-compatible because it returns this imported type without branching on its values.

### 4.2 Implement a modal-local action selector

Add an `AIChangesReviewActionSelect` component in `AIChangesReviewModal.tsx`. Keep it local to this feature rather than expanding `LogseqPopover`, `LogseqDropdownMenu`, or `LogseqSelect`.

The selector will:

- Accept a typed `value` and `onChange` callback.
- Render a real `button` trigger displaying the selected label and a presentational chevron.
- Use `@floating-ui/react` with:
  - `placement: "top-start"` to prefer opening upward;
  - fixed positioning and `autoUpdate` so the popup follows the footer while content/viewport geometry changes;
  - a small `offset`;
  - `flip()` to move below only when needed;
  - `shift({padding: 8})` to remain inside the iframe viewport;
  - width/size handling so the popup is at least the trigger width and remains usable in short/narrow viewports.
- Render the popup inline within the modal/focus-trap subtree and give it sufficient z-index. Do not use a body/app portal unless browser validation proves fixed inline content is clipped; if that fallback is needed during implementation, mount within the modal panel so focus remains trapped correctly.
- Style the trigger and popup with existing Logseq theme aliases (`border-border`, `bg-secondary-background`, `text-text`, primary/focus styles) rather than introducing fixed theme colors.

Accessibility and interaction contract:

- Trigger: `type="button"`, an accessible `Review action` name, `aria-haspopup="listbox"`, `aria-expanded`, and `aria-controls`.
- Popup: `role="listbox"` with a stable label/ID.
- Options: stable IDs, `role="option"`, and `aria-selected`; visibly distinguish selected, keyboard-active, and hover states.
- Use Floating UI click, dismiss, role, and list-navigation interactions (and refs for all three options) so pointer and keyboard behavior are consistent.
- Trigger click or Enter/Space opens the list. Arrow Up/Down opens and navigates from the current selection.
- While open, Arrow Up/Down and Home/End navigate; Enter/Space selects; Escape closes only the selector; Tab dismisses and continues normal focus traversal.
- Selecting an option updates the footer state, closes the popup, and restores focus to the trigger. It must not resolve the modal.
- Outside interaction closes only the selector; it must not close or confirm the modal.
- Stop propagation for selector-owned Escape, Enter/Space, and Arrow events where necessary so `useModal` does not scroll the diff or close the modal during selector interaction.

### 4.3 Refactor footer state and confirmation

Refactor `AIChangesReviewModalFooter` in the same file:

- Replace `onContinue`, `onDiscard`, and `onCommit` props with one typed `onConfirm(action)` prop.
- Initialize local selected-action state to `"commit"`.
- Render only `AIChangesReviewActionSelect` and one primary `LogseqButton` labeled `Confirm`.
- Have Confirm call `onConfirm(selectedAction)` explicitly. The static typed option/state model ensures it cannot emit `undefined`, `null`, or an unsupported value.
- Retain the footer border and spacing. On normal widths, align selector and Confirm beside each other at the right. On narrow widths, allow a full-width stack (selector above Confirm) so the longest label remains legible.
- Do not dynamically execute actions on selection or dynamically make Confirm destructive/red; only its explicit click performs the selected existing action.

### 4.4 Wire one explicit result into the modal

In `AIChangesReviewModalComponent`:

- Replace the three footer callbacks with `onConfirm={(action) => handleConfirm(action)}`.
- Set `enableEnterKey: false` and remove the now-unused destructive `defaultResult`. Native keyboard activation of the focused Confirm button remains available, while option selection cannot accidentally trigger a second/global confirmation.
- Leave `enableEscapeKey: true` and `enableOutsideClickClose: false` unchanged.
- Leave `ModalHeader`'s `onClose={() => handleCancel()}` and `showCloseButton={true}` unchanged, preserving the header X and its `null` result.
- In `src/chat-app/tools/impl/LogseqCommitChangesTool.tsx`, rename the `"continue-later"` switch case to `"defer-commit"` while retaining the exact existing stop/retention behavior and message targeting. Do not modify the launcher or transaction operations.

### 4.5 Update focused tests

Update `tests/src/ui/pages/AIChangesReviewModal.test.ts`:

- Preserve existing diff-viewer/page-icon tests.
- Replace the old structural three-button assertion with mounted jsdom tests using `createRoot`, `act`, and deterministic cleanup.
- Cover:
  1. Default trigger label is `Approve and Commit`; immediate Confirm emits `"commit"` exactly once.
  2. Opening the selector presents exactly the three agreed labels in the agreed order and none of the old button labels.
  3. Selecting `Reject and Revert Changes` does not submit immediately; subsequent Confirm emits `"discard"`.
  4. Selecting `Defer Commit` does not submit immediately; subsequent Confirm emits `"defer-commit"`.
  5. Changing back to `Approve and Commit` emits `"commit"`.
  6. Trigger/listbox/options expose the intended ARIA state, including expanded and selected state changes.
  7. Arrow-key navigation plus Enter changes selection without confirming.
  8. Escape closes an open selector and restores trigger focus without confirming or closing the modal pathway.
  9. Outside pointer dismissal closes only the selector.
- Where practical, add a focused component-level assertion/mocked `useModal` configuration that the modal passes the selected explicit result, disables global Enter handling, and retains header cancellation. Avoid brittle pixel-position assertions in jsdom.
- Update or extend `tests/src/chat-app/tools/impl/LogseqCommitChangesTool.test.ts` so the renamed `"defer-commit"` outcome is shown to retain queued changes and invoke the same targeted stop pathway as before.

### 4.6 Scope and compatibility

- Do not alter shared selectors/popovers because none currently satisfies the interaction contract and changing them would increase regression risk.
- Do not change documentation or prompts: names and presentation change, but commit, defer, reject/revert, and close semantics remain the same.
- Do not add dependencies; `@floating-ui/react` and the required icons/React APIs already exist.
- Preserve iframe theming, modal focus trapping, and downstream transaction behavior; only the defer result's internal discriminator changes.
