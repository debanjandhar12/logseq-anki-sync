### Behavior that names must preserve

- Editing and Refresh create alternate branches in the same conversation; original messages remain saved. Previous/Next change the displayed branch, not saved message contents.
- Advanced navigation asks for confirmation when Logseq changes are applied but uncommitted. Confirming switches branches and reverts those graph changes; canceling preserves both the displayed branch and graph changes.
- Refreshing/editing even a later exchange can revert earlier uncommitted Logseq changes. This is not discarding earlier message edits.
- Successful commit locks earlier Edit, Refresh, and branch controls, including those associated with the committing exchange. Copy stays available. Later messages can still be edited.
- Closing review leaves commit pending. Approval after reopening restores the same Logseq page, not a different conversation. Rejection and deferral have different outcomes.
- The Stop test checks availability during review and its replacement by Send after approval; it does not click Stop.
- Updating an unchanged message with multiple text sections does not combine its saved sections or create a branch.
- UI tests check specific window sizes, not every possible size.
