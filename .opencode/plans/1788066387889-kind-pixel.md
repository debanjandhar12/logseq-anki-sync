# Multi-provider configuration plan

## 1. User Requirement

Currently, we use logseq provided settings page for provider settings and only have support for a single provider. We need to change this to support multiple provider configs. For this, we will need to create a new settings page inside src/ui/pages/ and add a button in the main settings page to open this new page.

### Storage info
We will store the provider settings inside same place as other logseq settings as base64 encoded json string. (using logseq.settings.updateSettings). The key will be "providerConfigSetting" (DELETE: llmProvider, llmAPIUrl, llmAPIKey, llmAPIModelList).

### New Page details
Logseq has recently introduced a way to add buttons to the settings.ts page schema. We will use this to show our provider settings button. For example:
```
logseq.provideModel({
        showToolbarMenu: () => {
            console.log('Settings button clicker');
        }
});

logseq.useSettingsSchema([
  {
    key: 'open-toolbar',
    type: 'button',
    title: 'Toolbar',
    text: 'Open Toolbar',
    action: 'showToolbarMenu',
    description: 'Open the toolbar menu.',
  },
])
```
Note: above may show typescript error currently as the plugin sdk with new typing is not release yet but functionality wise this should work.

### New Page details 2

Provider configuration already setup by user will be listed in the left hand side (instead of file name). Provider configuration can be added / edited / deleted similar to skill editor.

The content will be an ui and not codemirror. For Openai / Gemini, it will display:
Base Url (disabled and auto populated), Api Key, Model List (auto populated).


Note:
- Model list should be an editable list with enabled/disabled checkbox.
- For openai / gemini, we currently populate the model list from @opencode-ai/models snapshot. We should remove this logic. Instead, we should add a fetch models button / link component beside / near the model list. It will call the models endpoint using user's api key (we can keep this button disabled / throw show msg validation until base url and api key is filled) and use to fill the model list. We can throw UI.showMessage validation if user pressed the fetch modal without filling api key.
- We also need a test button.
- There will be a top level select component to select provider type.
- There will be a top level text input for setting unique provider config id. There should be validation for dublicate when clicking save. provider config id should also always be lowercase only (have validation / make inputbox accept only lowercase).
- Validations for missing api key etc should be shown after clicking save.
- You may border the api key / base url field with danger / red color if empty.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Which provider types must the first version support, and how should Base URL behave for each?** Existing three: OpenAI and Gemini use fixed, disabled URLs; OpenAI Compatible has an editable URL.
- **When Fetch Models returns IDs, how should it update an existing editable model list?** Merge and preserve: retain manual rows and existing enabled states, append newly fetched IDs enabled by default.
- **What should the Test button verify?** Run a minimal inference using the first enabled model, rather than treating model discovery alone as a connection test.
- **How should selection disambiguate identical model IDs across configurations?** Persist one config-qualified value in the existing `selectedModelId` setting; do not add a companion selection setting. Per the follow-up, use a simple delimiter rather than an encoded/versioned identity format.
- **Should Save require at least one enabled model in each provider configuration?** Yes.
- **Can an existing provider configuration ID be renamed?** Yes; selection reconciliation must account for the rename.
- **How should Model Native web search behave?** Keep it as a global option and conditionally install native tools at runtime for the selected OpenAI or Gemini configuration; an OpenAI Compatible selection gets no native provider tools.
- **How should reasoning-effort controls behave after snapshot metadata is removed?** Continue to show Low/Medium/High for every enabled model.

### 2.2 Final Summarized Requirements

1. Replace the four visible single-provider settings with a settings button that opens a large provider-configuration modal under `src/ui/pages/`.
2. Persist `ProviderConfig[]` directly as JSON encoded to a UTF-8-safe base64 string in `providerConfigSetting`, accessed only through `LogseqSettingAccessor`. Do not add a version wrapper, migrate, or read the old `llm*` settings.
3. Support any number of OpenAI, OpenAI Compatible, and Google Gemini configurations, including multiple configurations of the same type.
4. Provide draft CRUD, lowercase unique IDs, pre-populated disabled official Base URL fields, an editable compatible Base URL, masked API keys, editable model rows, enable/disable controls, model discovery, minimal inference testing, save validation, error highlighting, and unsaved-change protection.
5. Remove the `@opencode-ai/models` snapshot and aggregate every enabled configured model into the chat selector, grouped by provider configuration ID.
6. Keep `selectedModelId`, storing the provider configuration ID and raw model ID in one simple delimiter-separated value. Split it before calling provider SDKs.
7. Preserve Jina behavior. Resolve Model Native tools from the selected provider configuration at request time.
8. Preserve the current reasoning effort UI for all listed models.

## 3. Existing System

### 3.1 Settings and modal patterns

- `src/settings.ts` currently declares `llmProvider`, `llmAPIUrl`, `llmAPIKey`, and `llmAPIModelList`, installs CSS visibility rules for compatible-provider fields, and rejects Model Native when the one global provider is unsupported.
- The repository already implements the new Logseq settings-button runtime shape with `buttonText` and `buttonAction`, a narrow local `SettingsButtonSchemaDesc`, and a cast only at the SDK boundary. `@logseq/libs@0.3.3` does not yet type this host feature.
- `src/constants.ts` contains `LogseqModelAction`; `src/settings.ts` calls `logseq.provideModel` before registering the schema.
- `src/ui/pages/SkillEditorModal/SkillEditorModal.tsx`, `src/ui/launchers/showSkillEditorModal.ts`, `createModalPromise`, and `UI.showModal` establish the intended two-column, iframe-isolated modal CRUD pattern. The page is not a Logseq graph route.
- Application code must use `LogseqSettingAccessor`; direct `logseq.settings`, direct parent-window access, and `console.log` are prohibited.

### 3.2 Provider and model flow

- `src/core/ai-sdk/types.ts` currently conflates supported provider types with a single selected provider through `ProviderEnum`.
- `getLLMModelList()` reads one provider. Compatible models come from a comma-separated setting; OpenAI and Google models come from `@opencode-ai/models/snapshot` and are filtered to reasoning text models.
- `getLLMModel(modelId)` reads one global key/URL/provider and creates OpenAI Responses, OpenAI Compatible chat-completions, or Google chat models.
- Model IDs are provider-scoped. With multiple configurations, raw IDs such as `gpt-5` can collide across credentials/configurations.
- `usePersistedModelSelection` persists an exact selector ID and deterministically falls back to the first model. Its write queue is private to the hook.
- `ModelSelector.tsx` is a project-owned assistant-ui adaptation. It supports compound command groups but its default list renders a single group. Its model context places the selected option ID in `context.config.modelName`.
- `runLocalAISDKChatModel` currently resolves the model and native tools separately from global settings. Title generation also reads `selectedModelId` and passes it to `getLLMModel`.

### 3.3 Web tools and networking

- Model Native currently provides OpenAI `web_search` or Google `google_search` plus `url_context`; OpenAI Compatible gets none.
- Jina frontend tools are independently selected by `webToolsProvider` and read `jinaApiKey` at execution time. This feature does not alter Jina registration semantics.
- `LogseqHttpProxy.init()` patches global `fetch`, so provider model-discovery requests can use normal `fetch` without direct parent-window access.
- The existing Model Native settings listener assumes one global provider and must be removed for runtime-conditional behavior.

### 3.4 Tests and documentation

- `tests/src/settings.test.ts` covers existing settings buttons. Provider factories, model lists, selection hooks, provider tools, and the model selector currently have little or no direct coverage.
- Component tests use React `createRoot`/`act`, manual DOM interaction, mocked Logseq globals, and mocked fetch/provider constructors.
- Docusaurus has an empty Providers category and no provider configuration guide. `ai-generated-thread-titles.md` documents use of the selected model and must reflect configuration-qualified selection.

## 4. Solution

### 4.1 Domain model, stable labels, and storage codec

Update `src/core/ai-sdk/types.ts` to replace `ProviderEnum` with a provider-type/config distinction:

```ts
enum ProviderTypeEnum {
    OPENAI = "openai",
    OPENAI_COMPATIBLE = "openai-compatible",
    GOOGLE = "google"
}

interface ProviderModelConfig {
    id: string;
    enabled: boolean;
}

interface ProviderConfig {
    id: string;
    type: ProviderTypeEnum;
    baseUrl: string;
    apiKey: string;
    models: ProviderModelConfig[];
}

```

- Keep serialized provider-type values stable and separate their user-facing labels (`OpenAI`, `OpenAI Compatible`, `Google Gemini`) in constants.
- Add `src/core/ai-sdk/provider-config/providerConfigCodec.ts` with small `encodeProviderConfigs(ProviderConfig[])` and `decodeProviderConfigs(string)` helpers. Encode/decode UTF-8, not raw `btoa(JSON.stringify(...))`, so Unicode model/config data round-trips.
- Validate the decoded array and each configuration with Zod. Strict editor decoding surfaces corrupt storage and prevents silently replacing it; safe runtime reading logs a redacted error and returns no configurations.
- Never include API keys in errors, logs, React keys, selector IDs, or descriptions. Document that base64 is encoding rather than encryption.
- Add default URL constants only for initializing/resetting the Base URL form field: `https://api.openai.com/v1` for OpenAI and `https://generativelanguage.googleapis.com/v1beta` for Gemini. Persist `baseUrl` for every configuration and have model discovery, Test, and production provider factories all consume that stored/form value. The field is disabled for OpenAI/Gemini and editable for OpenAI Compatible, keeping the request logic generic.

### 4.2 Simple selected-model identity and reconciliation

Add `src/core/ai-sdk/provider-config/selectedModelId.ts`:

```text
<provider-config-id>////<raw-model-id>
```

- Keep this helper intentionally small: one constant delimiter, one formatter, and one parser that splits at the first delimiter. Reserve `////` in provider configuration IDs and validate that IDs do not contain it; model IDs may contain the delimiter because the parser preserves the complete remainder. A missing delimiter is an invalid selection.
- Selector options use the joined string as `id`, while their display name and all SDK calls use the raw model ID.
- Add a pure `resolveLLMSelection` that decodes selection, reads one provider-config snapshot, locates the configuration and enabled model, validates required credentials/URL, and returns `{config, rawModelId}` with user-readable errors.
- Add `reconcileSelectedModelId(previousSelection, nextConfigs, renamedIds)`: preserve the selected raw model through a config rename when still enabled; otherwise retain an unchanged valid selection; otherwise select the first enabled model in persisted config/model order; if no model exists, save an empty selection. This same rule handles deleting/disabling the selected model/config and malformed previous values.

### 4.3 Provider model discovery, merge, and connection test

Create focused non-React services under `src/core/ai-sdk/provider-config/`.

`fetchProviderModels.ts` will validate draft credentials/base URL and call global `fetch`:

- OpenAI: `GET <baseUrl>/models`, bearer authorization, parse OpenAI-shaped `{data: [{id}]}`. The disabled form field is initialized to `https://api.openai.com/v1`.
- OpenAI Compatible: normalize trailing slashes and call `GET <baseUrl>/models` with bearer authorization. Do not append `/v1`; the form explains that the entered API base must expose `/models`. Allow absolute `http:` for local providers and `https:`, but reject malformed URLs and embedded URL credentials.
- Gemini: `GET <baseUrl>/models` using `x-goog-api-key`; follow `nextPageToken`; include only entries supporting `generateContent`; strip one `models/` prefix before passing IDs to the SDK. The disabled form field is initialized to `https://generativelanguage.googleapis.com/v1beta`.
- For all responses, trim, remove blank IDs, deduplicate case-sensitively in response order, validate response shapes, and produce bounded/redacted HTTP errors without secrets.

`mergeProviderModels.ts` will preserve all existing rows and order, preserve enabled states, append only new fetched IDs, and enable appended rows. It will never remove manual/stale rows.

`testProviderConfig.ts` will use the unsaved draft, its first enabled model, and the same provider factory as production to perform a bounded minimal `generateText` request (small token limit, prompt such as `Reply with OK.`). Any completed generation is success; exact output matching is unnecessary. It excludes global prompts, history, reasoning settings, Jina, and provider-native tools. Fetch and Test report success/failure through `logseq.UI.showMsg`; failures are redacted.

### 4.4 Provider configuration modal

Add `src/ui/pages/ProviderConfigModal/` with a container plus small sidebar/form/model-list components and pure validation/snapshot utilities; add `src/ui/launchers/showProviderConfigModal.ts` following the Skill Editor launcher.

- Use a large modal, disabled outside/Escape closing, header, two-column body, footer Save/Cancel, and dirty-state confirmation.
- Sidebar lists configuration IDs in persisted/draft order, offers Add, and selects the previous/first remaining entry after local deletion. Use a transient `editorKey` and `originalId` so renames are distinct from delete/add.
- Form uses ordinary themed controls: provider type select, lowercase config ID input, Base URL, masked API key, Fetch Models, Test, Delete, and scrollable model rows.
- Lowercase entered config IDs as the user types and validate trimmed nonempty IDs, case-insensitive duplicates, and the reserved `////` delimiter at Save. Do not impose any other unstated slug character restriction.
- Provider changes populate the standard OpenAI/Gemini URL and disable the field, or enable it for Compatible; retain key/model rows unless the user changes them.
- Model rows have editable ID, enabled checkbox, and remove action; an Add Model action supports manual rows. Keep Low/Medium/High reasoning available for every enabled model by emitting `efforts: true`.
- Save validates every draft: valid provider type, unique lowercase ID without the reserved delimiter, nonblank API key, valid stored/form Base URL, nonblank/unique model IDs, and at least one enabled model per config. An empty global config collection is allowed.
- Maintain field/row error maps. On Save failure, select the first invalid config, focus/scroll its first invalid field, apply danger borders plus `aria-invalid`, show one validation message, and perform no persistence.
- Fetch validates provider type, URL, and key. Test additionally validates an enabled model. Keep separate busy states, prevent duplicate requests/destructive actions, and leave drafts unchanged on remote failure.
- Save one encoded payload and reconciled `selectedModelId` in one `LogseqSettingAccessor.updatePluginSettings` patch, then close successfully. Cancel never persists drafts.

### 4.5 Logseq settings integration

Modify `src/settings.ts` and `src/constants.ts`:

- Add `OPEN_PROVIDER_CONFIG_SETTINGS` and register its fire-and-forget launcher in the existing `provideModel` object before schema registration.
- Remove `llmProvider`, `llmAPIUrl`, `llmAPIKey`, and `llmAPIModelList` from `PluginSettings` and the visible schema. Add `providerConfigSetting?: string` with an encoded `[]` default and a Provider Configurations button under the LLM heading.
- Hide the backing encoded string row with plugin-scoped settings CSS so users cannot accidentally edit credentials/payload; retain the existing narrow SDK button typing workaround using runtime fields `buttonText`/`buttonAction`.
- Remove old provider-dependent field visibility and the listener that disables Model Native based on one global provider. Retain Jina key visibility and logger handling.
- No migration/cleanup reads will be added. Old stored `llm*` keys are inert after their schema/type references are removed.

### 4.6 Aggregated model list and grouped selector

Refactor `getLLMModelList()` to decode all configurations in order and return enabled model rows only:

```ts
interface LLMModelOption {
    id: string;               // config-id////raw-model-id
    name: string;             // raw provider model ID
    providerConfigId: string; // group label/key
    efforts: true;
}
```

- Do not sort; config order followed by model-row order defines stable display and fallback behavior.
- Duplicate raw model IDs in different configs remain distinct because option IDs include the configuration ID.
- Update `src/chat-app/components/ModelSelector.tsx` to group the default list by `providerConfigId`, include that ID in search keywords, and show enough config context in the selected trigger to distinguish duplicate models (for example, `config-id / model-id`).
- Preserve exact controlled selection and model-context registration behavior. Register the joined option ID as `modelName`; provider splitting occurs only at the AI boundary.
- Update the assistant-ui customization comment in the copied component to document provider grouping/config-qualified identity. No upstream file in `src/shadcn` is modified.
- Preserve `usePersistedModelSelection`'s current local write queue, exact-ID validation, default-first fallback, empty-list behavior, and reasoning effort persistence.

### 4.7 Provider factories, runtime, titles, and native tools

Refactor model construction into `createLLMModel(resolvedSelection)` plus `getLLMModel(configQualifiedSelectedModelId)`:

- OpenAI uses selected config credentials and `responses(rawModelId)` to retain provider-defined tool support.
- Every provider factory receives the selected configuration's stored `baseUrl` as well as its API key. OpenAI Compatible uses the config ID as provider name and `chatModel(rawModelId)`; OpenAI retains `responses(rawModelId)` and Gemini retains `chat(rawModelId)`.
- Gemini uses selected config credentials and `chat(rawModelId)`.

In `runLocalAISDKChatModel`, resolve the config-qualified selection once and use that same result for model creation and native tools.

Change `getLLMProviderTools` to accept the resolved selection:

- if the global web setting is not Model Native, return no native tools;
- selected OpenAI config gets `web_search` built with its key;
- selected Gemini config gets `google_search` and `url_context` built with its key;
- selected OpenAI Compatible config gets no native tools without rewriting the global web setting.

Jina tools remain controlled by the global web setting and retain their current implementation. Title generation continues to read `selectedModelId`, but `getLLMModel` now decodes it and passes only the raw model ID to the SDK.

## 5. Verification

### 5.1 Unit and component tests

Add/update tests for:

1. **Codec/schema:** empty-array and Unicode round trips; malformed base64/JSON/array items; errors/logs never reveal keys.
