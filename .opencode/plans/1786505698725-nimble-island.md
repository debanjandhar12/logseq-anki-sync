# Review Follow-up for Chat Page Export

## 1. User Requirement

In 02a8cccf export as page and export as debug was introduced. THe following changes are required and was deemed necesary during review:
(a) We need to remove the ChatDebugReportFormatter.ts and the copy debug info menu item.
(b) After ThreadTopToolBarMore is opened, clicking outside does not close the menu list.
(c) In exported page, All user message should be set with MessageUser icon and all assistant messages (including tool calls), should have icon MessageChatbot. 
    [Logseq plugin api Editor has a block icon method]
(d) In exported page, all tool call blocks should be collapsed.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

1. **Question:** The exporter currently creates no assistant-message container. Should `MessageChatbot` be applied to the visible assistant-generated blocks, to a new container per assistant message, or to the entire tool subtree?
   **Answer:** Apply it to the visible assistant-generated blocks. Preserve the existing hierarchy: assistant text blocks and tool-call parent blocks receive the chatbot icon; `Tool Args` and `Tool Result` children remain iconless.
2. **Question:** When positional reconciliation reuses an existing block as an iconless `Tool Args` or `Tool Result` block, should a stale icon be removed?
   **Answer:** Yes. Reconcile the exact icon state and remove stale icons from generated iconless blocks.
3. **Question:** Should this follow-up add the missing Export as Page documentation?
   **Answer:** No. Limit the change to code and tests.

### 2.2 Final Summarized Requirements

- Remove the debug-report formatter, its tests, all toolbar clipboard/debug-copy logic, and the `Copy Debug JSON` menu item. Retain raw thread loading because page export still uses the persisted title fallback.
- Make `ThreadTopToolBarMore` a non-modal, controlled dropdown so Radix/assistant-ui can report outside interactions through the existing Shadow DOM portal bridge and close the menu reliably. Preserve keyboard and menu-item semantics.
- Preserve the current exported page hierarchy:
  - each user-message root block gets Logseq's Tabler `message-user` icon (`MessageUser`);
  - each assistant text block gets `message-chatbot` (`MessageChatbot`);
  - each tool-call parent block gets `message-chatbot`;
  - `Tool Args` and `Tool Result` child blocks have no icon;
  - each tool-call parent ends collapsed.
- Apply presentation reconciliation to both reused and newly inserted blocks. On reused blocks, remove stale icons when the desired block is iconless. Re-exporting must restore a manually expanded tool-call parent to collapsed.
- Do not introduce assistant-message container blocks, do not put chatbot icons on tool argument/result children, and do not add documentation in this follow-up.

## 3. Existing System

### 3.1 Toolbar and debug export

- `src/chat-app/components/ThreadTopToolBar.tsx` owns export/copy busy state, captures the active assistant-ui branch, and renders `ThreadTopToolBarMore`.
- The page-export handler loads `ThreadStore.loadRawThread()` to parse `ThreadFileData.title`, builds a desired tree with `ChatPageExporter`, reconciles it, navigates to the page, and reports success/failure through the centralized `CHAT_UI` logger and Logseq notifications.
- The debug-copy handler separately loads the raw thread, formats it with `ChatDebugReportFormatter`, and writes it through `WindowBridge`. Removing debug copy makes both imports and the `"copy"` operation-state variant obsolete, but does **not** make `ThreadStore.loadRawThread()` obsolete.
- `src/chat-app/export/ChatDebugReportFormatter.ts` has no other runtime consumer or barrel export. Its only direct test is `tests/src/chat-app/export/ChatDebugReportFormatter.test.ts`.
- The existing `.opencode` plan describing commit `02a8cccf` is a historical artifact and will not be rewritten as part of runtime cleanup.

### 3.2 More-menu dismissal

- `ThreadTopToolBarMore` currently uses an uncontrolled `<ThreadListItemMorePrimitive.Root>`.
- In assistant-ui 0.14.27, that primitive defaults to a modal Radix dropdown unless `sharedFocusGroup` or `modal={false}` is supplied. Modal mode disables outside pointer events at the document body and is fragile in this app's `ShadowWrapper` plus redirected Radix portal/Popper setup.
- The nearby thread-list menu is effectively non-modal via `sharedFocusGroup`; controlled `open`/`onOpenChange` is also an established pattern in `ModelSelector` and `ReviewChangesDisplay`.
- `sharedFocusGroup` is not appropriate for the standalone top toolbar because it also opts into thread-list focus behavior. Explicit `modal={false}` is the narrower fix.
- The current test only covers the pure action-availability helper. Vitest runs jsdom and only includes `*.test.ts`, so it cannot fully reproduce production Shadow DOM event retargeting; the local open-state contract can be unit tested, with an end-to-end Logseq check covering the actual portal boundary.

### 3.3 Page conversion and reconciliation

- `src/chat-app/export/ChatPageExporter.ts` represents desired blocks with only `content` and `children`.
- User messages become root blocks. Assistant text parts and tool-call parent blocks become children of the preceding user block. `Tool Args` and `Tool Result` are children of a tool-call parent. System and unsupported parts are omitted.
- `exportPage()` gets or creates the deterministic page, reads its tree, and recursively reconciles siblings by position. Shared blocks retain UUIDs, excess blocks are removed in reverse order, and missing blocks are appended.
- Every mutation currently goes through `runReconciliationOperation()` so failures include page, parent, and positional path context and preserve the original cause.
- `src/logseq/LogseqEditor.ts` is the project API boundary, but it currently has no icon/collapse wrappers.
- Installed `@logseq/libs` exposes:
  - `Editor.setBlockIcon(blockId, "tabler-icon", iconName)`;
  - `Editor.removeBlockIcon(blockId)`;
  - `Editor.setBlockCollapsed(blockId, true)`;
  - fetched block state as `block["collapsed?"]`.
- The canonical Tabler IDs present in the installed icon package are `message-user` and `message-chatbot`.

## 4. Solution

### 4.1 Remove debug export and simplify toolbar state

**Delete:**

- `src/chat-app/export/ChatDebugReportFormatter.ts`
- `tests/src/chat-app/export/ChatDebugReportFormatter.test.ts`

**Modify `src/chat-app/components/ThreadTopToolBar.tsx`:**

- Remove the `ChatDebugReportFormatter` and `WindowBridge` imports, `handleCopyDebugJson`, its prop plumbing, the menu item, and all debug-copy notifications/logging.
- Replace `activeOperation: "export" | "copy" | null` with export-specific boolean state such as `isExportInProgress`; retain and rename the synchronous ref lock so rapid clicks in the same React turn cannot start duplicate exports.
- Rename generic single-action symbols for clarity:
  - `areChatActionsDisabled` -> `isPageExportDisabled`;
  - `isThreadChatActionEnabled` -> `isThreadPageExportEnabled`;
  - corresponding prop and CSS-variable names to export-specific names.
- Keep the existing capture-before-await export flow, stored-title lookup, centralized error logging, notification behavior, and navigation only after successful reconciliation.
- Update `tests/src/chat-app/components/ThreadTopToolBar.test.ts` to import the renamed availability helper and retain the full status/ID/message-count/busy-state matrix.

### 4.2 Make `ThreadTopToolBarMore` dismiss reliably

In `ThreadTopToolBarMore`:

- Add local controlled state: `const [isOpen, setIsOpen] = useState(false)`.
- Configure the primitive as:

```tsx
<ThreadListItemMorePrimitive.Root
    modal={false}
    open={isOpen}
    onOpenChange={setIsOpen}
>
```

- Continue relying on Radix's dismissable-layer behavior rather than adding a global document listener. Non-modal mode avoids host-body pointer suppression while `onOpenChange(false)` updates the controlled state after an outside pointer event or Escape.
- Use menu `onSelect` semantics for enabled actions and close controlled state before invoking Export or Devtools. Disabled export items remain non-selectable and must not invoke or close through the action callback.
- Export `ThreadTopToolBarMore` as a named component for a focused unit test. In the existing `.test.ts` file, render it with `React.createElement` and mocked assistant-ui primitives to verify the local contract: root receives `modal={false}`, opening updates state, simulated `onOpenChange(false)` removes the menu, selecting an enabled item closes and invokes once, and a disabled export does not invoke. Do not claim this jsdom test proves the production Shadow DOM event path.
- Update the copied-component `Changes:` comment to remove debug-copy wording and record the controlled non-modal menu customization, as required by `src/chat-app/AGENTS.md`.

### 4.3 Model complete desired icon and tool-collapse presentation

In `src/chat-app/export/ChatPageExporter.ts`, extend `DesiredLogseqBlock` with explicit presentation metadata. Use an explicit nullable icon so `null` means “this generated block must be iconless,” rather than the ambiguous “leave unchanged” meaning of an optional field:

```ts
type DesiredLogseqBlockIcon = "message-user" | "message-chatbot" | null;

interface DesiredLogseqBlock {
    content: string;
    children: DesiredLogseqBlock[];
    icon: DesiredLogseqBlockIcon;
    collapseToolCall: boolean;
}
```

Populate every generated node without changing hierarchy or content serialization:

- user root: `icon: "message-user"`, `collapseToolCall: false`;
- assistant text: `icon: "message-chatbot"`, `collapseToolCall: false`;
- tool-call parent: `icon: "message-chatbot"`, `collapseToolCall: true`;
- tool args/result: `icon: null`, `collapseToolCall: false`.

The collapse field intentionally expresses the required positive tool-call operation. Non-tool blocks will not be forcibly expanded: the stated requirement only mandates collapsed tool calls, while preserving collapse state on other generated blocks avoids overriding unrelated user presentation choices. A reused or manually expanded desired tool-call block is always set back to collapsed.

### 4.4 Add Logseq Editor presentation wrappers

In `src/logseq/LogseqEditor.ts`, add thin async wrappers consistent with the existing project boundary:

- `setBlockIcon(blockIdentity, iconName)` -> `logseq.Editor.setBlockIcon(blockIdentity, "tabler-icon", iconName)`;
- `removeBlockIcon(blockIdentity)` -> `logseq.Editor.removeBlockIcon(blockIdentity)`;
- `setBlockCollapsed(blockIdentity, true)` -> `logseq.Editor.setBlockCollapsed(blockIdentity, true)`.

Use SDK-compatible `BlockIdentity`/`EntityID` types (not untyped strings), with the icon methods constrained to the SDK's `BlockIdentity` acceptance. Do not write Logseq icon properties or collapsed fields directly.

Extend `ChatPageExporterDependencies` and `defaultDependencies` with bound versions of all three methods so exporter tests remain isolated from a running Logseq instance.

### 4.5 Reconcile presentation for existing and inserted blocks

Add focused private helpers in `ChatPageExporter` and route each API mutation through `runReconciliationOperation()`.

For each **shared existing block**:

1. Update content when it differs.
2. If an icon is desired, unconditionally call `setBlockIcon`; current SDK entities do not expose a dependable typed icon representation, so this repairs missing/manually changed icons without brittle property inspection.
3. If the desired icon is `null`, call `removeBlockIcon` to clear an icon left by positional reuse.
4. Reconcile descendants recursively.
5. If `collapseToolCall` is true, call `setBlockCollapsed(uuid, true)` after descendants are complete, guaranteeing a successful export leaves the full tool subtree collapsed. This call is intentional even when the fetched block says it is already collapsed, so re-export deterministically enforces the requirement and does not depend on potentially stale fetched state.

For each **newly inserted block**:

1. Insert and retain the returned UUID.
2. Set a desired user/chatbot icon. Skip `removeBlockIcon` for newly inserted iconless args/results because insertion creates them without an icon; stale-icon cleanup is only needed for reused blocks.
3. Reconcile/insert descendants.
4. Collapse a tool-call parent after its children exist.

Keep reverse-order excess removal and positional UUID preservation unchanged. The result is state-idempotent: rerunning export converges to the same content, hierarchy, icons, and collapsed tool parents, although icon/collapse setter calls may repeat because readable icon state is not reliable and the required state must be reasserted.

Extend the contextual operation names to distinguish `set icon`, `remove icon`, and `collapse`. Include the target block UUID in presentation-operation errors in addition to page, parent, and path. Preserve the cause, avoid logging content/tool data in errors, and stop at the first failure so a later retry can converge from the partial state.
