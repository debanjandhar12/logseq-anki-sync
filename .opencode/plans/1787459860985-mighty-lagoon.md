# Refactor SkillEditorModal into a proper module

## 1. User Requirement

> I have been refactoring SkillEditorModal.tsx.
>
> Can you turn SkillEditorModal into a actual module with index.ts exports? Also, move few methods out (refactor)?

## 2. Final Requirement After Discussion With User

### Clarification Q&A

- **Q: How deep should the method extraction go?**
  A: Extract `handleSave`'s validation into a separate file/method. Move larger utils as separate file methods into a `utils/` subfolder of `SkillEditorModal`.
- **Q: Should consumers switch to importing from the new index.ts barrel?**
  A: Yes, via index.ts.

### Final Summarized Requirements

- Convert `src/ui/pages/SkillEditorModal/` into a proper module following existing repo patterns (`LogseqCodeEditor`, `template-engine`): folder barrel `index.ts` as the single import surface.
- Move larger pure helpers out of `SkillEditorModal.tsx` into `utils/` subfiles.
- Extract `handleSave`'s inline validation loop into a reusable pure function.
- Update all consumers to import via the barrel. Runtime behavior must remain identical.

## 3. Existing System

- `src/ui/pages/SkillEditorModal/` currently contains only `SkillEditorModal.tsx` (471 lines) and `createSkillEditorExtensions.ts`.
- `SkillEditorModal.tsx` mixes: the React component (~337 lines), module constants (`UNTITLED_FILE_NAME`, `INVALID_FILE_NAME_CHARACTERS`, `NEW_SKILL_CONTENT`, `SKILL_EDITOR_EXTENSIONS`), and 7 file-level helpers (`getSkillFileMetadata`, `getDisplayFileName`, `getSkillFileName`, `getFilesSnapshot`, `isValidFileName`, `updateDisableModelInvocation`, `getErrorMessage`) plus one exported helper `getFirstInvalidSkillTemplate`.
- `EditableSkillFile` interface (id / content / originalFileName?) is file-local; only `getFirstInvalidSkillTemplate`'s signature exposes it via `Pick<...>`.
- `handleSave` (lines 181-252) contains an inline validation loop: Mustache template check, per-file `parseSkillFile`, filename validity check, duplicate-name check. Each failure shows `logseq.UI.showMsg("Validation failed in <file>: <message>", "error")` and aborts on first error. Only the template-validation failure additionally switches the active file (`setActiveFileId`). On success it deletes removed original files from `SkillFileStore`, saves all parsed files, and resolves `true`.
- Consumers:
  - `src/ui/launchers/showSkillEditorModal.ts` (line 3): imports `SkillEditorModalComponent` via deep path.
  - `src/ui/index.ts` (lines 38-39): re-exports `SkillEditorModalProps` / `SkillEditorModalComponent` via deep path.
  - `tests/src/ui/pages/SkillEditorModal.test.ts` (line 2): imports `getFirstInvalidSkillTemplate` via deep path.
- Established module patterns: barrel `index.ts` separating `export type {...}` from value exports (see `src/core/template-engine/index.ts`, `src/ui/components/LogseqCodeEditor/index.ts`).

Add the extraction of `handleSave`'s validation loop as a pure function:

```ts
export type SkillFileSaveIssueKind =
    | "invalid-template"
    | "invalid-file-name"
    | "duplicate-name"
    | "parse-error";

export interface SkillFileSaveIssue {
    kind: SkillFileSaveIssueKind;
    fileId: string;
    fileName: string; // display name for the error message
    message: string;
}

export interface ValidatedSkillFilesForSave {
    issue: SkillFileSaveIssue | null;
    parsedFiles: SkillFileData[]; // empty when issue != null
}

export function validateSkillFilesForSave(
    files: readonly Pick<EditableSkillFile, "id" | "content">[]
): ValidatedSkillFilesForSave
```

Logic (mirrors current `handleSave` exactly, first-error-wins):
1. Run `getFirstInvalidSkillTemplate`; if an issue exists and its file is found, return `{issue: {kind: "invalid-template", fileId, fileName: getDisplayFileName(file.content), message: issue.message}, parsedFiles: []}`.
2. Iterate files in order; per file call `parseSkillFile(file.content)` inside try/catch:
   - parse throws -> `{kind: "parse-error", message: getErrorMessage(error)}`
   - `!isValidFileName(getSkillFileName(parsed))` -> `{kind: "invalid-file-name", message: `"${parsedFileName}" is not a valid file name.`}`
   - normalized name already seen -> `{kind: "duplicate-name", message: `another skill file already uses name "${parsed.name}".`}`
   - otherwise record normalized name and push parsed file.
3. On success return `{issue: null, parsedFiles}`.

Message strings must match the current ones byte-for-byte so UI text is unchanged.

**6. `src/ui/pages/SkillEditorModal/SkillEditorModal.tsx` (rewrite top half)**

- Remove moved constants/helpers; keep `NEW_SKILL_CONTENT` and `SKILL_EDITOR_EXTENSIONS`.
- Import from local files: types, frontmatter utils, `validateSkillFilesForSave`, snapshot util, `getErrorMessage`. Import `createSkillEditorExtensions` via relative `./createSkillEditorExtensions`.
- `handleSave` becomes:

```ts
const handleSave = React.useCallback(async () => {
    setIsSaving(true);
    try {
        const {issue, parsedFiles} = validateSkillFilesForSave(files);
        if (issue) {
            if (issue.kind === "invalid-template") setActiveFileId(issue.fileId); // preserve current behavior
            await logseq.UI.showMsg(`Validation failed in ${issue.fileName}: ${issue.message}`, "error");
            return;
        }

        const nextFileNames = new Set(parsedFiles.map(getSkillFileName));
        for (const originalFileName of originalFileNames) {
            if (!nextFileNames.has(originalFileName)) {
                await SkillFileStore.deleteSkillFile(originalFileName);
            }
        }
        for (const parsedFile of parsedFiles) {
            await SkillFileStore.saveSkillFile(parsedFile.content);
        }
        returnResult(true);
    } finally {
        setIsSaving(false);
    }
}, [files, originalFileNames, returnResult]);
```

Everything else in the component (state, effects, other handlers, JSX) stays untouched.

### Edge cases and compatibility

- Behavior preserved exactly: first-error-wins ordering, identical message strings, active-file switch only for template errors, delete-then-save store sequence, `finally` clearing `isSaving`.
- Double parsing avoided: success path reuses `parsedFiles` returned by the validator (previously `handleSave` parsed once too; no regression).
- No public API renames: `SkillEditorModalComponent`, `SkillEditorModalProps`, `getFirstInvalidSkillTemplate` keep their names; deep paths are replaced by the barrel everywhere.

Add `tests/src/ui/pages/SkillEditorModal/validateSkillFiles.test.ts` (pure unit tests, mirroring existing test style):
