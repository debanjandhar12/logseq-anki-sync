# Journal Page Creation and Rename Guards

## 1. User Requirement

> Create a isJournalPageName utility.
> Aditionally, add validation that jounarnal pages cannot be deleted in DeletePageCommand and journal
> pages cannot be created in CreatePageCommand and journal pages cannot be renamed to and renamed from.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **User changed the original deletion/creation policy:**
  > Change of plans!
  >
  > We will support creation of journal pages and deletion of journal pages and restoration of journal pages. I do not think any changes are required for deletion and restoration now.
  >
  > For creation, use createJournalPage and check if jounal page is required by detecting if page name is in this format: aug 22nd, 2026 or Aug 22nd, 2026 or AUG 22ND, 2026 (case insensitive). For rename, use a query similar to one i gave to check...
- **Rename directions:** reject both renaming an existing journal page to another name and renaming a non-journal page to a valid journal-formatted name.
- **Accepted month spelling:** exactly three-letter English month abbreviations, case-insensitively; full month names are not accepted.
- **Invalid calendar dates:** an impossible date such as `Feb 30th, 2026` is not a journal page name and is treated as an ordinary page name rather than rejected.
- **Validation timing:** perform journal-related command validation at `execute()` time.
- **Journal source detection:** use authoritative `:block/journal-day` metadata queried by page UUID. Cross-referencing Logseq source established that a page UUID must be queried directly; the sample block-to-page traversal applies to a content-block UUID, not a page UUID.
- **`createJournalPage` input:** cross-referencing `/home/debanjand/Documents/Projects/logseq/` established that `Editor.createJournalPage` accepts `string | Date`, internally invokes `new Date(...)`, returns `PageEntity | null`, and does not accept a custom UUID. The implementation will pass a locally constructed `Date` derived from the validated name.

### 2.2 Final Summarized Requirements

1. Add a reusable, pure `isJournalPageName(pageName)` utility.
2. Recognize only complete names in the form `MMM Do, YYYY`, with:
   - a three-letter English month;
   - case-insensitive letters, including the ordinal suffix;
   - a correct ordinal suffix for the day;
   - a real Gregorian calendar date;
   - exact punctuation/spacing and a four-digit year.
3. Return `false` for malformed or impossible dates, allowing those names to remain ordinary page names.
4. In `CreatePageCommand`, use `logseq.Editor.createJournalPage(Date)` for names recognized by the utility; retain ordinary `createPage` behavior for all other names.
5. Preserve reversible-command identity, changed-page tracking, serialization, deletion on revert, and restoration on re-execution for journal pages even though Logseq owns their deterministic UUID.
6. Leave `DeletePageCommand` and its existing restoration behavior unchanged; journal deletion/restoration is supported.
7. In `RenamePageCommand`, reject:
   - a source page whose UUID has `:block/journal-day`; and
   - a target name for which `isJournalPageName(newName)` is true.
8. Keep existing non-journal create, rename, revert, and error behavior compatible.

## 3. Existing System

### 3.1 Reversible page creation

- `src/core/logseq-reversible-transaction-tracker/commands/CreatePageCommand.ts` generates a random `pageUuid` in serialized command state and creates ordinary pages with `createPage(..., {customUUID})`.
- Execution preflights by page name and distinguishes active pages from soft-deleted pages. It only restores a page when its UUID equals the command-owned UUID.
- Revert resolves the page by stored UUID and soft-deletes it. A subsequent execute finds/restores the same UUID.
- Journal creation cannot use the provisional random UUID: Logseq's `createJournalPage` has no options argument and assigns a journal-day-derived UUID. The actual returned UUID must therefore replace the provisional state UUID after successful journal creation.
- The state schema and codec already serialize `pageUuid`, so no serialized shape or codec migration is needed.

### 3.2 Rename behavior

- `src/core/logseq-reversible-transaction-tracker/commands/RenamePageCommand.ts` resolves an active source page by UUID and currently calls `renamePage` without journal checks.
- It records changed identities only after page resolution. New guards can run before state/changed-page mutation.
- Logseq stores journal status authoritatively as `:block/journal-day`.
- For a page UUID, the correct Datascript relation is directly:

  ```clojure
  [?page :block/uuid #uuid "..."]
  [?page :block/journal-day ?journal-day]
  ```

  `:block/page` is only needed when starting from a content block and would fail for a page-root UUID.

### 3.3 Logseq journal API behavior

- Logseq source declaration: `/home/debanjand/Documents/Projects/logseq/libs/src/LSPlugin.ts`.
- Host implementation: `/home/debanjand/Documents/Projects/logseq/src/main/logseq/api/editor.cljs`.
- `createJournalPage(date)` validates via JavaScript `Date`, formats the local calendar date as `yyyy-MM-dd`, and delegates to page creation with `{journal: true, redirect: false}`.
- It resolves invalid input as `null`, is intended to be idempotent by journal day, may restore a recycled journal, and returns the actual page entity.
- Passing a local component-based `Date` avoids relying on browser parsing of ordinal names or UTC interpretation of date-only ISO strings.

### 3.4 Tests and documentation

- Existing command tests are live-Logseq integration tests under `tests/src/core/logseq-reversible-transaction-tracker/commands/` and are skipped unless a DB graph is available through `logseq-proxy`.
- Pure utilities use unguarded Vitest table tests.
- `src/chat-app/prompts/SKILL_LOGSEQ_TOOLS_GUIDE.md` currently says journal pages cannot be created, deleted, or renamed. That is inconsistent with the revised policy and must be updated.
- The worktree already contains unrelated changes in `src/settings.ts` and `.opencode-trace/`; implementation must not modify or clean them.

## 4. Solution

### 4.1 Add the journal page-name utility

Create `src/logseq/utils/isJournalPageName.ts` as a reusable Logseq naming utility.

- Export `isJournalPageName(pageName: string): boolean`.
- Internally parse with an anchored, case-insensitive expression for exactly `MMM D<suffix>, YYYY`; do not trim input, so leading/trailing or altered internal whitespace does not silently match.
- Map only `jan` through `dec` to month indexes. Reject full/unknown month names.
- Compute the expected ordinal suffix, with 11/12/13 using `th`, and reject mismatches.
- Validate the day against the selected month and Gregorian leap-year rules. Consequently, `Feb 30th, 2026` and `Feb 29th, 2025` return `false`, while `Feb 29th, 2024` returns `true`.
- Keep a shared internal parser that returns numeric year/month/day components (or `null`) so the create command uses exactly the same interpretation as the boolean utility. Export a narrowly named parser only if needed by `CreatePageCommand`; otherwise expose a companion date conversion from the module and keep parsing details private.
- Construct the Date from local components (using `setFullYear` rather than parsing the display string) and round-trip/check its components before passing it to Logseq. This avoids JavaScript's normalization of impossible dates and special handling of years below 100.

### 4.2 Route journal creation through `createJournalPage`

Update `CreatePageCommand.execute()` in `src/core/logseq-reversible-transaction-tracker/commands/CreatePageCommand.ts`.

1. Preserve `assertCanExecute()` and the existing page-name collision/restore flow.
2. Parse the requested name once at execute time.
3. If no page exists and the parsed name is a valid journal date:
   - construct the validated local `Date` from the parsed components;
   - call `logseq.Editor.createJournalPage(date)`;
   - use the existing `Logseq failed to create page: <name>` error if it returns `null`;
   - normalize the returned page;
   - replace `commandState.pageUuid` with the returned journal UUID before marking execution successful;
   - track only that actual UUID in `changedPages`.
4. If the name is not valid (including impossible date-shaped names), retain the existing `createPage` call and random `customUUID` behavior.
5. Keep the existing active/deleted UUID ownership checks. After first successful journal execution, the persisted actual UUID allows revert and re-execution to delete/restore the same journal page.
6. Keep `revert()` unchanged: it already deletes by the now-authoritative state UUID and returns the command to `new`.

The mutation of `pageUuid` must occur only after a returned page is successfully normalized. A failed journal API call must leave the provisional state usable for diagnostics/retry and must not mark or track a page.

### 4.3 Add authoritative journal metadata lookup

Create `src/logseq/LogseqJournalHelper.ts` to isolate Datascript access and result validation.

- Add `isJournalPageUuid(pageUuid: string): Promise<boolean>` (or an equivalent `getJournalDayByPageUuid` returning `number | null`).
- Query the page entity directly by its validated UUID and require `:block/journal-day`, for example:

  ```clojure
  [:find ?journal-day
   :where
   [?page :block/uuid #uuid "<validated-page-uuid>"]
   [?page :block/journal-day ?journal-day]]
  ```

- Since `RenamePageCommandArgsSchema` already enforces canonical UUID syntax, safely construct the UUID literal in one helper rather than interpolating arbitrary input throughout commands.
- Return false/null for an empty result. Validate a matching row's journal day as an integer. Propagate query errors or malformed result shapes rather than silently allowing a potentially unsafe rename.
- Unit-test that the generated query uses direct `:block/uuid` plus `:block/journal-day` and does not traverse `:block/page`.

### 4.4 Guard both rename directions

Update `RenamePageCommand.execute()` in `src/core/logseq-reversible-transaction-tracker/commands/RenamePageCommand.ts`.

1. Resolve the source with `requireActivePage` as today.
2. Before changing command state, changed pages, or the graph, query the source page UUID through `LogseqJournalHelper`.
3. If it is a journal, throw a stable command error such as `Cannot rename a journal page using RenamePageCommand.`
4. If `isJournalPageName(this.args.newName)` is true, throw `Cannot rename a page to a journal page name using RenamePageCommand.`
5. Preserve the existing rename and revert flow for all other names. In particular, an impossible date such as `Feb 30th, 2026` is permitted as an ordinary target name.
6. Check the source first, so attempts to rename a journal produce the source-journal error regardless of target.

No `DeletePageCommand` change is included.

### 4.5 Keep tool guidance synchronized

Update `src/chat-app/prompts/SKILL_LOGSEQ_TOOLS_GUIDE.md` to state that:

- formatted journal names passed to page creation create journal pages;
- journal pages may be deleted/restored;
- journal pages cannot be renamed, and ordinary pages cannot be renamed to a valid journal-formatted name.

No chat tool schema/registry change is needed because validation and API routing remain encapsulated in the commands.
