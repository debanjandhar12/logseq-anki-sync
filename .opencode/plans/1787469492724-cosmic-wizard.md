# Remove Unused Mustache Template View Keys

## User Requirement

> Check usage and if none, remove
>
> ```
> additionalSystemMessage: values.globalAgentInstruction,
> "additional system message": values.globalAgentInstruction,
>         "current page": values.currentPage,
>         "current editing block": values.currentEditingBlock,
>         "model invokable skill list": values.modelInvokableSkillList,
>         view[`last${weekday}`] = values.lastWeekdays[weekday];
> ```
>
> from MustacheView.ts
>
> Note: only additionalSystemMessage is being completely removed. Other have aliases which remain.

## Final Requirement After Discussion

### Clarification Q&A

1. **Q:** All 6 listed keys have zero real consumption — only tests assert on some of them. Remove all 6 and update those tests?
   **A:** Yes, remove them all; update the referencing tests.
2. **Q:** Removal breaks end-user stored skill files using e.g. `<% current page %>`, `<% additionalSystemMessage %>`, `<% lastFriday %>` (render empty + editor lint errors). Accept?
   **A:** Yes, accept breakage. No migration docs needed.

### Final Summarized Requirements

Remove exactly the six listed view-key entries from `createMustacheViewFromValues()` in `src/core/template-engine/MustacheView.ts`. Post-conditions:

- The `globalAgentInstruction` value is exposed **only** via the `globalAgentInstruction` key.
- `currentPage`, `currentEditingBlock`, `modelInvokableSkillList` keep their canonical camelCase keys (spaced aliases gone).
- Weekdays keep **only** the spaced lowercase form (`last monday` … `last sunday`); camelCase forms (`lastMonday` …) are gone.
- Validation whitelist (`validateMustacheTemplate`) and skill-editor autocomplete shrink automatically since both derive from `getMustacheTemplateVariableNames()`.

## Existing System

- `src/core/template-engine/MustacheView.ts`:
  - `createMustacheViewFromValues(values)` builds a flat `Record<string, string>` view: 10 canonical keys + 5 compatibility aliases + 14 weekday entries, then wraps it in `createCaseInsensitiveMustacheView()` (Proxy doing case-insensitive lookup; lowercased index map preserves spaces, so `LASTSATURDAY` matches `lastSaturday` today but would never match `last saturday`).
  - `MUSTACHE_TEMPLATE_VARIABLE_NAMES` is frozen `Object.keys(createMustacheViewFromValues(EMPTY_MUSTACHE_VIEW_VALUES))` — the single source of truth for valid variables.
- Consumers of the key set:
  - `src/core/template-engine/validateMustacheTemplate.ts` — lints templates against the derived name set (`Unknown Mustache variable: <name>`); used by the Skill Editor linter.
  - `src/ui/pages/SkillEditorModal/createSkillEditorExtensions.ts` — autocomplete options built from the same set.
  - Runtime rendering (`parseTemplateString.ts`) does not consult the name list; unknown vars render as empty strings (mustache.js default).
- Usage audit result (all six keys): **no built-in prompt, doc, or runtime consumption anywhere.** Only self-referential test assertions/fixtures reference some of them. Critically, `modelInvokableSkillList` (camelCase) IS used by `src/chat-app/prompts/MAIN_SYSTEM_MESSAGE.md:30` — it is not being removed; only its spaced alias is.
- Docusaurus docs contain zero references to any affected key — no documentation updates required.

## Solution

### 1. `src/core/template-engine/MustacheView.ts`

In `createMustacheViewFromValues()` delete these object entries:

```ts
additionalSystemMessage: values.globalAgentInstruction,
"additional system message": values.globalAgentInstruction,
"current page": values.currentPage,
"current editing block": values.currentEditingBlock,
"model invokable skill list": values.modelInvokableSkillList,
```

In the weekday loop, delete the camelCase assignment and keep the spaced alias:

```ts
for (const [weekday] of WEEKDAYS) {
    view[`last ${weekday.toLowerCase()}`] = values.lastWeekdays[weekday];
}
```

Resulting view shape (19 keys): `globalAgentInstruction`, `currentPage`, `currentEditingBlock`, `modelInvokableSkillList`, `chatAppAgentToolResultMaxChar`, `time`, `today`, `tomorrow`, `yesterday`, `userTimeZone`, plus `last sunday` … `last saturday`.

No other changes in this file:
- `MustacheViewValues` interface, `EMPTY_MUSTACHE_VIEW_VALUES`, and async `createMustacheView()` supply *values*, not view keys — untouched.
- `getMustacheTemplateVariableNames()` derives from the view shape, so validator + autocomplete updates automatically.

### 2. `tests/src/core/template-engine/MustacheView.test.ts`

First test ("exposes canonical variables and compatibility aliases"):
- Delete assertions on `view.additionalSystemMessage`, `view["additional system message"]`, `view.ADDITIONALSYSTEMMESSAGE`, `view["current page"]`, `view.lastSaturday`, and `view["last saturday"] === view.lastSaturday`.
- Preserve feature coverage instead:
  - Case-insensitive proxy: `expect(view.GLOBALAGENTINSTRUCTION).toBe("Be precise");`
  - Spaced weekday alias resolves: `expect(view["last saturday"]).toBe("2026-08-15");` (mocked format `YYYY-MM-DD`, base date `2026-08-22T12:30:00`)
- Keep `view.globalAgentInstruction`, `view.currentPage`, `view.lastSaturday`→drop, rename test to reflect canonical keys + spaced aliases (e.g. "exposes canonical variables and spaced aliases").

Second test ("derives supported variable names from the synchronous view shape"):
- Replace `toContain("additional system message")` with `toContain("currentEditingBlock")` (or similar surviving key) and add negative assertions: `not.toContain("additionalSystemMessage")`, `not.toContain("lastMonday")`.
- Drop `expect(view.lastSunday)`; keep `expect(view["last sunday"]).toBe("Sunday")`.

### 3. `tests/src/core/template-engine/validateMustacheTemplate.test.ts`

Line 8 fixture `"<% globalAgentInstruction %> <% additional system message %> <% TODAY %>"` → swap the removed alias for a surviving spaced alias so the test still covers canonical + alias + case-only variants: `"<% globalAgentInstruction %> <% last sunday %> <% TODAY %>"`.

### 4. `tests/src/ui/pages/SkillEditorModal/validateSkillFiles.test.ts`

Line 38 fixture `"<% current page %>"` → `"<% currentPage %>"` (keeps exercising the multi-valid-files path).

### Not changed (verified)

- `tests/src/ui/components/LogseqCodeEditor/extensions/mustache.test.ts` — autocomplete mechanics test with its own inline `variableNames` fixture; independent of the real list.
- `MAIN_SYSTEM_MESSAGE.md` uses canonical `modelInvokableSkillList` — unaffected.

### Edge cases / behavior notes

- Removed keys fail validation loudly in the Skill Editor (`Unknown Mustache variable`) but render as empty at runtime (mustache.js) — accepted by user decision.
- Case-insensitivity cannot rescue removed camelCase weekdays: proxy normalization keeps the space (`last saturday` → `last saturday`), so `<% lastFriday %>` no longer resolves. Intended.
