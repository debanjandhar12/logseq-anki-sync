# Chat Message Typography Adjustment

## 1. User Requirement

> I need you to adjust the text size of the user and assistant to be slightly smaller. Check assistant ui docs and figure out the best way to adjust the text height.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Question:** Should the change target font size, line height, or both, and what values should normal user/assistant prose use?
- **Answer:** Use **14px font size with 22px line height**.

### 2.2 Final Summarized Requirements

- Render normal user-message and assistant-message prose at `14px` with an exact `22px` line height.
- Scope the change to textual message content; do not resize attachments, action bars, branch controls, reasoning panels, tool UIs, errors, or activity indicators.
- Preserve the assistant Markdown hierarchy: headings and fenced code keep their existing explicit typography, while prose such as paragraphs, lists, links, blockquotes, and table text becomes smaller.
- Keep the customization local to the chat application and do not modify the assistant-ui registry source under `src/shadcn/`.

## 3. Existing System

- `src/chat-app/components/Thread.tsx` renders the project-owned `ThreadMessage`, which dispatches to `UserMessage` and `AssistantMessage`; the similarly named message implementations in `src/shadcn/assistant-ui/thread.tsx` are not active for chat messages.
- `src/chat-app/components/UserMessage.tsx` renders text through `MessagePrimitive.Parts` inside `.aui-user-message-content`. It currently has no explicit font size or line height, so the default text paragraph inherits Shadow DOM typography.
- `src/chat-app/components/AssistantMessage.tsx` renders only text parts through `MarkdownText`; reasoning, tools, data, indicators, and errors use separate render paths. Its broad content wrapper has `leading-relaxed`, so changing that wrapper would also risk changing non-prose UI.
- `src/shadcn/assistant-ui/markdown-text.tsx` gives the Markdown container the stable `.aui-md` class. Paragraphs and list items additionally use `.aui-md-p`/`.aui-md-li` with `leading-relaxed`; headings and fenced code have explicit `text-*`/line-height utilities.
- `src/chat-app/App.tsx` injects `src/chat-app/style/main.css` into the chat's `ShadowWrapper`, after the shared Tailwind stylesheet. The chat stylesheet is therefore the established place for scoped chat-only CSS overrides.
- The installed versions are `@assistant-ui/react@0.14.27` and `@assistant-ui/react-markdown@0.14.6`.
- Current assistant-ui documentation confirms that primitives are intentionally styleable through local `className`/CSS, demonstrates typography on the message content bubble rather than `MessagePrimitive.Root`, and explicitly expects the locally installed Markdown component to be customizable:
  - https://www.assistant-ui.com/docs/primitives/message
  - https://www.assistant-ui.com/docs/ui/markdown
- There are no existing user-message or Markdown typography tests. The existing `AssistantMessage.test.ts` only verifies message-part grouping.

## 4. Solution

### 4.1 Add scoped chat typography rules

Modify only `src/chat-app/style/main.css`.

1. Add a documented rule for `.aui-user-message-content`:
   - `font-size: 14px`
   - `line-height: 22px`
   - The assistant-ui default user text paragraph inherits these values.
   - The selector intentionally targets the inner bubble rather than `MessagePrimitive.Root`, leaving attachments, the action bar, and branch picker unchanged.

2. Add a documented rule for `.aui-md`:
   - `font-size: 14px`
   - `line-height: 22px`
   - This scopes the assistant size change to Markdown text parts, excluding sibling reasoning/tool/data/error UI.
   - Ordinary descendants (links, emphasis, blockquotes, tables, and inline prose) inherit the new values. Existing explicit heading sizes, code-header size, and fenced-code size continue to override inherited font size.

3. Override the Markdown elements that currently declare their own line height:

   ```css
   .aui-md .aui-md-p,
   .aui-md .aui-md-li {
       line-height: 22px;
   }
   ```

   This produces the requested exact text height for paragraphs and both compact and loose Markdown lists instead of Tailwind's proportional `leading-relaxed` value. Do not target `.aui-md-pre`, so fenced code retains its current `13px` and relaxed line height.

4. Keep the selectors in the chat-only stylesheet instead of copying or editing the 259-line registry Markdown component. The existing semantic class hooks provide a smaller, upgrade-safe customization surface, and `src/shadcn/AGENTS.md` requires registry files to remain original.

### 4.2 Compatibility and edge cases

- Long and multiline user text will retain existing wrapping and bubble padding; only glyph and line-box dimensions change.
- Assistant paragraphs, nested lists, blockquotes, and table text receive the compact base typography. Paragraph/list selectors ensure explicit `leading-relaxed` utilities do not defeat the exact `22px` target.
- Markdown headings preserve their explicit size scale and Tailwind-provided line heights. Fenced code preserves `text-[13px] leading-relaxed`. Inline code intentionally remains `0.85em`, scaling relative to the newly smaller surrounding prose.
- Since the CSS is injected inside `ShadowWrapper`, the rules affect only this chat UI and do not leak into Logseq or other plugin interfaces.
- No user setting, runtime state, data flow, package update, or documentation change is required.

## 5. Verification

### Automated checks

1. Format and lint the sole modified implementation file as required by the repository:

   ```bash
   pnpm run check:fix src/chat-app/style/main.css --reporter=summary
   ```

2. Run type checking and the production build to ensure the inline stylesheet continues to load through Vite and Tailwind/Shadow DOM bundling succeeds:

   ```bash
   npx tsc --noEmit
   pnpm build
   ```

3. Run the existing suite for regressions (noting that integration tests can require the Logseq API proxy at `127.0.0.1:12315`):

   ```bash
   pnpm test --run --reporter=dot --silent
   ```

No new unit test is planned for this static CSS-only adjustment: jsdom does not validate the production Shadow DOM/Tailwind cascade or computed pixel values, and a source-string/class contract test would duplicate the stylesheet without testing rendered behavior.

### Manual end-to-end validation

Run the plugin in Logseq and inspect a thread containing:

- single-line and multiline user messages;
- assistant paragraphs, links, bold/italic text, blockquotes, compact and nested lists, a table, headings, inline code, and fenced code;
- an assistant response with reasoning/tool UI and an error or activity state where available.

In browser developer tools, verify computed styles inside the chat Shadow DOM:

- `.aui-user-message-content` and its default text paragraph resolve to `font-size: 14px` and `line-height: 22px`;
- `.aui-md` prose, `.aui-md-p`, and `.aui-md-li` resolve to `14px/22px`;
- headings, fenced code, reasoning/tool content, controls, attachments, and message errors retain their prior typography and layout;
- text still wraps correctly and message/action-bar spacing does not overlap at narrow sidebar widths.
