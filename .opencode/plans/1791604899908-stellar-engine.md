### 3.3 Duplication / structural problems

- `bytesEqual`, `byDepthAscending/Descending`, `depth` are copy-pasted in two files.
- The snapshot is two parallel arrays; each consumer rebuilds `Map`/`Set` indexes (`collectSandboxChanges`, `findSnapshotConflicts`, `snapshotChildren`).
- `collectSandboxChanges` mixes I/O (MEMFS walk) with diff rules, so diff rules can only be tested with real Pyodide.
- Entry-equality rules exist twice (worker: "file changed?", host: "live entry still equals snapshot entry?").
- Budget logic is spread over 5 tiny files (constants, 2 asserts, formatBytes, error).
- Shared code used by the worker lives in the host-only folder (worker imports `../just-bash-fs-bridge/utils/assert*`), which blurs the host/worker boundary.

### 3.4 Constraints (verified)

- Logseq plugin iframe: no `SharedArrayBuffer`, not `crossOriginIsolated`; `lsp://` scheme is registered without `allowServiceWorkers`.
- Host storage (`LogseqPluginStorageManager`, `JustBashAdapterFS`) is Promise-only, UTF-8 text only, mtime always epoch 0.
- just-bash 3.2.0 `IFileSystem` is async (only `resolvePath`/`getAllPaths` sync).
- Pyodide 314.0.6 / Emscripten 5.0.3: FS `node_ops`/`stream_ops` are synchronous; FS syscalls are not JSPI-suspendable.

### 3.5 Project conventions observed

- Helpers: `src/core/just-bash-wrapper/utils/` (`fsPaths.ts`, `fsErrors.ts`, `fsContent.ts`) and the c97167c2 pattern `just-bash-fs-bridge/utils/<exportName>.ts` (one export per file, file named after it).
- Classes in PascalCase files (`JustBashAdapterFS.ts`, `ReadOnlyFileSystem.ts`, `SandboxSnapshotError.ts`).
- Tests mirror `src/` under `tests/src/`.

## 4. Findings

### 4.1 (a) Live adapter just-bash <-> Emscripten FS

**Not possible in this environment.**
- Emscripten FS callbacks must return synchronously. The host FS is async, and without SAB + `Atomics.wait` the worker cannot block while it waits for a postMessage reply.
- just-bash's own `python3` (CPython, not Pyodide) does exactly this via a SAB `SyncBackend` + custom `HOSTFS` and is documented Node-only. Its `createHOSTFS` is internal/unexported.
- JSPI (Chrome 137+, supported by Pyodide 314) does not help: `__syscall_openat`/`FS.read` consume `node_ops` results synchronously and are not wrapped with `WebAssembly.Suspending`. A Python-level facade (`builtins.open` patch + `run_sync`) is possible but only partial (C extensions bypass it), and it would be more code to maintain.
- Main-thread Pyodide does not help (FS still sync, storage still async).
- Sync XHR to a service worker (JupyterLite DriveFS / `sync-message`) would work without SAB, but Logseq's `lsp` scheme does not allow service workers; changing that requires the Electron main process.
- The inverse (Pyodide MEMFS as the shared FS, as in `luqs1/tab-agent`) would require Pyodide on the main thread, permanently loaded, and MEMFS to become the source of truth instead of Logseq storage. Not suitable.

**On the readwrite remark: correct.** Write-back already goes through `context.fs` (`MountableFs` -> `JustBashAdapterFS`), so registering a mount with `"readwrite"` works today with no bridge changes. The only caveat is that storage is UTF-8 only, so writing binary files into such a mount fails at write-back (`fsContent.ts` uses a fatal decoder) and is reported on stderr.

### 4.2 (b) Library to replace the manual sync

None fits. Checked:
- Pyodide `mountNativeFS`/`syncfs` and Emscripten IDBFS: same MEMFS + reconcile pattern, but they reconcile by mtime (ours is always 0) and delete paths that exist only at the destination, which would delete host files created during a run. No conflict detection.
- memfs / `@jsonjoy.com/fs-snapshot`: serialization only, no diff, restore overlays without deletes, Node-style stat API.
- Tree diff libraries (`fs-tree-diff`, `dir-compare`, `jsondiffpatch`): either tied to Node or would still need our own walking, byte comparison and guarded apply.

### 4.3 (c) Common adapter library: ZenFS deep dive

`@zenfs/core` 2.7.6 + `@zenfs/emscripten` 1.0.10 (Port backend + Async cache + EmscriptenPlugin). **Not recommended:**
- `Async` preloads the whole tree into a worker cache, so it is still a snapshot and copies no less data.
- Writes succeed on the local cache; host failures surface later. `Async.sync()` suppresses queued failures (`await this._promise.catch(() => {})`), so EROFS write-backs would be silently lost unless we hook into internals.
- No conflict detection; writes already sent persist after abort/timeout; Port timeout default 250 ms and timeouts don't cancel.
- Smoke test with Pyodide 314.0.6 found plugin bugs: fd 0 leak (content can stay in cache), `utime` ignored (`attr.timestamp` vs `attr.atime/mtime`), `mmap` ENODEV, root mode not copied.
- A custom backend over `IFileSystem` must emulate byte-range IO over whole-file text storage (intermediate invalid UTF-8 states), inode ids, errno mapping.
- Estimated code to reach parity: 450-750 LOC added vs 386 removed (750-1,150 for the "ZenFS as single source of truth" variant). ~85 KB gzip per bundle (bridge today is ~2 KB). LGPL-3.0 (its web-app exception probably doesn't cover a distributed Electron plugin). In practice one maintainer.
- Worth revisiting only if all of these become true: the project independently wants one Node-compatible VFS shared by many runtimes, all writers go through it, and write-through semantics without conflict detection are acceptable.

### 4.4 (d) Other approaches

1. **Refactor our own bridge around one shared tree model and one pure diff function** (chosen; section 5). Biggest maintenance win per line changed.
2. Custom Emscripten FS type `SandboxSyncFS` (MEMFS + `syncfs` pull/push over comlink, the `mountNativeFS` pattern): rejected for now. It adds ~50 LOC over (1), moves the write-back trigger into the worker (abort/merge logic crosses comlink), and `FS.syncfs` syncs every mount. It only pays off with long-lived workers or mid-run sync.
3. Upstream: just-bash issue #121 (browser Pyodide) is open. If upstream ships a browser Python, re-evaluate dropping our implementation.

## 5. Solution: shared sandbox tree model

### 5.1 Structure decisions

- **Plain data + standalone functions, not a class.** The snapshot crosses the comlink boundary by structured clone, which drops prototypes. A `SandboxTree` class would arrive in the worker as a plain object, so we would need rehydration code on every hop (`SandboxTree.fromJSON`). Plain types with pure functions avoid that and are trivially testable.
- **Exception: `SandboxBudget` is a class.** It holds mutable running state (`totalBytes`), is created locally on each side, and never crosses comlink.
- **File naming:** `types.ts` = types only (no runtime code). `utils/<exportName>.ts` = exactly one exported function. Classes and errors = `<ClassName>.ts`. Constants = `constants.ts`.
- **Folder ownership:** `sandbox-tree/` = pure, shared by host and worker (no `IFileSystem`, no `PyodideFS`). `just-bash-fs-bridge/` = host only (imports `IFileSystem`). `worker/` = worker only (imports `PyodideFS`). The worker never imports from `just-bash-fs-bridge/`.

### 5.5 `sandbox-tree/diffSandboxTrees.ts`

```ts
/** Pure: changes that turn `base` into `next`. Mode-only changes are ignored. */
export function diffSandboxTrees(
    base: SandboxSnapshot,
    next: SandboxSnapshot,
    skippedPaths: ReadonlySet<string> = new Set()
): Omit<SandboxChanges, "unsupported">
```

Rules (identical to current `collectSandboxChanges`):
- `next` dir that is not a dir in `base` (and not root) -> `createdDirectories`.
- `next` file where `!isSameEntry(base.entries.get(path), entry)` -> `writtenFiles` (covers new, modified, dir->file).
- `base` file whose path is not a file in `next` and not in `skippedPaths` -> `deletedFiles`.
- `base` dir (not root) whose path is not a dir in `next` and not in `skippedPaths` -> `deletedDirectories`.
- Sorting: `createdDirectories` by `compareByDepthAscending`, `deletedFiles` lexical, `deletedDirectories` by `compareByDepthDescending`.
- `skippedPaths` = paths reported as `unsupported` (e.g. symlinks), mirroring today's `seenFiles/seenDirectories.add(path)` for links so they are not reported as deletions.

### 5.6 `sandbox-tree/SandboxBudget.ts` + `SandboxSnapshotError.ts` + `constants.ts`

Replaces `assertFileWithinSnapshotBudget.ts` and `assertTotalWithinSnapshotBudget.ts`, keeping the same messages:

```ts
export class SandboxBudget {

    /** Pre-check (e.g. from stat size) before reading content. Throws SandboxSnapshotError. */

```

### 5.7 Host: `just-bash-fs-bridge/utils/readHostEntry.ts`


### 5.8 Host: `just-bash-fs-bridge/captureSandboxSnapshot.ts` (~20 LOC)

Same export and signature.

```ts
const root = filesystem.resolvePath("/", rootPath);
const budget = new SandboxBudget();
const entries = new Map<string, SandboxEntry>();
async function visit(path: string) {
    const entry = await readHostEntry(filesystem, path, budget);
    if (!entry) throw new SandboxSnapshotError(`missing filesystem entry: ${path}`);
    entries.set(path, entry);
    if (entry.kind !== "directory") return;
    for (const name of (await filesystem.readdir(path)).sort()) await visit(joinSandboxPath(path, name));
}
await visit(root);
return {root, entries};
```
Note: a missing root previously surfaced the raw fs ENOENT message; it now says `missing filesystem entry`. The caller still prefixes `cannot snapshot sandbox filesystem:` and the exit code (1) is unchanged.

### 5.9 Host: `just-bash-fs-bridge/utils/findSnapshotConflicts.ts`

Extracted from `applySandboxChanges.ts`. Same signature as today's private function:

```ts
export async function findSnapshotConflicts(
    filesystem: IFileSystem, changes: SandboxChanges, snapshot: SandboxSnapshot
): Promise<WriteBackFailure[]> {
    const deletedDirectories = new Set(changes.deletedDirectories);
    const directPaths = [...deletedFiles, ...deletedDirectories, ...createdDirectories, ...writtenFiles.map(p)];
    const affectedPaths = new Set(directPaths.flatMap((path) => [path, ...listAncestorsWithinRoot(path, snapshot.root)]));
    for (const path of affectedPaths) {
        try {
            const live = await readHostEntry(filesystem, path);       // no budget
            const original = snapshot.entries.get(path);
            if (!isSameEntry(original, live)) { failures.push(conflict(path)); continue; }
            if (original?.kind === "directory" && deletedDirectories.has(path)
                && !sameNames(await filesystem.readdir(path), listSnapshotChildren(snapshot, path))) {
                failures.push(conflict(path));
            }
        } catch (error) { failures.push({path, message: getErrorMessage(error)}); }
    }
    return failures;
}
// private in this file: conflict(path), sameNames(left, right)
```
Behavioural nuance: a live symlink at an affected path is now reported as `symbolic links are not supported: <path>` instead of the generic conflict message. It is still a failure, so nothing is written. Update the test if one covers it.

### 5.11 Worker: `readEmscriptenTree.ts` + `collectSandboxChanges.ts`

```ts
// worker/readEmscriptenTree.ts (~30 LOC)
export function readEmscriptenTree(filesystem: PyodideFS, root: string):
    {tree: SandboxSnapshot; unsupported: SandboxChanges["unsupported"]}
// link -> unsupported "symbolic links are not supported" (do not descend);
// dir -> entry + recurse (skip "." / ".."); file -> entry with readFile + mode & 0o777;
// other -> unsupported "unsupported filesystem entry".

// worker/collectSandboxChanges.ts (~15 LOC), same export + signature
export function collectSandboxChanges(filesystem: PyodideFS, snapshot: SandboxSnapshot): SandboxChanges {
    const {tree, unsupported} = readEmscriptenTree(filesystem, snapshot.root);
    const changes = diffSandboxTrees(snapshot, tree, new Set(unsupported.map(({path}) => path)));
    const budget = new SandboxBudget();
    for (const {path, content} of changes.writtenFiles) budget.add(path, content.byteLength);
    return {...changes, unsupported};
}
```
The budget still applies only to written files, as today. Memory: the walk holds references to all MEMFS file copies during the diff. `FS.readFile` already copied every file before this change, so peak memory is roughly the same.

### 5.12 Worker: `loadSandboxSnapshot.ts`

Same algorithm, iterating `snapshot.entries`. Root: `clearDirectory` if it exists, otherwise `mkdirTree`. Then `mkdirTree` for each dir, `writeFile` + `utime(0)` for each file, `chmod` files, `chmod` dirs ordered by `compareByDepthDescending`. Its private `byDepthDescending` is deleted.
