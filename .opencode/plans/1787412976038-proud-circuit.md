# Render Skill Templates and Improve Skill Authoring

## 1. User Requirement

> Currently we do not use template engine (mustache) during skill file read. It is currently used only in system message. Instead, we should parse it for skills in SkillTool.tsx before returning output. Aditionally, the current SkillFileEditor auto completes html for some reason? Instead we should autocomple markdown and mustache variables.
>
> Also, I also noticed a likely existing mismatch: 
> MAIN_SYSTEM_MESSAGE.md
>  uses <% globalAgentInstruction %>, while the Mustache view appears to expose that value under variants of additionalSystemMessage, so the current placeholder may render empty. => Plz fix this as well.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Question:** When the skill tool loads a skill, should Mustache render the entire stored file (including YAML frontmatter) or only the Markdown body?
  - **Answer:** Entire file.
- **Question:** What should “autocomplete Markdown” mean in the Skill Editor?
  - **Answer:** Markdown syntax snippets while disabling HTML tag completion; if snippets prove unsupported or disproportionately difficult, disabling HTML completion is the minimum requirement.
- **Question:** How should selecting a Mustache variable completion insert text?
  - **Answer:** Insert a complete `<% variable %>` tag and avoid duplicating an existing `%>`.
- **Question:** How should invalid Mustache in the Skill Editor be handled?
  - **Answer:** Show inline diagnostics for malformed syntax and unknown variables, and block saving until every skill file is valid.
- **Question:** Should validation apply only to interpolated variables, or also require Mustache section names to be supported variables?
  - **Answer:** Validate interpolated variables only. Ignore section/control names, including the build-time `includeFile` section.

### 2.2 Final Summarized Requirements

- Render the complete stored skill source through the existing runtime Mustache engine each time `SkillTool` loads it, before returning `skillFileContent`.
- Preserve storage, filename lookup, response shape, and existing error handling; rendering must not mutate or save the source skill.
- Keep CodeMirror Markdown language support in the Skills Editor but disable its default HTML-tag suggestions.
- Add focused Markdown syntax-snippet completions using CodeMirror’s supported completion APIs, without trying to implement a new Markdown language service.
- Add completion for all supported runtime template variables. Completion is active inside an unfinished `<% ...` tag and replaces it with one complete tag without duplicating `%>`.
- Validate the complete source of every skill for malformed Mustache and unsupported interpolated variables. Display active-file errors inline and prevent persistence if any active or inactive skill is invalid.
- Make `globalAgentInstruction` a supported canonical template variable while preserving the existing `additionalSystemMessage` aliases.
- Add regression tests and skill-authoring documentation.

## 3. Existing System

- `src/core/template-engine/parseTemplateString.ts` is the shared runtime renderer. It uses Mustache with `<%` / `%>` delimiters, creates the dynamic default view when none is supplied, and performs case-insensitive key lookup.
- Mustache 4.2 exposes `Mustache.parse(template, tags)`, whose token tree and offsets can validate real Mustache syntax more reliably than regular expressions. Unknown names otherwise render silently as empty strings.
- `src/core/template-engine/MustacheView.ts` resolves settings, current Logseq page/block, dates/timezone, tool-result limit, and enabled skill metadata. It currently reads `globalAgentInstruction` but stores that value only under `additionalSystemMessage` variants.
- `src/chat-app/hooks/useAssistantModelContext.tsx` currently provides the only `parseTemplateString()` application call and renders `MAIN_SYSTEM_MESSAGE.md` as model system context.
- `src/chat-app/tools/impl/SkillTool.tsx` reads a parsed `SkillFileData` and returns its original complete `content`, including YAML frontmatter, without rendering it.
- `src/ui/pages/SkillEditorModal.tsx` renders the shared `LogseqCodeEditor` with `markdown()`. `@codemirror/lang-markdown` enables HTML-tag completion by default (`completeHTMLTags: true`), while the shared editor’s basic setup activates CodeMirror autocompletion.
- `LogseqCodeEditor` is generic and used outside skill authoring, so skill-specific completions belong in a skill-editor extension rather than in the shared wrapper.
- The installed Markdown language package does not supply general Markdown syntax snippets. A small CodeMirror snippet source is therefore required to offer Markdown constructs.
- Built-in `<% #includeFile %>...<% /includeFile %>` expansion in `vite-plugins/inlineSkillFilePlugin.ts` is a separate Vite build-time transformation and must remain unchanged.

## 4. Solution

### 4.1 Centralize the supported template-variable contract

Add `src/core/template-engine/mustacheTemplateVariables.ts` containing CodeMirror-independent metadata for each canonical runtime variable, its compatibility aliases, and a short author-facing description. It must contain no live Logseq/settings calls, allowing runtime view construction, validation, and UI completion to import it. Export a normalized, case-insensitive supported-name set from the same metadata.

Add `src/core/template-engine/mustacheTemplateConstants.ts` for the shared `<%` / `%>` delimiter tuple. Update `parseTemplateString.ts` and the validator below to use this constant so rendering and validation cannot drift.

Canonical names will be:

- `globalAgentInstruction`
- `currentPage`
- `currentEditingBlock`
- `modelInvokableSkillList`
- `chatAppAgentToolResultMaxChar`
- `time`, `today`, `tomorrow`, `yesterday`, `userTimeZone`
- `lastSunday` through `lastSaturday`

Preserve spaced compatibility aliases already accepted by stored/custom templates:

- `additionalSystemMessage` and `additional system message` for `globalAgentInstruction`
- `current page`, `current editing block`, and `model invokable skill list`
- `last sunday` through `last saturday`

Case-only variants such as `currentpage` and `additionalsystemmessage` remain supported by the existing case-insensitive proxy and need not appear as duplicate suggestions.

Update `src/core/template-engine/MustacheView.ts` to populate each canonical key and all explicit aliases from the same resolved value. Generate weekday values from the centralized weekday definitions. This adds the missing `globalAgentInstruction` key used by `MAIN_SYSTEM_MESSAGE.md` while retaining all older aliases. Keep trimming the configured global instruction and keep the existing fallback values for unavailable page/block context.

Do not change `MAIN_SYSTEM_MESSAGE.md`: it already uses the intended canonical setting/template name.

### 4.2 Render complete skills at tool-read time

Update `src/chat-app/tools/impl/SkillTool.tsx` to import `parseTemplateString` and, after a successful `SkillFileStore.getSkillFile(fileName)` lookup, execute:

```ts
const renderedSkillFileContent = await parseTemplateString(skillFile.content);
```

Return `renderedSkillFileContent` in the existing `ChatToolResponse.success({skillFileContent})` shape.

Behavioral constraints:

- Render the complete original source, including YAML frontmatter and Markdown body.
- Render on every tool invocation so page, block, date/time, settings, and enabled-skill values are current.
- Do not render the requested filename.
- Do not reparse, persist, or otherwise mutate the rendered result; raw metadata and storage identity remain based on the stored source.
- Leave unknown-variable and escaping behavior to the existing Mustache renderer.
- Let render failures flow through the tool’s existing `try/catch` and error response convention.

No changes are needed in `SkillFileStore`, the generic tool execution pipeline, or the build-time inline-skill Vite plugin.

### 4.3 Validate skill templates with the real Mustache parser

Add `src/core/template-engine/validateMustacheTemplate.ts` as a pure, UI-independent validator. It will:

- parse the complete source using `Mustache.parse(source, MUSTACHE_TEMPLATE_TAGS)` rather than regex matching;
- recursively inspect only escaped (`name`) and unescaped (`&`, including triple-Mustache) variable-reference tokens;
- compare names case-insensitively against the canonical/alias set from `mustacheTemplateVariables.ts`;
- return structured issues containing source offsets, the offending name, a stable message, and an `error` kind;
- report dotted names and `.` as unsupported because the runtime view is intentionally flat;
- ignore section, inverted-section, closing, partial, comment, and delimiter-change token names. This prevents false positives for `<% #includeFile %>` while still validating variable references nested inside section bodies;
- preserve Mustache's own parsing semantics in frontmatter, prose, and fenced/inline code, because runtime rendering also processes the entire file. Literal `{{...}}` Logseq macros remain inert under the custom delimiters;
- catch malformed/unclosed Mustache parse errors and convert them to a structured syntax issue. Use the parser's reported offset when available, otherwise highlight from the last unmatched `<%` to the end of its line/document so the editor always has a useful range.

Integrate the same pure validator in two places:

1. In the Skill Editor CodeMirror extensions, adapt issues to `@codemirror/lint` diagnostics and install `linter()` plus `lintGutter()` for inline underlines, hover messages, gutter markers, and existing lint-keymap navigation.
2. At the start of `SkillEditorModal`'s save validation, synchronously validate every file before any deletion/save. If an issue exists, switch to the first invalid file, show the existing Logseq validation message with its filename and issue, and return before persistence. Do not rely on debounced CodeMirror state, because only the active file has a mounted editor. Keep the Save action clickable so an error in an inactive file can navigate the user to it; “block Save” means reject persistence, not silently disable the button.

### 4.4 Add skill-specific CodeMirror completions

Add `@codemirror/autocomplete`, `@codemirror/lint`, and `@codemirror/state` as direct runtime dependencies in `package.json` (and regenerate `pnpm-lock.yaml`) because new source/tests will import their APIs directly rather than rely on transitive packages.

Add `src/ui/pages/skill-editor/skillEditorExtensions.ts` as the skill-specific CodeMirror integration. Keep the generic `LogseqCodeEditor` unchanged.

The extension module will expose:

1. `mustacheVariableCompletionSource`
   - Read options from the centralized template-variable metadata.
   - Activate only when the cursor is inside an unfinished, variable-like `<% ...` tag on the current line.
   - Reject completed tags and Mustache control/section prefixes (`#`, `^`, `/`, `!`, `>`, `&`).
   - Case-insensitively filter canonical names and aliases against the partially typed variable.
   - Present the complete tag and variable description.
   - Replace from the opening `<%` through the cursor, or through an existing trailing whitespace plus `%>`, with the selected full `<% variable %>` string. This prevents `%>%>` duplication.
   - Remain available in frontmatter and fenced code because runtime rendering applies to the complete skill source.

2. `markdownSyntaxCompletionSource`
   - Use CodeMirror `snippetCompletion()` for a deliberately small, maintainable set: headings, bullet/number/task lists, links/images, fenced and inline code, blockquotes, bold, italic, and horizontal rules.
   - Offer all snippets on explicit completion and context-relevant snippets after recognizable Markdown prefixes.
   - Restrict block snippets to line-leading/indented prefixes and suppress Markdown snippets inside YAML frontmatter, fenced/inline code, and unfinished Mustache tags.
   - This is snippet assistance only; Markdown parsing/highlighting remains owned by `@codemirror/lang-markdown`.

3. `createSkillEditorExtensions()`
   - Compose one configured `autocompletion({override: [...]})` instance with the two sources above.
   - Add `linter()` backed by `validateMustacheTemplate()` and `lintGutter()`; use a short idle delay while keeping save-time validation authoritative.

Update `src/ui/pages/SkillEditorModal.tsx` to:

- use `markdown({completeHTMLTags: false})`, preserving Markdown language behavior while removing HTML-tag suggestions;
- pass `basicSetup={{autocompletion: false}}` so the shared wrapper does not install a second autocomplete engine;
- include `createSkillEditorExtensions()` in the extensions list;
- memoize/staticize the extension array outside the render path so editor extensions are not recreated on each keystroke.

### 4.5 Tests

- `additionalSystemMessage`, `additional system message`, and case-only legacy spellings still resolve identically;

- renderer failures retain the tool’s error-result shape.

- canonical, alias, and case-only variable references are accepted in escaped and unescaped forms;
- unknown, dotted, and `.` references produce correctly ranged issues;
- malformed/unclosed tags produce syntax issues rather than throwing from the editor/save path;
- variables in frontmatter and fenced code are validated, while `{{...}}` Logseq macros remain literal;
- section/control names (especially `includeFile`) are ignored, but variable references nested inside sections are still validated;
- delimiter changes and nested Mustache token trees are handled according to Mustache parsing semantics.

Add `tests/src/ui/pages/skill-editor/skillEditorExtensions.test.ts` and exercise completion sources with `EditorState` / `CompletionContext` directly:

- partial Mustache names offer canonical variables and aliases with full-tag application;
- existing `%>` is consumed rather than duplicated;
- completed/control tags and text outside an open tag produce no Mustache completion;
- frontmatter and fenced-code Mustache tags remain eligible;
- Markdown explicit/prefix completion returns the intended snippets and observes excluded contexts;
- validator issues become CodeMirror error diagnostics with matching ranges/messages;
- the configured Markdown extension has HTML-tag completion disabled (covered at the extension boundary rather than by browser UI automation).

Add focused `SkillEditorModal` save-validation coverage (in an existing/new `.test.ts` file matching Vitest's configured include) to verify an invalid active or inactive skill prevents all deletes/saves, navigates to the first invalid file, and reports its filename; a valid skill still persists its original unrendered source.

Tests must mock default-view dependencies so they do not require a running Logseq API server.
