## 2. Final Requirement After Discussion With User

### Clarification Q&A

1. **Question:** Should this preserve the current Python command behavior, apart from adding the requested `py` alias, or also expand interpreter options such as `-m` and `--`?
   **Answer:** Preserve behavior (Recommended): refactor existing modes, add `py`, fix directly related correctness issues; no new interpreter features.
2. **Question:** If a CLI library requires more browser/argument compatibility glue than the current small parser, should the plan keep a small local parser? Use a timeout library where it demonstrably removes code.
   **Answer:** Yes, minimize maintenance (Recommended): use libraries only when they reduce total maintained code; a small local parser is acceptable.
3. **Follow-up:** The user asked for another suitable npm parsing library and initially selected `arg`, then explicitly superseded that selection with: **“Use yargs-parser...”**
   **Final decision:** Use `yargs-parser` with its browser entry and a narrowly scoped compatibility adapter. Do not add `arg` or Commander.

### Final Summarized Requirements

- Provide `createPythonCommands(...commandNames)` in `createPythonCommands.ts`; caller owns aliases and registers `python`, `python3`, and `py`.
- Use `yargs-parser/browser` for declarative interpreter option parsing; preserve existing option boundaries and supported spellings.
- Replace bespoke deadline machinery with a browser-compatible library without weakening cancellation or hard worker termination.
- Move worker code under singular `pyodide/worker/`, with focused exported functions and matching filenames; remove the monolithic runtime file.
- Preserve supported modes, output/error contracts, network restrictions, isolated filesystem, top-level await, micropip, and fresh-worker-per-command behavior.
- Fix narrowly related cleanup, output-recovery, and wrapper-variable collision defects. Add meaningful tests and update alias documentation.
- Do not introduce generic worker frameworks, additional CLI options, persistent workers, package-policy redesign, or unrelated repository changes.

## 3. Existing System

### Code paths and constraints

- `JustBashWrapper.createInstance()` in `src/core/just-bash-wrapper/JustBashWrapper.ts` registers the two exported command objects. It disables built-in Python and JavaScript, uses allowlisted fetch, and supplies a mounted virtual filesystem.
- `pyodide/pythonCommand.ts` privately creates individual commands. Its short parser handles first-token help/version, `-c CODE`, a script filename, `-`, or stdin source with no arguments. Everything after the code/script selector is forwarded verbatim as script arguments. It reads selected scripts through Bash's filesystem and strips a shebang.
- Stdin is just-bash's opaque `ByteString`; current code uses an unsafe cast plus `TextDecoder`. Public root exports include `latin1FromBytes`, `encodeUtf8ToBytes`, and `decodeBytesToUtf8`. The latter falls back to Latin-1 for invalid UTF-8, unlike the current replacement-character decoding.
- `pyodide/pyodideRuntime.ts` creates a worker for every invocation, wraps it with Comlink, waits for readiness (30 seconds), executes (120 seconds), races worker errors, forwards abort to host fetch, releases the proxy, and always terminates. `withDeadline` manually manages timers, event listeners, and promise settlement.
- `pyodide/pyodideWorker.ts` is a side-effectful Comlink entry. `pyodide/workerProtocol.ts` contains the shared host/worker types and remains at its current location.
- `pyodide/pyodideWorkerRuntime.ts` combines dynamic loading, global state, secured fetch, protected JS capabilities, Python I/O, micropip loading, Python source generation, execution, and cleanup.
- Only exact bundled WASM/stdlib URLs bypass host secure fetch. Remote requests, including package installation, go through the existing host network policy. Responses remain binary `Uint8Array` values.
- Python has its own Pyodide filesystem; selected Bash script source is passed into it, not a filesystem bridge. Worker termination discards package/runtime state.
- `vite-plugins/pyodideAssetsPlugin.ts` emits installed runtime assets; `vite.config.ts` uses ES workers and a `?worker` entry import. Asset serving/build behavior must remain intact.
- Direct dependencies are `comlink@4.4.2`, `pyodide@314.0.6`, and `just-bash@^3.2.0`. Repository Node engine is `>=22.12 <23`.

### Commit review findings

- `137961c4` replaced custom QuickJS with Pyodide and added command, worker, build assets, network integration, documentation, and tests.
- `04f8c7c4` corrected `SystemExit` result assignment, added integer validation, restricted JS capabilities, and validated Bash tool results. Preserve these protections.
- Current worker setup installs global fetch and configures I/O before entering `try/finally`; setup exceptions can skip cleanup.
- User code executes with `globals()` shared with the wrapper. A user assignment to `exit_code` can corrupt normal completion, and assignments to wrapper imports can interfere with error handling.
- Output capture repeatedly re-encodes the full accumulated string, leading to quadratic work. Decoder flushing in the catch path can throw again after overflow; diagnostic appending bypasses the cap.
- Existing tests cover command forwarding and host orchestration, but not actual Python wrapper semantics or worker helpers.

### Library investigation

- Commander targets Node CLI programs; using it here entails browser/process/output adapters while preserving unusual interpreter-tail semantics. Do not add Commander.
- Following the user's explicit choice, add `yargs-parser@22.0.0`. Its public `yargs-parser/browser` export avoids Node-specific libraries and accepts pre-tokenized argument arrays. Use that entry consistently in application and unit tests; do not import the Node entry and rely on polyfills.
- Add `@types/yargs-parser` as a dev dependency. Declare the browser subpath in `src/types/yargs-parser-browser.d.ts`, reusing the root package's `Parser` type rather than duplicating the parser API. Validate the declaration against the installed DefinitelyTyped exports when implementing.
- Do not deep-import just-bash's internal argument parser; it is not part of the public exports.
- Add `p-timeout@7.0.2` as a direct dependency. Its ESM implementation has no Node imports, supports `AbortSignal`, cleans timers/listeners, handles already-aborted inputs and late promise rejection, and supports the repository's Node version.
- Keep Comlink for RPC, Pyodide's existing I/O APIs, and standard `Request`/`Response`, `Proxy`, and streaming `TextDecoder`. No evaluated library replaces the domain-specific fetch/capability logic without adding adapters or weakening restrictions.
- Installed Pyodide includes runtime/stdlib assets and supports Node loading. Core wrapper tests can run against these local assets without downloading micropip; full browser worker/package behavior needs a browser/Logseq smoke test.

## 4. Solution

### A. Command factory and explicit aliases

Rename `pyodide/pythonCommand.ts` to `pyodide/createPythonCommands.ts`.

```ts
export function createPythonCommands(...commandNames: string[]) {
    return commandNames.map((commandName) =>
        defineCommand(commandName, async (args, context) => {
            // Existing mode selection and execution forwarding.
        })
    );
}
```

- Retain shared private help/error/stdin helpers and a private parsing adapter; do not export single-command constants or a second public factory. No consumers outside this repository require compatibility exports.
- Accept arbitrary caller-supplied aliases, not a union hard-coded to three names. Return an empty array for no aliases; reject empty/whitespace aliases and duplicate names synchronously with clear errors. Do not trim or silently deduplicate aliases.
- Help and parser errors use the selected alias. Version text remains unchanged; runtime diagnostics retain the existing `python:` prefix.
- Preserve first-argument help/version handling and tail forwarding. For example, `-c CODE --help -V` passes both tail tokens to Python; `script.py -c value` passes its tail unchanged. `-m` and interpreter-level `--` remain unsupported.
- Define yargs-parser options once: boolean `help`/`version`, aliases `h`/`V`, string `command`, alias `c`, and `narg: {command: 1}`. Disable `short-option-groups`, `camel-case-expansion`, `dot-notation`, `boolean-negation`, `parse-numbers`, `parse-positional-numbers`, and `duplicate-arguments-array`; enable `halt-at-non-option`. Use `.detailed()` so parser errors can be converted into the adapter's stable exit-2 errors.
- Keep the compatibility adapter small and explicit:
  1. A leading bare `-` or absent argument selects stdin source and bypasses option parsing.
  2. A leading non-option selects a script; parse with `halt-at-non-option` and preserve the original filename/tail array without coercion.
  3. For leading `-c`, reject an absent next token with the existing error, parse only an internal normalized `--command=${args[1]}` token, and preserve `args.slice(2)` as the untouched script tail. Normalizing to an equals-value token preserves empty code, code beginning with a dash, newlines, and embedded equals without letting script flags become interpreter options.
  4. For leading supported help/version spellings, parse only that first token, preserving current behavior that ignores subsequent arguments.
  5. Reject other leading option spellings directly with the existing unknown-option message. This deliberately prevents the library from accidentally adding `--command`, grouped flags, option equals forms, negations, or `--` to the public interface.
- Do not parse a joined command string: Bash has already tokenized quoting, pipelines, and heredocs. The library replaces option interpretation, not script loading or execution-mode semantics.
- Preserve current missing-source/file/fetch errors, filesystem resolution, exported environment, cwd, and signal forwarding.
- Remove the opaque stdin cast using `latin1FromBytes(context.stdin)` at the existing decoding boundary. Keep the small `TextDecoder` conversion to preserve malformed UTF-8 replacement semantics. Tests use `encodeUtf8ToBytes`, not casts.
- Correct shebang-only source handling: remove the entire first line even when no newline exists, then apply the empty-input check to the stripped source.
- Update `pyodide/index.ts` to export only the factory. In `JustBashWrapper.ts`:

```ts
customCommands: [...createPythonCommands("python", "python3", "py")],
python: false,
javascript: false
```

Update the comment to refer to Pyodide/custom commands rather than the removed filename.

### B. Replace deadline bookkeeping

Modify `pyodide/pyodideRuntime.ts`, `package.json`, and `pnpm-lock.yaml`. Dependency updates include both `p-timeout` and the chosen parser plus its development typings.

```ts
await pTimeout(Promise.race([client.ready(baseUrl), workerError]), {
    milliseconds: startupTimeoutMs,
    message: "worker startup timed out",
    signal: controller.signal
});
// Same pattern for execution with its own duration and message.
```

- Import `pTimeout` and `TimeoutError`; delete `withDeadline` and `PythonDeadlineError` entirely.
- Keep the worker-error race, injected worker/client factories, Comlink callback proxy, explicit execution payload, and host fetch signal binding.
- Check pre-aborted cancellation before calling readiness, and cancellation again before dispatching execution. Return `python: execution aborted\n`, exit 124, regardless of the caller's abort reason type; do not leak arbitrary reasons into this stable message.
- Normalize errors in this order: aborted controller -> existing cancellation result; `TimeoutError` -> phase-specific timeout result, exit 124; other errors -> existing failure, exit 1.
- Use one outer cleanup path after worker creation, including client-construction failure. The client is optional until construction succeeds. Remove the caller listener, abort host fetch, release the client if available, and terminate in nested `finally` so release failure cannot prevent termination.
- Do not mistake deadline rejection for cancellation of RPC/Python. `p-timeout` only rejects the wait; controller abort and unconditional worker termination remain authoritative.
- Internal duration overrides are test seams. Normalize finite values <= 0 to 1 ms (still an immediate timeout); permit positive finite values and positive infinity; reject NaN/negative infinity as configuration failures before dispatch. Defaults stay 30,000 and 120,000 ms.
- Remove worker event handlers during cleanup. Late operation rejection must be consumed; verify this with the pinned library and regression tests.

### C. Worker folder and explicit runtime ownership

Resulting implementation layout:

```text
pyodide/
  createPythonCommands.ts
  index.ts
  pyodideRuntime.ts
  workerProtocol.ts
  worker/
    pyodideWorker.ts
    initializePyodideWorker.ts
    executePythonInWorker.ts
    createWorkerFetch.ts
    createPythonGlobals.ts
    createPythonIO.ts
    createPythonExecution.ts
```

Remove old root `pyodideWorker.ts` and `pyodideWorkerRuntime.ts`. Change the Vite import to `./worker/pyodideWorker?worker`. Do not add a worker barrel or generic runtime abstraction.

**`worker/initializePyodideWorker.ts`** exports `initializePyodideWorker(runtimeBaseUrl)` and its concrete `PyodideWorkerRuntime` interface. Return an object containing Pyodide, bound original fetch, exact local asset URL set, and protected Python globals. Normalize the URL and use the existing dynamic import, indexURL, package CDN, and capability options. No unrelated module-level mutable state.

**`worker/pyodideWorker.ts`** remains the only side-effectful entry. Own one cached initialization promise. `ready` caches/awaits it; `execute` requires initialization and calls `executePythonInWorker(runtime, execution, fetch)`. Expose the unchanged `PythonWorkerApi` contract with Comlink. The host still performs exactly one execution per worker; do not implement worker pooling or concurrent execution.

**`worker/createPythonGlobals.ts`** exports `createPythonGlobals()`. Keep `protectCallable` and `protectConstructor` private in this module and preserve allowed capabilities/property traps exactly. Fetch is installed per execution and deleted in cleanup. Do not claim these proxies make Python a complete security sandbox or replace them with a generic deep proxy library.

**`worker/createWorkerFetch.ts`** exports `createWorkerFetch(hostFetch, originalFetch, allowedLocalAssetUrls)`. Preserve exact local URL exceptions and otherwise serialize Request method/headers/text body to the host callback. Preserve binary response body, metadata, and final `url`. Do not bypass secure fetch for additional URLs or redesign request-body support.

**`worker/createPythonIO.ts`** exports `createPythonIO(stdin)` returning Pyodide-compatible stdout/stderr write options, stdin options, an idempotent `finish()`, and a result/diagnostic accessor.

- Capture each stream independently with a streaming decoder and a running input-byte counter. Limit Python-produced bytes to 1 MiB per stream; check before decoding/appending. This eliminates full-buffer re-encoding on every write.
- Use per-execution chunk arrays and join only when producing results. Reject an overflowing write without storing it; retain prior accepted output.
- Keep an overflow flag, so subsequent writes fail consistently. `finish()` flushes each decoder once and is non-throwing even after overflow. Guard terminal decoder output at the same boundary.
- Diagnostic formatting deduplicates the caught message as before, but never re-enters a throwing output writer. Permit a separately bounded diagnostic suffix of at most 4 KiB on stderr; total result stderr is therefore bounded by the Python output cap plus that suffix. Test this explicit policy.
- Preserve line-oriented stdin including existing newline and EOF behavior. No stdin package is needed.

**`worker/createPythonExecution.ts`** exports `createPythonExecution(execution)` returning `{bootstrap, source}`. Keep current cwd/environment/argv setup and literal escaping through JSON for these string-only inputs.

- Generate an async Python wrapper function whose imports, exit status, and exception handling are locals.
- Evaluate user source in a separate fresh dictionary containing `__name__: "__main__"` and `__file__: execution.fileName`, not wrapper `globals()`.
- Retain `eval_code_async` for top-level await and filename-aware tracebacks.
- Return 0 on normal completion or `SystemExit(None)`, the integer for integer `SystemExit`, and print non-integer `SystemExit` to stderr and return 1. Ordinary exceptions propagate to the JS catch for existing traceback handling.
- Keep wrapper internals unreachable by ordinary user variable assignment; test assignments to `exit_code`, `sys`, and wrapper-like names.

**`worker/executePythonInWorker.ts`** exports `executePythonInWorker(runtime, execution, fetch)`.

1. Create per-execution I/O capture.
2. Enter `try` before creating/installing secured fetch or configuring Pyodide I/O.
3. Install secured worker fetch and protected `jsglobals.fetch`; configure I/O.
4. Load micropip using Pyodide's built-in package loader. Remove bespoke `micropipLoaded` state: the host uses a fresh worker, and Pyodide already handles loaded packages.
5. Run bootstrap, await wrapper execution, flush I/O, and validate the numeric result is an integer.
6. Catch setup/load/execution/output errors and return captured output plus bounded diagnostic with exit 1.
7. Always restore original global fetch, delete the exposed fetch capability, and release the callback's Comlink proxy. Release failure must not replace the command result.

Helpers receive explicit inputs and are independently importable without invoking Comlink `expose` or dynamically loading Pyodide. Keep shared types in `workerProtocol.ts`; no protocol wire-format changes.

## 5. Verification

### Automated cases

- Factory: arbitrary aliases, no aliases, duplicate/blank rejection, alias-specific help/errors, versions, stdin/script/`-c` modes, shebang-only script, missing input/file/fetch, environment and cancellation forwarding.
- Argument tails: flags and empty strings after script or `-c CODE` remain exact; unsupported interpreter options remain errors without runtime invocation.
- Parser compatibility: numeric-looking strings such as `001`, code beginning with `-`, empty code, code with equals/newlines, and flags immediately after `-c CODE`. Confirm no grouped flags, equals-form interpreter options, negated options, or `--command` are accidentally enabled. Browser-entry import must resolve in Vitest and the production build without Node parser dependencies.
- Stdin: ASCII, Unicode/emoji using `encodeUtf8ToBytes`, and malformed UTF-8 retain documented existing replacement behavior.
- Host: readiness gate, success, startup/execution deadline, pre/mid abort with custom reason, worker error/messageerror, worker/client construction failure, release failure, binary fetch, host-fetch abort, late rejection, timer/listener cleanup, duration edge cases.
- I/O: split multibyte sequences, independent streams, final unterminated input line, exact cap/overflow, safe repeated finish, bounded diagnostic, no second exception during recovery.
- Worker: every setup step failure restores fetch and releases the callback; package failures and invalid exit values return ordinary failure results. Protected globals retain denied property access and allowed calls/constructors.
- Fetch: only exact local runtime assets use original fetch; all other URLs use host callback; preserve body bytes and response metadata; rejection propagation.
- Real local Python: normal return, top-level await, argv/cwd/env, quoted/Unicode source and filenames, `__name__`, `SystemExit` None/int/string, ordinary traceback, and user variable collisions do not corrupt wrapper results.
