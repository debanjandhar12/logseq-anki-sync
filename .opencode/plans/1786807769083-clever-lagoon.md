## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Q: Which built-in provider-to-title-model mapping should be used?**
  - **A:** Initially requested `gpt-5.6-luna` and `gemini-3.5-flash-lite`; both IDs were verified in the installed model snapshot.
- **Subsequent requirement change:** “Actually, we should generate title using same model as current user model. That way we get advantage of context cache. We can add our prompt as a later use message.”
- **Q: What request shape should be used for cache-prefix reuse?**
  - **A:** Send exactly two user messages: the original first-user text first, then the title instruction. Do not include an assistant reply, full chat, main system prompt, tools, or reasoning configuration.
- **Q: Should the provider-to-title-model mapping remain after selecting the current user model?**
  - **A:** No. Drop the title-model mapping. Still create `src/core/ai-sdk/constants.ts` and move `PROVIDER_SNAPSHOT_KEY` there.
- **Q: How should the current user model be resolved?**
  - **A:** Read persisted `selectedModelId` from plugin settings. If it is unavailable, use the required fallback rather than selecting another model.
- **Q: How should model output be handled?**
  - **A:** Normalize it rather than persisting the raw response or relying only on the prompt.

### 2.2 Final Summarized Requirements

- Replace the deterministic vocabulary/POS title implementation with an asynchronous AI SDK `generateText` call.
- Use the persisted current chat model (`selectedModelId`) through the existing `getLLMModel` provider factory.
- Send only the first user message’s text followed by a dedicated title instruction as a second user message. Do not send the main system prompt, assistant response, later conversation, tools, attachments, or reasoning settings.
- Normalize generated output into a concise title of at most 50 characters.
- For missing user text/model/configuration, provider or generation errors, or unusable model output, return exactly `New Chat (${remoteId})`. There is no NLP or other semantic fallback.
- Remove the obsolete NLP/vocabulary implementation and remove `compromise` after confirming it has no other consumer.
- Add `src/core/ai-sdk/constants.ts` and move `PROVIDER_SNAPSHOT_KEY` out of `types.ts`; do not add the superseded provider-to-title-model map.
- Add a dedicated internal title-generation prompt under `src/chat-app/prompts/`.
- Preserve title persistence and assistant-ui’s title stream contract.
- Document the confirmed assistant-ui lifecycle: automatic title generation is once per newly initialized thread after its first `runEnd`; there is no automatic retry, while an explicit API call can generate again.

## 3. Existing System

### Title generation and persistence

- `src/chat-app/runtime/ThreadBoundLocalAISDKRuntimeProvider.tsx` supplies a memoized `LocalThreadListAdapter` to `useRemoteThreadListRuntime`.
- `src/chat-app/runtime/LocalThreadListAdapter.ts#generateTitle` currently calls the synchronous `src/core/title-generator/generateTitle.ts`, atomically writes the result through `ThreadStore.updateThread`, then emits the same complete value as one `createAssistantStream` text append.
- The current generator reads only the first text part of `messages[0]`, then tries `extractVocabTitle`, `extractContentWordsTitle`, and finally `remoteId`.
- The old implementation is isolated to `src/core/title-generator/`: `extractVocabTitle.ts`, `extractContentWordsTitle.ts`, `getCustomVocab.ts`, and `titleUtils.ts`. Repository inspection found no other consumer of these helpers.
- `compromise` is imported only by `extractContentWordsTitle.ts`. It is a direct production dependency in `package.json`; pnpm lock data also includes its otherwise-unreferenced transitive packages `efrt`, `grad-school`, and `suffix-thumb`.

### AI SDK and model selection

- `src/core/ai-sdk/getLLMModel.ts#getLLMModel` is the canonical provider factory. It reads settings through `LogseqSettingAccessor`, validates provider/API configuration, and returns an AI SDK language model for OpenAI, Google, or OpenAI-compatible providers.
- `settings.selectedModelId` is persisted by the model selector and represents the current user-selected chat model. The title adapter does not receive runtime model context, so settings are the agreed source.
- The project uses AI SDK `7.0.31`; normal chat uses `streamText`, while title generation can use the installed non-streaming `generateText` API. No provider-native or frontend tools are needed.
- `PROVIDER_SNAPSHOT_KEY` currently lives in `src/core/ai-sdk/types.ts` and is consumed only by `getLLMModelList.ts`.
- Prompt assets are Markdown files in `src/chat-app/prompts/` and are inlined with `?inlineSkill`.

### assistant-ui call frequency

- Installed assistant-ui source in `RemoteThreadListHookInstanceManager.tsx` registers title generation only when a thread runtime initializes with status `new`.
- It installs a one-use `runEnd` listener, disposes the listener before calling `threadListItem.generateTitle()`, and therefore automatically generates once after the new thread’s first run ends.
- The listener is consumed even if generation fails; assistant-ui does not automatically retry.
- The public `generateTitle()` API remains callable explicitly and has no one-shot/idempotency guard, so explicit calls can regenerate and overwrite a title. This repository currently exposes no regenerate-title UI.

## 4. Solution

### 4.1 Centralize the provider snapshot constant

- Add `src/core/ai-sdk/constants.ts` exporting `PROVIDER_SNAPSHOT_KEY`, with the existing OpenAI-to-`openai` and Google-to-`google` mappings and a type that permits the intentionally unmapped OpenAI-compatible provider.
- Remove the constant from `src/core/ai-sdk/types.ts`, leaving provider enums and reasoning types there.
- Update `src/core/ai-sdk/getLLMModelList.ts` to import the constant from `constants.ts` and `ProviderEnum` from `types.ts`.
- Do not create a provider title-model mapping: the later requirement to use `selectedModelId` supersedes it, and an unused/fallback mapping could silently use a model different from the chat model.

### 4.2 Add the title-generation prompt

- Add `src/chat-app/prompts/GENERATE_THREAD_TITLE.md` as an internal prompt asset, not a skill and not part of default skill registration.
- Instruct the model to produce only a concise title for the preceding user message, without labels, quotes, Markdown, explanation, or trailing punctuation, capped at 50 characters.
- Import the prompt in `LocalThreadListAdapter.ts` with `?inlineSkill` and inject it into the core generator. This preserves dependency direction: the reusable core module does not import from `chat-app`.

### 4.3 Implement AI SDK generation

- Rewrite `src/core/title-generator/generateTitle.ts` as an asynchronous function accepting `remoteId`, readonly `ThreadMessage[]`, and the injected title instruction.
- Construct the sole fallback once as ``New Chat (${remoteId})``.
- Locate the first message with `role === "user"`. From that message only, collect text content parts in order, trim/discard empty parts, and join multiple text parts with newlines. Ignore leading assistant messages, non-text parts, attachments, all later user messages, and the assistant response. If the first user message has no usable text, return the fallback without inspecting later user messages.
- Read `selectedModelId` at invocation time through `LogseqSettingAccessor.getPluginSettings()`. Trim it and return the fallback if absent/blank; do not fall back to the first provider model.
- Resolve the model through `await getLLMModel(selectedModelId)`, retaining all current provider/API-key/API-URL validation in one place.
- Call `generateText` with only:

```ts
{
  model,
  messages: [
    {role: "user", content: originalUserText},
    {role: "user", content: titleInstruction}
  ]
}
```

- Do not pass `system`/`instructions`, the normal chat system prompt, full history, assistant output, tools, reasoning effort, temperature, or chat call settings. This ordering gives the title request the same initial user-message prefix as the chat request where provider caching supports it.
- Catch model resolution and generation errors, log a warning through the centralized `LoggerCategory.CHAT_UI` logger without user text, credentials, or raw model output, and return the fallback. Missing text/model/prompt are expected fallback paths and should not create noisy warnings.

### 4.4 Normalize model output

- Add `src/core/title-generator/normalizeGeneratedTitle.ts` to replace only the still-needed deterministic presentation constraints from `titleUtils.ts`.
- Normalize by trimming, collapsing multiline/duplicate whitespace, removing common fenced/Markdown wrappers, paired quotes/backticks/emphasis, common `Title:`/`Chat title:`/`Thread title:` prefixes, and trailing punctuation.
- Enforce a maximum of 50 Unicode code points, preferring a word boundary and avoiding surrogate-pair splitting; clean trailing punctuation again after truncation.
- Treat empty, wrapper-only, or punctuation-only output as unusable and return `undefined`; `generateTitle` then returns the exact fallback.
- Keep normalization deterministic and non-semantic: it must not reintroduce vocabulary or NLP title extraction.

### 4.5 Preserve adapter semantics

- Update `src/chat-app/runtime/LocalThreadListAdapter.ts#generateTitle` to await the asynchronous core generator and pass the inlined prompt.
- Keep inference before `ThreadStore.updateThread` so a network call never holds the per-thread storage lock.
- Preserve the current atomic update, missing-thread `skip`, and all unrelated thread fields.
- Persist and emit the same final title, including fallback titles, as one assistant-stream text append.
- Continue allowing storage failures to reject; do not misclassify persistence failures as model failures or return a stream claiming an unpersisted title.
- Add no adapter-level once-only guard; rely on assistant-ui’s automatic lifecycle while retaining explicit regeneration behavior.

### 4.6 Remove NLP code and dependency

- Delete:
  - `src/core/title-generator/extractContentWordsTitle.ts`
  - `src/core/title-generator/extractVocabTitle.ts`
  - `src/core/title-generator/getCustomVocab.ts`
  - `src/core/title-generator/titleUtils.ts`
- Remove `compromise` using pnpm so `package.json` and `pnpm-lock.yaml` are updated consistently. Confirm pnpm also removes only now-orphaned NLP transitive entries.
- Perform a final repository search for deleted symbols and `compromise`; do not modify the independent Docusaurus lockfile.

### 4.7 Tests and documentation

- Rewrite `tests/src/core/title-generator/generateTitle.test.ts` with mocked `generateText`, `getLLMModel`, settings accessor, and logger. Cover:
  - exact fallback for absent/blank first-user text, absent/blank selected model, provider/model errors, generation errors, and unusable output;
  - first-user-message selection, combining only its text parts, ignoring non-text/later messages, and not falling through to a later user message;
  - use of the trimmed persisted `selectedModelId`, including rereading changed settings on a later explicit call;
  - the exact two-user-message AI SDK request and absence of system prompt, tools, reasoning, assistant response, or extra history;
  - normalization of labels, quotes, Markdown/fences, multiline output, punctuation, empty output, Unicode, and the 50-character cap;
  - safe logging that excludes user/model raw content.
- Extend `tests/src/chat-app/runtime/LocalThreadListAdapter.test.ts`, mocking the core generator, to verify prompt injection, awaiting the result, preserving thread data, persisting and streaming identical generated/fallback titles, missing-thread skip behavior, persistence rejection, and repeated explicit calls.
- Add `docusaurus/docs/chat/ai-generated-thread-titles.md` describing model selection, sent data, normalization/fallback, and the automatic-once versus explicit-repeat lifecycle.
