### B. Make the repository-owned test proxy reject API failures

Modify `tests/helpers/logseq-proxy-wrapper/createLogseqProxy.ts`; add `tests/helpers/logseq-proxy-wrapper/callLogseqApi.ts` and `tests/helpers/logseq-proxy-wrapper/createLogseqProxy.test.ts`.

Keep existing package initialization, settings/subscriptions, setup overrides, and throttling. Immediately after package initialization, replace its seven namespace proxies with repository-owned forwarding proxies using `callLogseqApi`. This confines the change to tests, avoids patching node_modules or globally intercepting unrelated fetch traffic, and preserves the current root initialization contract. Do not change dependencies in this fix.

Transport logic:

```ts
const response = await fetch(`${apiServer}/api`, {
    method: "POST",
    headers: {"Content-Type": "application/json", Authorization: `Bearer ${apiToken}`},
    body: JSON.stringify({method, args}),
});
const data = /* parse JSON for JSON content types, otherwise text */;
if (!response.ok || isApiErrorEnvelope(data)) {
    throw new Error(/* method + HTTP status + bounded server error */);
}
return data;
```

- Detect an own top-level non-null error field, not falsiness of the entire successful result. Preserve successful null, false, zero, arrays, objects, and text.
- Malformed JSON must reject with method/status context; non-JSON HTTP failures must reject with a bounded useful message. Let network rejection propagate with useful context. No retries or silent fallback.
- Never include authorization headers, token, or full argument payload in error/log output. Use the central logger if additional logging is actually needed; do not retain the dependency's per-call console noise.
- Generate `logseq.<namespace>.<method>` with the original argument array. Avoid synthesizing symbol properties and a callable `then` so proxies are not accidentally treated as thenables. No broad mockability abstraction is necessary; modal tests still own their fixture.
- Unit tests mock fetch and restore the original Logseq global after each test. Cover request method/arguments, auth header without snapshotting real credentials, 500 JSON error, 200 error envelope, non-JSON failure, malformed JSON, network rejection, successful falsy values, settings behavior, and a successful call after an earlier rejected call. Keep transport errors separate from the throttle queue's deliberate recovery of its internal tail.

This makes host failures truthful; it is **not sufficient on its own** to make the tag tests pass.
