## 3. Existing System

Paths below are relative to the repository root. Let `P = src/core/just-bash-wrapper/pyodide` and `T = tests/src/core/just-bash-wrapper/pyodide`.

### Data flow and ownership

```text
createPythonCommands
  -> captureSandboxSnapshot(just-bash IFileSystem)
  -> Comlink worker receives SandboxSnapshot
  -> materializeSnapshot(PyodideFS)
  -> Python execution
  -> collectSandboxChanges(PyodideFS)
  -> applySandboxChanges(just-bash IFileSystem)
```

- `P/createPythonCommands.ts` orchestrates capture, execution, write-back, and failure reporting.
- `P/fs-bridge/captureSandboxSnapshot.ts` traverses the host subtree in sorted order using `lstat`; rejects symlinks and unsupported entries; captures bytes and masked modes. It checks file and aggregate budgets before and after reads.
- `P/fs-bridge/sandboxFsLimits.ts` combines the 16 MiB per-file and 128 MiB total constants, `SandboxSnapshotError`, two assertions, and private `formatBytes`.
- `P/fs-bridge/applySandboxChanges.ts` defines `WriteBackFailure` and `SandboxWriteBackAbortedError`. It rejects unsupported/noncanonical/out-of-root changes, checks snapshot conflicts twice, and checks cancellation before commit. Once commit starts, operation failures are accumulated without cancellation interrupting it.
- `P/worker/materializeSnapshot.ts` replaces contents below the snapshot root, creates directories/files, resets file timestamps, then applies modes (directories deepest-first).
- `P/worker/collectSandboxChanges.ts` compares file bytes, detects additions/deletions, reports unsupported entries without following symlinks, and budgets only newly written/changed file contents. It currently imports pure limits from `fs-bridge`.
- `P/worker/executePythonInWorker.ts` marks the snapshot materialized only after loading succeeds, runs Python, and collects changes even after ordinary execution failures. A loading failure prevents collection; a collection failure drops changes and produces exit code 1. Fetch/callback cleanup remains intact.
- `P/workerProtocol.ts` contains value-only snapshot/diff payloads. These cross Comlink using structured cloning; the refactor must not introduce buffer transfer/detachment.

### Conventions and constraints

- Existing modules use direct file imports, named exports, and type-only imports. No bridge barrel currently exists.
- The worker entry is bundled separately through `pyodideWorker?worker` in `P/pyodideRuntime.ts`. Shared budget helpers must remain pure, with no host runtime imports or barrel dependencies.
- TypeScript includes source and tests with bundler resolution. No aliases/configuration changes are needed.
- `T/worker/sandboxSnapshot.test.ts` uses real local Pyodide in the Node environment. `T/worker/executePythonInWorker.test.ts` mocks the snapshot loader and collector.
- Host capture/write-back tests currently live under `T/fs-bridge/`. Broader command and runtime tests are at `tests/src/core/just-bash-wrapper/createPythonCommands.test.ts` and `pyodideRuntime.test.ts`.
- `docusaurus/docs/chat/bash-sandbox.md` documents user-visible behavior, not these filenames. This behavior-preserving refactor needs no user documentation change.
- An older `.opencode/plans/1791087477221-nimble-harbor.md` contains historical names. Leave historical plans unchanged.

## 4. Solution

### A. Rename the bridge and mirrored tests

Move `P/fs-bridge/` to `P/just-bash-fs-bridge/` and `T/fs-bridge/` to `T/just-bash-fs-bridge/`. Preserve the capture/write-back filenames and exported function signatures. Update all active source imports, test imports, and mocks affected by this change.

### B. Extract constants and utilities

The target bridge layout is:

```text
just-bash-fs-bridge/
  constants.ts
  captureSandboxSnapshot.ts
  applySandboxChanges.ts
  utils/
    assertFileWithinSnapshotBudget.ts
    assertTotalWithinSnapshotBudget.ts
    formatBytes.ts
    SandboxSnapshotError.ts
    SandboxWriteBackAbortedError.ts
    WriteBackFailure.ts
```

Move existing definitions without changing their logic:

- `constants.ts`: named exports `MAX_SANDBOX_SNAPSHOT_FILE_BYTES = 16 * 1024 * 1024` and `MAX_SANDBOX_SNAPSHOT_TOTAL_BYTES = 128 * 1024 * 1024`; no runtime dependencies.
- `utils/formatBytes.ts`: named export `formatBytes(byteLength: number): string`, returning `${byteLength / (1024 * 1024)} MiB` exactly as today.
- `utils/SandboxSnapshotError.ts`: preserve constructor, superclass, and `name`.
- Each assertion module imports its corresponding constant from `../constants`, `formatBytes`, and `SandboxSnapshotError`. Keep the strict `>` comparison: exactly-at-limit values pass. Preserve JSON path quoting and exact messages.
- `utils/SandboxWriteBackAbortedError.ts`: preserve the no-argument constructor, `name`, and `execution aborted before filesystem write-back` message.
- `utils/WriteBackFailure.ts`: export the existing interface `{path: string; message: string}`. Consumers use `import type`.

Delete `sandboxFsLimits.ts` after updating imports. Do not add re-exports in the old implementation files, a compatibility shim, or a barrel. Keep the other private write-back and diff helpers in their existing modules.

### C. Update dependencies without changing execution

- `P/just-bash-fs-bridge/captureSandboxSnapshot.ts`: import the two assertions and `SandboxSnapshotError` directly from their utility files.
- `P/just-bash-fs-bridge/applySandboxChanges.ts`: remove inline exported error/interface definitions; import their new definitions. Preserve all validation and commit logic.
- `P/createPythonCommands.ts`: import capture/apply from renamed paths; import the write-back error directly from its utility module and `WriteBackFailure` as a type. Using the same error class preserves `instanceof` cancellation handling.
- `P/worker/collectSandboxChanges.ts`: import assertions directly from `../just-bash-fs-bridge/utils/...`. Those modules transitively depend only on constants, string formatting, and an `Error` subclass. No host adapter or `just-bash` runtime dependency enters the worker through them.
- Capture tests and worker snapshot tests import constants from the new bridge `constants.ts`, and assertions from their individual modules.

### D. Keep worker ownership and rename the loader

Keep the Pyodide operations in `worker/` because their input is `PyodideFS`, not just-bash `IFileSystem`. Directory location itself does not determine execution context, but this boundary clearly separates the private Pyodide filesystem from authoritative host capture/write-back.

- Move `P/worker/materializeSnapshot.ts` to `P/worker/loadSandboxSnapshot.ts` and rename its named export to `loadSandboxSnapshot`.
- Retain its existing comment describing replacement with an exact host snapshot. Loading is destructive replacement of that subtree, not merging or host write-back.
- Update `P/worker/executePythonInWorker.ts` import and call; rename `materialized` to `snapshotLoaded`.
- Preserve this control flow:

```ts
let snapshotLoaded = false;
// Inside the existing execution try block:
loadSandboxSnapshot(pyodide.FS, execution.snapshot);
snapshotLoaded = true;
// Existing package loading and Python execution follow.
// After execution's existing catch:
if (snapshotLoaded) {
    // Existing collectSandboxChanges and error handling remain unchanged.
}
```

- Update the module path/export in the mock in `T/worker/executePythonInWorker.test.ts` and imports/calls in `T/worker/sandboxSnapshot.test.ts`.
- Do not rename `collectSandboxChanges`, change `PyodideFS`, or modify worker protocol shapes.

### E. Focused regression coverage

- Add `T/just-bash-fs-bridge/utils.test.ts` (Node environment, no Logseq dependency) covering both formatted limits, exactly-at-limit acceptance, one-byte-over-limit rejection with `SandboxSnapshotError`, exact messages including quoted file paths, and both error classes' names/messages. No runtime test is needed for the interface.
- Extend `T/worker/executePythonInWorker.test.ts` with direct imports of mocked `loadSandboxSnapshot`/`collectSandboxChanges`. Reset mock implementations and invocation history between cases so failure tests cannot leak state.
- Assert loading precedes `loadPackage` and Python execution; successful loading allows collection after an execution failure; loading failure skips collection and still cleans up; collection failure omits changes, preserves stdout, emits the existing error prefix, and exits with 1.
- Add a focused case to the real-Pyodide `T/worker/sandboxSnapshot.test.ts`: create a stale file and alter existing content, call `loadSandboxSnapshot` again, and assert the stale file disappears and original contents/modes are restored. Existing tests retain byte diff, symlink, output-budget, and permission coverage.
