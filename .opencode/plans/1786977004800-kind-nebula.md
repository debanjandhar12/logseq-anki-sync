# Running Thread Title Shimmer Plan

## 1. User Requirement

In ThreadList.tsx, could we style ThreadListItemPrimitive.Title using tw-shimmer for threads that are currently running?

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Question:** When should a thread title shimmer: only while assistant-ui reports an active assistant stream, or for the entire adapter/tool roundtrip?
- **Answer:** Assistant stream. Use assistant-ui's reactive `ThreadState.isRunning`; stop shimmering when the stream ends or requires user action.

### 2.2 Final Summarized Requirements

- Show a `tw-shimmer` text effect on every thread-list title whose own assistant-ui runtime reports `isRunning === true`, including a running background thread after the user switches away.
- Keep idle, metadata-only, and user-action-waiting threads visually unchanged.
- Preserve title fallback, truncation, interaction, accessibility, reduced-motion behavior, and existing rename/delete behavior.
- Keep the change local to the customized chat component and focused tests; do not alter persisted thread metadata, the full adapter-run tracker, registry sources, or global CSS.

## 3. Existing System

- `src/chat-app/components/ThreadList.tsx` renders each row through `ThreadListPrimitive.Items`. Every row has a `threadListItem` scope and currently places `ThreadListItemPrimitive.Title fallback="New Chat"` in one truncating span.
- The installed assistant-ui version exposes execution state as `ThreadState.isRunning`. `ThreadListItemState.status` instead represents list lifecycle (`new`, `regular`, or `archived`) and must not drive this feature.
- A row can obtain its scoped local ID from `useAuiState((state) => state.threadListItem.id)`. The installed API's `assistantRuntime.threads.getById(id)` returns the corresponding `ThreadRuntime`, whose `getState()` and `subscribe()` support a reactive `isRunning` snapshot.
- Persisted threads that have not been opened in the current session can exist in the list without an instantiated thread runtime. Calling `getState()` or subscribing through `getById(id)` can therefore throw; this is a normal lifecycle state and should be treated as idle.
- `ThreadListItemPrimitive.Title` accepts only `fallback`; it cannot receive `className` or `asChild`. The effect must be applied by wrapping/duplicating the primitive rather than passing styling into it.
- `tw-shimmer` is already installed and imported by `src/ui/styles/main.css`, which is injected into the chat sidebar's Shadow DOM. No stylesheet or dependency change is needed.
- `src/chat-app/components/ToolFallback.tsx` establishes the accessibility pattern: retain normal readable content and conditionally overlay an absolutely positioned, `aria-hidden` duplicate with `shimmer pointer-events-none absolute inset-0 motion-reduce:animate-none`.
- Project Vitest configuration discovers `*.test.ts` files, and component tests use React DOM `createRoot`/`act` with partial assistant-ui mocks.

## 4. Solution

### 4.1 Resolve each row's running state

Modify `src/chat-app/components/ThreadList.tsx` to add a private `useThreadListItemIsRunning` hook.

- Read the row's local thread ID from the existing `threadListItem` scope.
- Obtain the installed assistant runtime through the project's existing `useAssistantRuntime` convention and resolve `assistantRuntime.threads.getById(threadId)`. Although legacy/deprecated upstream, this is the compatible public export in the pinned version for accessing an arbitrary row's runtime; do not use the currently selected `state.thread` scope.
- Use React `useSyncExternalStore` to select only `threadRuntime.getState().isRunning`, so the row rerenders when its own stream starts or stops.
- Wrap runtime lookup/snapshot reads in a safe function that returns `false` when the backing runtime is absent or disappears. Missing runtimes are expected for unopened metadata and should not be logged.
- In the subscription function, first probe the resolved runtime and subscribe directly when available. If lookup, probing, or subscription fails, subscribe to the thread-list runtime and retry attaching the row-runtime subscription when list state changes. Notify the external-store callback during that transition so the snapshot is reread. Dispose both the temporary list subscription and row subscription safely on transition/unmount.
- Memoize callbacks/runtime resolution as needed so React does not tear down subscriptions on unrelated renders. Use the same safe boolean snapshot for client and server snapshots.

This data flow supports independent simultaneous running rows, follows a background thread after selection changes, allows an unopened row to become reactive once its runtime materializes, and fails closed to an ordinary title if a thread is deleted or detached.

### 4.2 Render an accessible shimmer title

In the same file, extract a private `ThreadListItemTitle` component and replace the inline title span in `ThreadListItem`.

- Keep an outer `data-slot="aui_thread-list-item-title"` wrapper with `relative min-w-0 flex-1 overflow-hidden`.
- Always render one normal title in a block-level truncating span using `ThreadListItemPrimitive.Title fallback="New Chat"`. This remains the only accessible title.
- When the row hook reports running, render a second identical primitive in an absolute, block-level truncating span with:
  - `aria-hidden`
  - `data-slot="aui_thread-list-item-title-shimmer"`
  - `shimmer pointer-events-none absolute inset-0 motion-reduce:animate-none`
- Preserve the same fallback on both copies so an untitled running thread shimmers `New Chat`; constrain both copies to the existing title width so long titles remain ellipsized and do not overlap the menu.
- Update the copied-component “Changes” comment above `ThreadListItem` to document the running-title customization, as required by `src/chat-app/AGENTS.md`.

No change is planned for `src/shadcn/assistant-ui/thread-list.tsx`, runtime persistence/tracking modules, `src/ui/styles/main.css`, dependencies, or documentation because this is a localized visual state treatment using an already documented dependency.

### 4.3 Add focused regression coverage

Create `tests/src/chat-app/components/ThreadList.test.ts` (using `createElement`, because the configured test glob is `*.test.ts`). Partially mock `@assistant-ui/react` with lightweight primitive wrappers, a scoped thread-list-item fixture, and controllable assistant/thread runtime subscriptions.

Cover:

1. A running row resolves its own scoped ID, keeps the visible title, and adds an `aria-hidden` overlay with the expected shimmer, pointer-event, positioning, truncation, and reduced-motion classes.
2. An idle row has no shimmer overlay and retains the visible title.
3. Runtime subscriber notifications toggle the shimmer reactively from idle to running and back.
4. A metadata-only row whose runtime snapshot/subscription initially throws renders safely as idle, listens for runtime materialization through the list fallback, then starts shimmering after the runtime appears and reports running.
5. An untitled running row renders `New Chat` identically in its accessible base and hidden overlay; long-title wrappers preserve overflow/truncation classes.
6. Unmounting disposes any active row and fallback subscriptions.
