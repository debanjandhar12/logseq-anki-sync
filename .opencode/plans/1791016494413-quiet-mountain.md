# Protect today's journal from DeletePageCommand

## 1. User Requirement

Currently in DeletePageCommand.ts, I need you to add a validation that current date's journal cannot be deleted...

## 2. Final Requirement After Discussion With User

### Clarification Q&A

- Question: Should “current date’s journal” mean today in the user's local timezone, with past and future journal pages remaining deletable?
- Answer: Local today only (Recommended).

### Final Summarized Requirements

- Reject deletion of the journal for the local calendar date at command execution time.
- Continue allowing ordinary pages and past/future journals, subject to existing validations.
- Reject before deletion or command-state/change-tracking mutations.
- Keep the existing command error propagation and revert/serialization behavior.

## 3. Existing System

- `src/core/logseq-reversible-transaction-tracker/commands/DeletePageCommand.ts`: `execute()` validates command status, rejects block UUIDs, resolves an active page with `requireActivePage`, rejects tag/property pages, records page name and changed UUID, calls `logseq.Editor.deletePage`, then marks the command executed. `revert()` restores the soft-deleted page.
- `commands/utils/getJournalDayByPageUuid.ts`: existing UUID-validated DataScript lookup for `:block/journal-day`; returns a `YYYYMMDD` integer or `null` for non-journals and throws on malformed query results. Reuse without modifying it.
- `RenamePageCommand.execute()` already uses this helper to reject journal renaming. Date metadata avoids dependence on title formatting, capitalization, or locale.
- `BaseReversibleCommand` exposes `getCommandState()` and `getChangedPages()`, enabling assertions that rejection has no bookkeeping side effects.
- The transaction tracker wraps command errors; the delete-page chat tool surfaces them. No changes to either layer are needed.
- `tests/src/core/logseq-reversible-transaction-tracker/commands/DeletePageCommand.test.ts` contains live DB-graph integration coverage for delete/revert and block/tag/property rejection. It skips if Logseq is unavailable. `tests/setup.ts` probes the API at `http://127.0.0.1:12315` by default.
- Existing unit tests use Vitest module mocks and `vi.stubGlobal`, with cleanup via `vi.unstubAllGlobals()`.

## 4. Solution

### Production change

Modify only `src/core/logseq-reversible-transaction-tracker/commands/DeletePageCommand.ts`:

1. Import `getJournalDayByPageUuid` from `./utils/getJournalDayByPageUuid`.
2. Immediately after `requireActivePage()` resolves, before tag/property guards and before changing `commandState` or `changedPages`, add:

```ts
const journalDay = await getJournalDayByPageUuid(page.uuid);
const now = new Date();
const currentJournalDay =
    now.getFullYear() * 10_000 + (now.getMonth() + 1) * 100 + now.getDate();
if (journalDay === currentJournalDay) {
    throw new Error("Cannot delete today's journal page using DeletePageCommand.");
}
```

- Use local date getters, not UTC getters or `toISOString()`.
- Read the clock after the journal query resolves, minimizing stale-date decisions around midnight. Compute the date once per execution, not at module load or construction.
- `null` metadata never matches today; ordinary pages keep their current behavior. Past and future dates do not match either.
- Let lookup errors propagate before deletion (fail closed), consistent with existing validation errors.
- Do not infer journal identity from names or add a new date utility for this single use.
- Preserve existing schemas, codec, revert implementation, tag/property/block validation messages, and success result.

### Regression coverage

Add `tests/src/core/logseq-reversible-transaction-tracker/commands/DeletePageCommand.unit.test.ts` as a non-skipped mocked suite, retaining the existing integration suite unchanged.

- Use a valid page UUID and an active page fixture. Mock `requireActivePage`, `getJournalDayByPageUuid`, and `LogseqEditor` checks. Stub global `logseq.Editor.getBlock` to return `null` and `deletePage` to resolve successfully.
- Freeze time with Vitest fake timers and `vi.setSystemTime(new Date(2026, 9, 3, 12))`; use local constructors so the expected date is independent of CI timezone.
- Restore real timers and stubbed globals, and reset mocks between tests.
- Cases:
  1. Metadata `20261003` rejects with the exact new error; `deletePage` is not called, state remains `{status: "new"}`, and changed pages remain empty.
  2. Metadata `20261002` and `20261004` each allow execution, invoke deletion with the page UUID, return `true`, and retain existing successful bookkeeping.
  3. Metadata `null` permits ordinary-page deletion even if its name resembles today's journal. Conversely, today's metadata rejects even with an unrelated title.
  4. Construct a command before local midnight, advance the mocked clock past midnight, and verify protection uses the new execution date, not the construction date.
  5. A rejected metadata lookup propagates its error without deletion or state mutation.

### Scope and compatibility

- No real journal creation/deletion is required for new tests, avoiding changes to users' journal content.
- The guard protects this command's deletion pathway; it does not change Logseq's native deletion behavior or unrelated API calls.
- No user-facing UI/schema changes or documentation changes are needed for this narrow validation fix.
