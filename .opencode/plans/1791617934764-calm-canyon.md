### 2.2 Final Summarized Requirements

Perform a behavior-preserving source organization refactor:

1. Split filesystem interfaces into `worker/PyodideFS.ts` and `worker/PyodideFsStat.ts`, retaining exported interface names.
2. Rename the worker entrypoint to `worker/pyodide.worker.ts`; rename locals to `workerApi` and `runtimePromise`.
3. Rename `pyodide/workerProtocol.ts` to `pyodide/types.ts`, containing only the existing shared execution/fetch/API contracts.
4. Rename `pyodide/pyodideRuntime.ts` to `pyodide/executePython.ts`; keep implementation types/helpers local, with private `PythonExecutionOptions` replacing `ExecutionOptions`.
5. Put Python and identity Bash command adapters in wrapper-level `commands/`, with explicit exports for direct use by `JustBashWrapper`.
6. Split network parsing from request assertions; rename the secure fetch file/factory; relocate the allowlist resource into `network/`.
7. Retain the cohesive `utils/fsContent.ts`, `fsErrors.ts`, and `fsPaths.ts` modules unchanged, including the colocated encoding type.
8. Update imports, mocks, tests, and the documentation resource path. No dependency upgrades, runtime changes, or compatibility aliases for old internal paths.

## 3. Existing System

All paths below are relative to the repository root. Source paths abbreviated within this document are relative to `src/core/just-bash-wrapper/` unless otherwise noted.

### 3.1 Commit findings

- `54fe79fa`: introduces shared filesystem snapshots, Pyodide change collection/write-back, virtual identity commands, effective read-only modes, and fatal UTF-8 decoding for storage-backed byte writes.
- `c97167c2`: organizes the host bridge as `just-bash-fs-bridge`, renames snapshot loading, and introduces focused error/budget coverage.
- `31c22857`: separates the reusable `sandbox-tree` model/budget/diff from the host bridge; snapshots become `Map<string, SandboxEntry>`; conflict detection and real storage-backed round-trip tests are added. This architecture is retained.

### 3.2 Execution and ownership

- `JustBashWrapper.createInstance()` builds the virtual read-only base plus mountable storage adapters, provides network transport, and registers `python`, `python3`, `py`, `whoami`, and `hostname`.
- `createPythonCommands()` adapts Bash arguments/stdin/environment to Python execution. It captures `/home/user`, executes Python, and applies changes through authoritative `context.fs`. Help/version/error handling can return without starting Python.
- `executePython()` creates one worker per execution, waits for readiness, proxies secure fetch through Comlink, handles startup/execution timeouts and cancellation, releases the client, and terminates the worker in `finally`.
- The worker entry lazily caches Pyodide initialization and exposes `PythonWorkerApi` through Comlink. Execution delegates to `executePythonInWorker()`.
- `sandbox-tree/types.ts` owns cloneable tree/diff types; `just-bash-fs-bridge/` owns host snapshot capture and conflict-checked write-back; `worker/` owns synchronous Emscripten filesystem operations.
- `PyodideFS` is deliberately a narrow synchronous capability interface, not just-bash's asynchronous mount-aware `IFileSystem`.

### 3.3 Network and storage

- `networkPolicy.ts` currently combines allowlist parsing, raw resource loading, and request assertions.
- `secureFetch.ts` implements manual redirects, allowlist enforcement, timeout/body limits, proxy final-URL validation, and integrity verification for an exact pinned SciPy wheel.
- `fsContent.ts` owns text re-encoding and strict UTF-8 conversion into plugin storage. `fsErrors.ts` owns eight consistently formatted filesystem errors. `fsPaths.ts` owns validated storage-mount/path/key mapping.

### 3.4 Build and testing constraints

- Vite handles the entry via `?worker`, uses `worker.format: "es"`, and loads the allowlist via `?raw`. Pyodide assets are managed independently by `vite-plugins/pyodideAssetsPlugin.ts`; no build configuration change is needed.
- Relevant dependencies: Pyodide 314.0.6, Comlink 4.4.2, p-timeout 7.0.2, and just-bash 3.2.x. No package or lockfile changes.
- Tests include fake worker/client orchestration tests, command mocks, actual Node Pyodide filesystem tests, and storage-backed round trips.
- Vitest configuration is in `vite.config.ts` (not a standalone Vitest config): jsdom by default, per-file Node overrides, and `tests/setup.ts`. Some suites require Logseq's API server at `http://127.0.0.1:12315`.
- Existing unrelated staged/deleted `.vitest` artifacts must remain untouched. Historical `.opencode/plans/` files are records, not current importers, and must not be rewritten.

## 4. Solution

### 4.1 Final layout

```text

  network/

  utils/
    fsContent.ts                  (unchanged)
```

### 4.2 Filesystem interface split

- Remove `worker/pyodideFs.ts` after creating the two replacement files.
- `PyodideFsStat.ts` contains the unchanged exported `{mode: number}` interface.
- `PyodideFS.ts` imports that interface with `import type {PyodideFsStat} from "./PyodideFsStat"`; retain every existing method signature and export name.
- Update type imports in `loadSandboxSnapshot.ts`, `readEmscriptenTree.ts`, and `collectSandboxChanges.ts`, plus worker tests `sandboxSnapshot.test.ts` and `collectSandboxChanges.test.ts`.
- Do not expose these implementation capabilities through `pyodide/types.ts` or merge them with `IFileSystem`.

### 4.3 Worker entry and shared contracts

- Move `worker/pyodideWorker.ts` to `worker/pyodide.worker.ts`; preserve the webworker library reference, `expose()`, readiness checks, cached initialization promise, and delegated execution.
- Rename local `runtime` to `runtimePromise`, and `api` to `workerApi`; change the final call to `expose(workerApi)`.
- Rename `workerProtocol.ts` to `types.ts` without changing any contract: `PythonWorkerExecution`, `PythonExecutionResult`, `PythonWorkerFetchResponse`, `PythonWorkerFetch`, and `PythonWorkerApi`.
- Keep its type-only imports of `SandboxChanges`/`SandboxSnapshot` from `./sandbox-tree/types`. Do not duplicate/re-export those model types or move private runtime options here.
- Update shared contract imports in host execution and worker helpers: `createWorkerFetch`, `createPythonIO`, `createPythonExecution`, `executePythonInWorker`, and the entrypoint. Update corresponding tests.
- Do not barrel-export the side-effectful worker entrypoint.

### 4.4 Host execution and Pyodide public boundary

- Move `pyodideRuntime.ts` to `executePython.ts`.
- Update the constructor import to `import PyodideWorker from "./worker/pyodide.worker?worker"`.
- Rename private `ExecutionOptions` to `PythonExecutionOptions` everywhere in the module.
- Keep `PythonWorkerClient`, `createExecution`, `createComlinkClient`, `createWorkerFetch`, `normalizeTimeout`, and `failure` local and otherwise unchanged.
- Change `pyodide/index.ts` to `export {executePython} from "./executePython"`; remove the command-factory export.
- Preserve the explicit wire-request projection in `createExecution()`: host fetch/signal/factory options must not cross the Comlink boundary.
- Preserve default runtime URL resolution, all exit codes/error text, binary fetch bodies, timeout normalization, event/listener cleanup, proxy release handling, and unconditional worker termination.

### 4.5 Bash command adapters

- Move root `virtualIdentityCommands.ts` to `commands/virtualIdentityCommands.ts` and `pyodide/createPythonCommands.ts` to `commands/createPythonCommands.ts`.
- Adjust identity constants import depth for the moved file. The Python factory retains the same depth for the constants import because its old/new directories have equal depth.
- Python factory imports execution through `import {executePython} from "../pyodide"` and imports bridge/tree modules through `../pyodide/just-bash-fs-bridge/...` and `../pyodide/sandbox-tree/types`.
- Add `commands/index.ts` with explicit exports of `createPythonCommands` and `virtualIdentityCommands`.
- `JustBashWrapper.ts` imports both from `./commands` and secure fetch from `./network`.
- Preserve command aliases, argument parsing, stdin decoding, shebang behavior, help/version, snapshot/write-back sequencing, output formatting, and all error/exit-code behavior.

Dependency direction:

```text
JustBashWrapper -> commands -> pyodide/index -> executePython -> worker entry
                         -> filesystem bridge / sandbox tree
JustBashWrapper -> network/index -> createSecureFetch -> assertion -> parser
```

No Pyodide module imports command registration; no barrel creates a reverse dependency.

### 4.6 Network responsibilities

- Extract `parseNetworkAllowlist()` unchanged into `network/utils/parseNetworkAllowlist.ts`: pure parsing, trimming/lowercasing, comments/blank lines, existing character validation/error, and `Set` semantics. No raw asset import.
- Move the remaining policy to `network/assertNetworkRequestAllowed.ts`. Preserve private `ALLOWED_METHODS`, exported `NETWORK_ALLOWLIST_HOSTS`, assertion defaults/signature, URL normalization, allowlisted apex/subdomain matching, and error messages.
- Move `network-allowlist.txt` into `network/` byte-for-byte and load it with `./network-allowlist.txt?raw` from the assertion module.
- Move `network/secureFetch.ts` to `network/createSecureFetch.ts`; rename `createAllowlistedFetch` to `createSecureFetch` and change its assertion import.
- Keep body reading, artifact integrity, limits, redirect handling, and result conversion helpers local and unchanged.
- Update `network/index.ts` to export the parser, assertion, and renamed factory explicitly. Keep `NETWORK_ALLOWLIST_HOSTS` out of the barrel, as currently.
- Preserve HTTPS/method/credentials/port restrictions, ten-redirect cap, redirect method conversion, hidden-redirect rejection, credentials omission, caller signal handling, thirty-second timeout cap, ten-MiB general response cap, exact fifteen-MiB SciPy exception/hash, proxy final-URL validation/header stripping, and returned URL/binary-body semantics.
- This is not a hardening pass: do not alter parser acceptance rules, abort behavior, transport semantics, or existing edge-case handling while moving code.
