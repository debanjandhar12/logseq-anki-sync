# Logseq page-type review icons

## 1. User Requirement

We need to modify LogseqPageDataPrinter to return the page type as well. (logseq-tag-page / logseq-property-page / logseq-page). Refer to ReadBlockCommand for how to detect (check tag first, then property and then if page). For non-existing pages, we will return null in this field.

Finally, we need to use that to show file icons in AIChangesReviewModalComponent. For this, first abstract away the icon selection of LogseqAttachmentThumb to a new method in src/chat-app/utils. Then reuse that in AIChangesReviewModalComponent. We might need to use ?? or || operator for before and after. Assume a tag page cannot become simple page or so on.

## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Question:** Where should the page-type icon appear in each AI changes diff?
- **Answer:** Replace the file badge. Extend the customized `DiffViewer` so the selected Lucide page icon occupies the existing optional file-badge position in its collapsible header.

### 2.2 Final Summarized Requirements

- Add nullable page-kind metadata to every printed page snapshot and to both sides of every reviewable page change.
- The only non-null page kinds are `logseq-tag-page`, `logseq-property-page`, and `logseq-page`.
- Classify an existing page in the same precedence used by `ReadBlockCommand`: tag first, property page second, ordinary page last. Missing and soft-deleted pages receive `null`.
- Preserve the page kind through alias/rename grouping and creation/deletion change construction.
- Extract all existing `LogseqAttachmentThumb` icon mappings into a pure utility under `src/chat-app/utils`, while preserving its current upstream thumbnail fallback.
- In the AI changes review, select the existing side's kind with `before.pageType ?? after.pageType`, map it to the shared icon, and render that icon in place of `DiffViewerFileBadge`.
- Keep `DiffViewer` backward compatible: callers without a custom icon retain the extension badge, and `showIcon={false}` still suppresses both forms of icon.

## 3. Existing System

### Page snapshot and change flow

- `src/core/logseq-reversible-transaction-tracker/LogseqPageDataPrinter.ts`
  - `print()` resolves each changed page identity, returns ordered `LogseqPrintedPageSnapshot` objects, and caches printed name/content by resolved UUID.
  - Unresolved pages use `resolvedPageUuid: null`; soft-deleted pages retain their UUID for before/after grouping. Both currently use `[DOES NOT EXIST]` and empty content.
  - `createChanges()` groups aliases and renames by UUID, selects the first existing snapshot on each side, filters no-ops, and currently reduces each side to `{pageName, content}`.
- `src/chat-app/tools/impl/LogseqCommitChangesTool.tsx` captures the applied state as `after`, reverts commands, captures `before`, and calls `createChanges()` before opening the modal.
- `src/core/logseq-reversible-transaction-tracker/index.ts` re-exports the printer's public contracts.

### Established page classification

- `src/core/logseq-reversible-transaction-tracker/commands/ReadBlockCommand.ts` checks a UUID as a tag with `LogseqEditor.isTagBlock()`, then fetches the raw entity with `logseq.Editor.getBlock()` and checks `LogseqEditor.isPropertyBlock()`, and only then handles it as an ordinary page.
- `src/logseq/LogseqEditor.ts` centralizes the tag and property predicates. Tag lookup failures are treated as “not a tag”; property classification recognizes `type === "property"` or an `ident`.
- Classification should be cached with the printable page data so duplicate identities resolving to one UUID neither repeat detection nor risk mismatched metadata.

### Current icon and diff behavior

- `src/chat-app/components/AttachmentUI.tsx` contains a local `LogseqAttachmentThumb` switch mapping image, block, ordinary page, property page, tag page, and PDF attachment types to Lucide icons. Unsupported types fall back to the upstream `AttachmentThumb`.
- Attachment type string constants live in `src/chat-app/runtime/LogseqAttachmentAdapter/constants.ts`.
- `src/chat-app/components/DiffViewer.tsx` is the project-owned customization of the upstream Shadcn viewer. Its collapsible header currently renders `DiffViewerFileBadge` when `showIcon` is true.
- `src/ui/pages/AIChangesReviewModal.tsx` maps each change to a `DiffViewer`, but currently passes `showIcon={false}` because Logseq page names are not file extensions.
- There are unit tests for the printer and commit preparation, but no current tests for attachment icon selection, the review-modal mapping, or the customized diff header icon behavior.

### Constraints

- Do not make transaction-tracker core import chat-runtime constants; that would invert the dependency direction. The page-kind union should be owned/exported by the printer's core contract, while the visual helper may use the existing attachment constants.
- Do not modify `src/shadcn/assistant-ui/diff-viewer.tsx`; custom behavior belongs in `src/chat-app/components/DiffViewer.tsx`.
- A valid reviewable change has at least one existing side. Creation/deletion therefore obtains its icon from the non-null side, and an edit/rename uses the before kind. Per the requirement, two existing sides cannot legitimately have different page kinds.

## 4. Solution

### 4.1 Extend printer contracts and classify existing pages

Modify `src/core/logseq-reversible-transaction-tracker/LogseqPageDataPrinter.ts`:

1. Export a narrow domain type:

   ```ts
   export type LogseqPageType =
       | "logseq-tag-page"
       | "logseq-property-page"
       | "logseq-page";
   ```

2. Add `pageType: LogseqPageType | null` to both `LogseqPrintedPageSnapshot` and `LogseqPrintedPageChangeSide`.
3. Import `LogseqEditor` and add a focused private classifier that receives the already-resolved active page UUID and follows this exact sequence:
   - If `await LogseqEditor.isTagBlock(uuid)`, return `logseq-tag-page` immediately and do not perform the property lookup.
   - Otherwise fetch the raw page-shaped block using `logseq.Editor.getBlock(uuid)`.
   - If that entity exists and `await LogseqEditor.isPropertyBlock(entity)` is true, return `logseq-property-page`.
   - Otherwise return `logseq-page`; reaching this branch is valid because `print()` has already resolved an existing active `PageEntity`.
4. On a UUID cache miss, classify once and cache `{pageName, content, pageType}` together. Duplicate identities then reuse all three values.
5. Make `createMissingSnapshot()` return `pageType: null` for both unresolved and soft-deleted pages without calling any classifier.

Export `LogseqPageType` from `src/core/logseq-reversible-transaction-tracker/index.ts` with the existing printer contracts.

### 4.2 Preserve page kind when creating review changes

In `LogseqPageDataPrinter.createChanges()` and `selectExistingSide()`:

- Copy `pageName`, `content`, and `pageType` from the same first existing snapshot in each alias group. Do not select these fields independently.
- When a side has no existing snapshot, return `{pageName: NON_EXISTENT_PAGE_NAME, content: "", pageType: null}`.
- Include `pageType` in no-op equality alongside name and content. A kind-only difference is not expected, but should not be silently discarded if malformed or transitional data reaches this layer.
- Preserve current UUID grouping, rename collapsing, order, and creation/deletion semantics unchanged.

Update affected typed fixtures in `tests/src/chat-app/tools/impl/LogseqCommitChangesTool.test.ts` so the test continues to prove that `prepareReview()` keeps before/after ordering and now also carries `pageType` through to the modal payload.

### 4.3 Extract the shared attachment icon selector

Add `src/chat-app/utils/getLogseqAttachmentIcon.ts` with a pure exported function:

```ts
getLogseqAttachmentIcon(type: string | null | undefined): LucideIcon | null
```

Move every explicit mapping currently in `LogseqAttachmentThumb` into this function:

- `image` -> `ImageIcon`
- `logseq-block` -> `TextSelectIcon`
- `logseq-page` -> `FileIcon`
- `logseq-property-page` -> `CircleParkingIcon`
- `logseq-tag-page` -> `HashIcon`
- `logseq-pdf` -> `FileTextIcon`
- unsupported, null, or undefined -> `null`

The utility returns a component type rather than JSX so each caller controls styling and fallback behavior.

Refactor `src/chat-app/components/AttachmentUI.tsx` so `LogseqAttachmentThumb`:

- Reads the attachment type as before.
- Calls `getLogseqAttachmentIcon(type)`.
- Renders the returned icon with the existing `size-4 text-muted-foreground` classes.
- Continues rendering `<AttachmentThumb />` when the helper returns `null`, preserving document/file/unknown behavior.

### 4.4 Add custom file-icon support to the project DiffViewer

Modify only `src/chat-app/components/DiffViewer.tsx`:

- Define a local extension of upstream `DiffViewerProps` with `fileIcon?: LucideIcon | null` in addition to the existing `contentClassName` customization.
- Forward `fileIcon` through `DiffViewer`, `DiffViewerFile`, and `DiffViewerCollapsibleHeader`.
- In the existing `showIcon` slot:
  - Render neither custom icon nor badge when `showIcon` is false.
  - Render the supplied Lucide component, with stable `size-4 shrink-0 text-muted-foreground` styling and a testable data slot, when `showIcon` is true and `fileIcon` is present.
  - Fall back to the current `DiffViewerFileBadge` when `showIcon` is true but no custom component was supplied, preserving compatibility for any future generic caller.
- Update the component's “Changes” comment to document the new custom header-icon support.

### 4.5 Render page-kind icons in the AI review modal

Modify `src/ui/pages/AIChangesReviewModal.tsx` inside `createAIChangesReviewDiffViewers()`:

- For each change, compute the stable kind as `change.before.pageType ?? change.after.pageType`. This uses the after kind for creations and the before kind for deletions/edits, without attempting to infer kind from the sentinel name.
- Resolve the icon component with `getLogseqAttachmentIcon(pageType)`.
- Pass the result through the new `fileIcon` prop and enable `showIcon` so the custom page icon replaces the extension badge.
- Keep all current names, contents, split mode, stats, sizing, and scrolling behavior unchanged.
- Tolerate an unexpected all-null change without throwing; the icon helper returns `null` and `DiffViewer` follows its documented fallback behavior.
