### 2.2 Final Summarized Requirements

- Implement a fourth provider type named **Codex Subscription** with persisted value `codex-subscription`.
- Use only `openai-oauth-ai-provider` for OAuth and AI SDK integration; do not keep the experimental `@openai-oauth/core`, `/web`, `/react`, or `/ai-sdk` approaches.

  2. open the verification URL,
  3. transition the UI to a prominent device-code/waiting state,
  4. immediately poll for completion,
  5. store credentials on success without a separate Complete button.
- Store a validated, versioned JSON envelope containing the complete token set required by `openai-oauth-ai-provider` as UTF-8 Base64 inside `ProviderConfig.apiKey`.

- Keep the existing Node 22 project requirement if possible, but align AI SDK versions with `openai-oauth-ai-provider@0.2.1` and gate release on a clean Node 22 install/build/test.
- Add a narrowly scoped browser-compatibility Vite plugin. Put all package compatibility shims inside `vite-plugins/openAIOAuthBrowserPlugin/`.

  - `ProviderConfig` contains `id`, `type`, `baseUrl`, `apiKey`, and `models`.
- `src/core/ai-sdk/provider-config/providerConfigSchema.ts`

### 3.4 OAuth package constraints

`openai-oauth-ai-provider@0.2.1` provides:

- `OpenAIOAuth.loginWithDeviceCode({onVerification, signal})`
- `OpenAIOAuthTokens` with required `accessToken`, `idToken`, `refreshToken`, and `updatedAt`, plus optional account/plan/FedRAMP metadata
- `createOpenAIOAuthProvider()` returning an AI SDK 7 `ProviderV4`
- `codex().listCodexModels()` for authenticated model discovery
- automatic token refresh and retry after authorization failures

Constraints discovered during the experiment and package inspection:

- Its default `FileTokenStore` statically imports Node filesystem modules, even when the application supplies another store. A targeted build-time replacement is required.
- Its published JWT parser uses Node `Buffer` and strictly fails claim extraction for the token shape returned during the successful browser experiment. The experiment only completed after using browser-safe, tolerant claim parsing. This is a package compatibility issue separate from token storage.
- The package declares Node >=24, exact peers `@ai-sdk/openai@4.0.28` and `@ai-sdk/provider@4.0.5`, and was developed with `ai@7.0.50`. The project currently targets Node 22 with older AI SDK packages.
- The package uses private ChatGPT Codex endpoints, which may change independently of the public OpenAI API.

### 3.5 Transport constraints

- `src/logseq/LogseqHttpProxy.ts` globally proxies browser HTTP requests through Logseq to bypass Electron CORS.
- It buffers responses and does not provide true incremental SSE streaming.
- It does not propagate aborts to the underlying host request.
- Device authorization and JSON polling work through this proxy in the experiment.
- The OAuth code exchange uses `application/x-www-form-urlencoded`; this body must be verified through the proxy and updated to preserve form text if necessary.
- Codex chat may work as buffered SSE, but token-by-token UI updates and immediate network cancellation cannot be promised without a separate transport project. This plan documents rather than broadens scope to redesign the proxy.

### 4.3 Define a versioned credential envelope

Add directory and files:

- `src/core/ai-sdk/codex/CodexCredentialCodec.ts`
- `src/core/ai-sdk/codex/types.ts` if shared types would otherwise create cycles

Persist this logical structure as UTF-8 JSON and then standard Base64 inside `ProviderConfig.apiKey`:

```ts
interface CodexCredentialEnvelopeV1 {
    version: 1;
    provider: "openai-oauth-ai-provider";
    tokens: {
        accessToken: string;
        idToken: string;
        refreshToken: string;
        updatedAt: number;
        accountId?: string;
        planType?: string;
        isFedRamp?: boolean;
    };
}
```

Expose:

```ts
encodeCodexCredentials(tokens): string
decodeCodexCredentials(encoded): OpenAIOAuthTokens
isValidCodexCredentials(encoded): boolean
```

Codec rules:

- Empty string represents signed out and is handled before decoding.
- Enforce an encoded/decoded size limit (1 MiB maximum).
- Decode with `atob`, bytes, and fatal UTF-8 `TextDecoder`; do not use Node Buffer.
- Require version/provider discriminator and all mandatory token fields.
- Require non-empty strings and a finite millisecond `updatedAt`; validate optional fields by type.
- Use strict schemas for the known v1 fields. Reject unknown envelope versions with a generic unsupported-version error.
- Never include input or decoded values in errors/logs.
- Do not store `expiresAt`; the package derives expiry from access-token claims and uses `updatedAt` as fallback.

### 4.4 Centralize Codex session creation and token persistence

Add:

- `src/core/ai-sdk/codex/CodexSessionManager.ts`
- `src/core/ai-sdk/codex/CodexProviderTokenStore.ts`
- `src/core/ai-sdk/codex/InMemoryCodexTokenStore.ts`
- `src/core/ai-sdk/provider-config/ProviderConfigRepository.ts`

#### ProviderConfigRepository

Make this the single serialized writer for `providerConfigSetting`, reusing the existing `async-lock` dependency and `LogseqSettingAccessor`.

Responsibilities:

- Read/decode current provider configs.
- Save the modal's complete draft while preserving existing selected-model reconciliation.
- Atomically update only one Codex provider's encoded credentials after a runtime refresh.
- Re-read settings inside the lock before every write to avoid losing unrelated configuration edits.
- Use the previous encoded credential value as an optimistic concurrency token. If provider ID, type, or credential value changed during refresh, reject the stale refresh instead of overwriting Logout, a new sign-in, rename, or deletion.
- Emit a non-secret `{providerId, encodedCredentials}` internal update event after a successful runtime rotation so an open modal can reconcile its draft.

The repository must preserve these races correctly:

- Runtime refresh before modal Save: an unchanged draft adopts the refreshed credentials.
- Modal Logout/replace before refresh persistence: stale refresh cannot restore old credentials.
- Provider rename/delete while refresh is pending: late old-ID refresh fails.
- Editing provider B while provider A refreshes: both changes survive.

#### Token stores

`CodexProviderTokenStore` implements the package `TokenStore` over a persisted provider:

- `load()` decodes the current Base64 envelope.
- `save(tokens)` encodes the entire replacement token set and asks `ProviderConfigRepository` to conditionally persist it.
- `withLock()` serializes refreshes for the same session.
- Do not use its `clear()` for modal Logout; Logout is a draft operation.

`InMemoryCodexTokenStore` is used for unsaved device login and unsaved replacement credentials:

- Holds the complete token set.
- Notifies the modal when `save()` receives login/refreshed tokens.
- Never writes settings.

#### Session manager

Expose factory methods for:

- Runtime session from persisted `ProviderConfig`.
- Draft session from the modal's encoded credential value.
- Device-code draft login.

Each session shares one `OpenAIOAuth` instance among:

- `createOpenAIOAuthProvider({auth, baseURL, fetch})`
- `codex({auth, baseURL, fetch})`

Pass the same explicitly captured/proxied fetch implementation to authentication and model/catalog clients. Cache runtime sessions by provider ID plus exact credential string; invalidate them on repository credential updates. This preserves the provider library's refresh deduplication and prevents use of superseded sessions.

#### Resolver design

The plugin must:

- use `enforce: "pre"`;
- normalize Windows separators and strip Vite query suffixes;
- resolve only exact relative imports from the pinned package's compiled `dist` directory;
- redirect `./store.js` when imported by the package's `auth.js`/`core.js` to `openAIOAuthStoreCompat.ts`;
- redirect `./jwt.js` when imported by the package's `auth.js`/`core.js` to `openAIOAuthJwtCompat.ts`;
- return `null` for all other modules;
- avoid broad `node:*`, `/store.js$/`, or whole-package aliases.

This exact matching deliberately causes a future changed package module graph to fail visibly rather than silently applying compatibility code to unrelated modules.

#### Store compatibility shim

`openAIOAuthStoreCompat.ts` mirrors the package runtime exports required by its internal graph:

- browser-safe `MemoryTokenStore`;
- matching `TokenStore` and `OpenAIOAuthTokens` types;
- `FileTokenStore` and `defaultTokenFilePath` stubs that throw immediately with a clear browser-runtime error.

It must contain no Node imports and no application persistence logic. Application persistence stays in `CodexProviderTokenStore`.

#### JWT compatibility shim

`openAIOAuthJwtCompat.ts` mirrors:

- `decodeJwtPayload`
- `parseOpenAIOAuthJwtClaims`
- `tryGetJwtExpiration`

Use browser Base64URL decoding (`atob` + UTF-8 `TextDecoder`) and preserve size/safe-integer checks. Keep `decodeJwtPayload()` strict, but make optional claim extraction tolerant: if OpenAI supplies the opaque/new token shape reproduced during experimentation, return no optional claims rather than failing an otherwise successful OAuth exchange. Preserve raw token storage regardless.

Add a maintenance comment documenting:

- the pinned upstream version;
- the reproduced `Could not decode JWT payload` failure;
- why tolerant parsing is separate from browser store compatibility;
- that the shim should be removed when upstream offers equivalent browser-safe behavior.

Explicitly enable the Buffer polyfill in `nodePolyfills.globals` as defense for remaining dependency code, but do not rely on `window.Buffer` initialized after module evaluation.

#### State machine

Use a discriminated state machine:

```text
signed-out
  -> starting
  -> awaiting-verification (code visible; polling already active)
  -> signed-in

starting/awaiting-verification
  -> cancelled -> state derived from current draft apiKey
  -> error -> retryable error state

signed-in
  -> logout -> signed-out draft
```

#### One-action device login

On Sign In:

1. Abort/invalidate any previous attempt.
2. Create an `AbortController` and monotonically increasing attempt ID.
3. Call one package method:

   ```ts
   auth.loginWithDeviceCode({
       signal,
       onVerification(authorization) {
           // display code, open URL, then return so package polling begins
       }
   })
   ```

4. In `onVerification`, transition to the prominent code/waiting view and call `WindowParentBridge.openWindow(verificationUrl, "_blank")`.
5. When the promise resolves, encode the token store's complete credentials into the active draft `apiKey`, mark the credential intent as replace, and display signed-in state.
6. There is no Complete button. A Cancel sign-in action is permitted and should abort/ignore the attempt.

Because `LogseqHttpProxy` may not terminate an in-flight host request, every callback/completion must also compare its attempt ID and check `signal.aborted`. Late buffered completion after cancellation, logout, provider switch, deletion, modal close, or unmount must not modify state.

#### Presentation and accessibility

- Signed out: use a larger primary CTA (`LogseqButton` `size="lg"` or a specialized semantic button if additional ARIA props are needed), with the bundled Tabler `brand-openai.svg?raw` icon and label “Sign in with Codex Subscription”.
- Starting: show an accessible starting status.
- Awaiting verification:
  - transition the auth panel content without destabilizing the full modal layout;
  - show `userCode` in large, selectable, high-contrast monospace text;
  - show the verification URL and a spinner (`Loader2`/`LoaderCircle`, `animate-spin motion-reduce:animate-none`);
  - use `role="status"`, `aria-live="polite"`, and `aria-busy="true"`;
  - include a Cancel sign-in action, not a completion action.
- Signed in: replace Sign In with “Signed in to Codex Subscription”, optional safe plan metadata, and a clearly labeled Logout action.
- Error: show sanitized actionable text and Retry; do not expose token/parser/network response bodies.
- On success/error, manage focus so keyboard/screen-reader users reach the new status/action.

#### Disabled API key field

For Codex, render the existing API key field disabled with:

- `value=""` regardless of the actual draft credential value;
- placeholder such as “Managed by Codex Subscription sign-in”;
- no encoded value in DOM attributes or React inputs.

For other providers, preserve current editable API-key behavior.

#### Draft Save/Cancel and refresh reconciliation

Track an editor-only credential intent: `unchanged`, `replace`, or `clear`.

- Loaded signed-in config starts `unchanged`.
- Successful device login becomes `replace`.
- Logout becomes `clear` and sets draft `apiKey = ""`.
- Save persists the draft through `ProviderConfigRepository`.
- Cancel writes nothing and restores persisted status on the next modal open.
- Subscribe to runtime credential-rotation events while the modal is open:
  - `unchanged` drafts adopt the latest rotated value without becoming dirty;
  - explicit `replace`/`clear` drafts win and ignore runtime events.
- Include OAuth busy state in modal busy handling. Prevent Save/provider switch/delete while login is active unless the operation first cancels the attempt.
