## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

**Q1: Package choice — `@ai-sdk/sandbox-just-bash` vs `just-bash` directly?**
Research finding: `@ai-sdk/sandbox-just-bash` calls just-bash's `Sandbox.create()`, but `Sandbox` is NOT exported from just-bash's browser bundle (verified in `dist/browser.d.ts` — only `Bash`, `InMemoryFs`, `MountableFs`, `IFileSystem`, etc. are). It also requires Node >= 22, pins just-bash 2.x, and pulls in `@ai-sdk/harness` (which drags a nested copy of `ai@7.0.58`). Since the plugin runs in a browser/electron environment, `createJustBashSandbox` would fail to bundle/run.
**A1:** Use `just-bash` (v3) directly: `new Bash({fs, cwd: "/home/user", python: false, javascript: false})`. `BashOptions` supports exactly the config flags requested. Vite auto-resolves just-bash's `browser` export condition for the plugin build; vitest (Node) uses the node build.

**Q2: How should BashTool be registered in ChatToolRegistry?**
**A2:** Always registered under the `MISC` toolkit (like `SkillTool`/`GetUserInfoTool`) — no settings toggle. The sandbox has no host access, so it is safe.

**Q3: How should BashTool return command output?**
**A3:** Inline, no truncation — return `{stdout, stderr, exitCode}` raw in the tool result.

### 2.2 Final Summarized Requirements

1. New module `src/core/just-bash-wrapper/`, decomposed for maintainability (class files PascalCase; helpers in a `utils/` subfolder with descriptive camelCase names — matching the existing `src/core/logseq-reversible-transaction-tracker/commands/utils/` convention) with a barrel `index.ts`:
   - `index.ts` — barrel exporting `JustBashAdapterFS`, `JustBashWrapper`, `JustBashMountPermission`, `JUST_BASH_USER_HOME`.
   - `types.ts` — shared types/constants: `JustBashMountPermission` (`"read" | "readwrite"`), `JUST_BASH_USER_HOME` (`"/home/user"`).
   - `JustBashAdapterFS.ts` — thin just-bash `IFileSystem` implementation backed by `LogseqPluginStorageManager` (one instance = one storage group = one flat virtual directory); static mount registry with `addLogseqPluginFolder(folderName, permission)`; module bottom registers `ToolResultStore.groupName` ("tool-results") with `"read"`; mounts resolve to `/home/user/<folderName>`. All low-level concerns are delegated to the `utils/` helpers below.
   - `JustBashWrapper.ts` — singleton returning a shared `Bash` instance created with `cwd: "/home/user"`, `python: false`, `javascript: false`, and a `MountableFs` (base `InMemoryFs` + registered mounts).
   - `utils/fsErrors.ts` — fs error factories following Node/just-bash message conventions.
   - `utils/fsPaths.ts` — posix path helpers built on the `path-browserify` lib.
   - `utils/fsContent.ts` — file content (en/de)coding helpers built on the `buffer` lib.
2. New tool `src/chat-app/tools/impl/BashTool.tsx` following the existing `BaseChatToolWithDefaultUI` class pattern; zod params: `command` (required string), `cwd` (optional string); always registered under `ToolkitEnum.MISC`; returns `{stdout, stderr, exitCode}` inline without truncation.
3. Minimal `LogseqPluginStorageManager` additions: a `fileExists(group, fileName)` helper (via `IAsyncStorage.hasItem`) and adding the missing `validateOperation` call to `deleteFile` (consistency fix). All other needed methods (`getFiles`, `getFileContent`, `saveFile`) already exist.
4. Dependencies: add `just-bash` (v3.x); promote `path-browserify` and `buffer` from devDependencies to dependencies (both already in the lockfile at `^1.0.1` / `^6.0.3`). NOTE: `node:` builtin imports are intentionally avoided in `src/` (current codebase convention), which is why the browser-safe libs are used directly.
5. Unit tests mirroring `tests/` structure; type-check, tests, build, and biome must pass.

## 3. Solution

### 3.1 Dependencies

- `pnpm add just-bash` (v3.x, currently 3.2.0) and promote `path-browserify` + `buffer` to `dependencies` (same versions already in devDependencies).
- Verified: just-bash's package root export has a `"browser"` condition (`dist/bundle/browser.js`) which Vite resolves automatically for the plugin build; it exports `Bash`, `InMemoryFs`, `MountableFs`, and the `IFileSystem` type. `OverlayFs`/`ReadWriteFs`/`Sandbox` are Node-only and not used.
- The just-bash browser bundle has external imports (`undici`, `node:zlib`, `diff`, `minimatch`, `sprintf-js`, `turndown`, `seek-bzip`). `node:zlib` is covered by the existing `vite-plugin-node-polyfills()` in `vite.config.ts`; the rest are plain npm deps installed with just-bash. Network commands are disabled by default in just-bash, so `undici` code paths are never exercised at runtime. `pnpm build` (verification step 4) validates bundling.

### 3.2 Module structure: `src/core/just-bash-wrapper/`

```
src/core/just-bash-wrapper/
├── index.ts                — barrel exports
├── types.ts                — JustBashMountPermission, JUST_BASH_USER_HOME
├── JustBashAdapterFS.ts    — thin IFileSystem class + static mount registry + default mount
├── JustBashWrapper.ts      — singleton
└── utils/
    ├── fsErrors.ts         — Node-style fs error factories
    ├── fsPaths.ts          — posix path helpers (path-browserify)
    └── fsContent.ts        — content encoding helpers (buffer)
```

just-bash's `MountableFs` strips the mount prefix before delegating (verified from source: `routePath()` forwards `relativePath` = `/` or `/<fileName>`), so the adapter only ever handles paths relative to its mount root. The backing store is flat (`group/fileName` keys; slashes rejected by `LogseqPluginStorageManager.validateOperation`), so the adapter exposes a **flat single-level virtual directory**: `/` = group root, `/<fileName>` = a file; nested paths are rejected.

#### `utils/fsPaths.ts` (new)

Path logic delegated to the `path-browserify` lib (posix semantics; already in the lockfile):

```ts
import path from "path-browserify";
import {enotsupError} from "./fsErrors";

/** Resolve a sandbox path against a base, returning a normalized absolute posix path. */
export function resolveSandboxPath(base: string, targetPath: string): string {
    return path.normalize(path.resolve(base, targetPath));
}

/**
 * Map a normalized sandbox path (relative to the mount root) to a storage fileName.
 * Returns null for the mount root itself; throws ENOTSUP for nested paths
 * (Logseq plugin storage groups are flat).
 */
export function toStorageFileName(resolvedPath: string): string | null {
    if (resolvedPath === "/") return null;
    const fileName = resolvedPath.slice(1);
    if (fileName.includes("/")) throw enotsupError("access", resolvedPath);
    return fileName;
}
```

#### `utils/fsContent.ts` (new)

```ts
import {Buffer} from "buffer";
import type {BufferEncoding, FileContent, ReadFileOptions, WriteFileOptions} from "just-bash";

/** Re-encode stored utf8 text into the encoding requested by readFile options. */
export function encodeStoredText(text: string, options?: ReadFileOptions | BufferEncoding): string {
    const encoding = typeof options === "string" ? options : options?.encoding;
    if (encoding == null || encoding === "utf8" || encoding === "utf-8") return text;
    return Buffer.from(text, "utf8").toString(encoding);
}

/** Convert IFileSystem write content (string | Uint8Array) to storable utf8 text. */
export function toStorableText(content: FileContent, _options?: WriteFileOptions | BufferEncoding): string {
    return typeof content === "string" ? content : new TextDecoder().decode(content);
}
```

#### `JustBashAdapterFS.ts` (new)

Thin `IFileSystem` class: static mount registry (per requirement) + instance methods that delegate path/encoding/error concerns to the helpers above and persistence to `LogseqPluginStorageManager`. Each method body is 1–5 lines.

```ts
import type {
    BufferEncoding, CpOptions, DirentEntry, FileContent, FsStat,
    IFileSystem, MkdirOptions, ReadFileOptions, RmOptions, WriteFileOptions
} from "just-bash";
import {ToolResultStore} from "src/core/stores/tool-results/ToolResultStore";
import {LogseqPluginStorageManager} from "src/logseq/LogseqPluginStorageManager";
import {encodeStoredText, toStorableText} from "./utils/fsContent";
import {
    eexistError, einvalError, eisdirError, enoentError,
    enotdirError, enotsupError, erofsError
} from "./utils/fsErrors";
import {resolveSandboxPath, toStorageFileName} from "./utils/fsPaths";
import {JUST_BASH_USER_HOME, type JustBashMountPermission} from "./types";

/**
 * just-bash IFileSystem adapter over a single Logseq plugin storage group.
 * Exposes the flat group as a single-level directory; mounted by JustBashWrapper
 * at /home/user/<folderName> via MountableFs.
 */
export class JustBashAdapterFS implements IFileSystem {
    private static readonly mountRegistry = new Map<string, JustBashMountPermission>();

    /** Register a Logseq plugin storage folder for mounting at /home/user/<folderName>. */
    static addLogseqPluginFolder(folderName: string, permission: JustBashMountPermission): void {
        if (!folderName || folderName.includes("/") || folderName === "." || folderName === "..")
            throw new Error(`Invalid Logseq plugin folder name for just-bash mount: "${folderName}"`);
        JustBashAdapterFS.mountRegistry.set(folderName, permission); // re-adding replaces permission
    }

    /** Consumed by JustBashWrapper to build MountableFs mounts. */
    static getMountConfigs(): Array<{mountPoint: string; filesystem: JustBashAdapterFS}> {
        return [...JustBashAdapterFS.mountRegistry.entries()].map(([folderName, permission]) => ({
            mountPoint: `${JUST_BASH_USER_HOME}/${folderName}`,
            filesystem: new JustBashAdapterFS(folderName, permission)
        }));
    }

    constructor(
        private readonly groupName: string,
        private readonly permission: JustBashMountPermission
    ) {}

    /** Best-effort listing cache for the synchronous getAllPaths() (glob support). */
    private cachedFileNames = new Set<string>();

    // ---------------- private helpers ----------------

    private assertWritable(op: string, path: string): void {
        if (this.permission === "read") throw erofsError(op, path);
    }

    private dirStat(): FsStat {
        return {
            isFile: false, isDirectory: true, isSymbolicLink: false,
            mode: this.permission === "read" ? 0o40555 : 0o40777,
            size: 0, mtime: new Date(0)
        };
    }

    private fileStat(content: string): FsStat {
        return {
            isFile: true, isDirectory: false, isSymbolicLink: false,
            mode: this.permission === "read" ? 0o100444 : 0o100666,
            size: new TextEncoder().encode(content).length, mtime: new Date(0)
        };
    }

    /** Reads raw stored text for an existing file; throws ENOENT otherwise. */
    private async readStoredText(path: string, op: string): Promise<string> {
        const fileName = toStorageFileName(resolveSandboxPath("/", path));
        if (fileName == null) throw eisdirError(op, path);
        const content = await LogseqPluginStorageManager.getFileContent(this.groupName, fileName);
        if (content === undefined) throw enoentError(op, path);
        return content;
    }

    /** Persists text and keeps the listing cache in sync. */
    private async storeText(path: string, text: string, op: string): Promise<void> {
        const fileName = toStorageFileName(resolveSandboxPath("/", path));
        if (fileName == null) throw eisdirError(op, path);
        await LogseqPluginStorageManager.saveFile(this.groupName, fileName, text);
        this.cachedFileNames.add(fileName);
    }

    // ---------------- IFileSystem: reads ----------------

    async readFile(path: string, options?: ReadFileOptions | BufferEncoding): Promise<string> {
        return encodeStoredText(await this.readStoredText(path, "open"), options);
    }

    async readFileBuffer(path: string): Promise<Uint8Array> {
        return new TextEncoder().encode(await this.readStoredText(path, "open"));
    }
    // readFileBytes (optional) intentionally omitted: MountableFs falls back to readFileBuffer.

    async exists(path: string): Promise<boolean> {
        const resolved = resolveSandboxPath("/", path);
        const fileName = toStorageFileName(resolved); // null === root
        if (fileName == null) return true;
        return LogseqPluginStorageManager.fileExists(this.groupName, fileName);
    }

    async stat(path: string): Promise<FsStat> {
        const resolved = resolveSandboxPath("/", path);
        if (toStorageFileName(resolved) == null) return this.dirStat();
        return this.fileStat(await this.readStoredText(resolved, "stat"));
    }

    async lstat(path: string): Promise<FsStat> {
        return this.stat(path); // no symlinks exist in this fs
    }

    async realpath(path: string): Promise<string> {
        const resolved = resolveSandboxPath("/", path);
        if (!(await this.exists(resolved))) throw enoentError("realpath", path);
        return resolved;
    }

    async readdir(path: string): Promise<string[]> {
        if (toStorageFileName(resolveSandboxPath("/", path)) != null)
            throw enotdirError("scandir", path);
        const fileNames = await LogseqPluginStorageManager.getFiles(this.groupName);
        this.cachedFileNames = new Set(fileNames);
        return fileNames;
    }

    async readdirWithFileTypes(path: string): Promise<DirentEntry[]> {
        return (await this.readdir(path)).map((name) => ({
            name, isFile: true, isDirectory: false, isSymbolicLink: false
        }));
    }

    resolvePath(base: string, path: string): string {
        return resolveSandboxPath(base, path); // sync by contract
    }

    /** Sync by contract; interface explicitly permits unsupported/empty. Best-effort via cache. */
    getAllPaths(): string[] {
        return ["/", ...[...this.cachedFileNames].map((name) => `/${name}`)];
    }

    // ---------------- IFileSystem: writes (permission-gated) ----------------

    async writeFile(path: string, content: FileContent, options?: WriteFileOptions | BufferEncoding): Promise<void> {
        this.assertWritable("open", path);
        const fileName = toStorageFileName(resolveSandboxPath("/", path));
        if (fileName == null) throw eisdirError("open", path);
        await LogseqPluginStorageManager.saveFile(this.groupName, fileName, toStorableText(content, options));
        this.cachedFileNames.add(fileName);
    }

    async appendFile(path: string, content: FileContent, options?: WriteFileOptions | BufferEncoding): Promise<void> {
        this.assertWritable("append", path);
        const fileName = toStorageFileName(resolveSandboxPath("/", path));
        if (fileName == null) throw eisdirError("append", path);
        const existing = (await LogseqPluginStorageManager.getFileContent(this.groupName, fileName)) ?? "";
        await LogseqPluginStorageManager.saveFile(this.groupName, fileName, existing + toStorableText(content, options));
        this.cachedFileNames.add(fileName);
    }

    async rm(path: string, options?: RmOptions): Promise<void> {
        this.assertWritable("rm", path);
        const fileName = toStorageFileName(resolveSandboxPath("/", path));
        if (fileName == null) { // mount root
            if (!options?.recursive) throw eisdirError("rm", path);
            for (const name of await LogseqPluginStorageManager.getFiles(this.groupName))
                await LogseqPluginStorageManager.deleteFile(this.groupName, name);
            this.cachedFileNames.clear();
            return;
        }
        if (!(await LogseqPluginStorageManager.fileExists(this.groupName, fileName))) {
            if (options?.force) return;
            throw enoentError("rm", path);
        }
        await LogseqPluginStorageManager.deleteFile(this.groupName, fileName);
        this.cachedFileNames.delete(fileName);
    }

    async cp(src: string, dest: string, _options?: CpOptions): Promise<void> {
        this.assertWritable("cp", dest);
        await this.writeFile(dest, await this.readStoredText(src, "cp"));
    }

    async mv(src: string, dest: string): Promise<void> {
        this.assertWritable("mv", dest);
        const srcName = toStorageFileName(resolveSandboxPath("/", src));
        await this.cp(src, dest);
        if (srcName != null) {
            await LogseqPluginStorageManager.deleteFile(this.groupName, srcName);
            this.cachedFileNames.delete(srcName);
        }
    }

    async mkdir(path: string, options?: MkdirOptions): Promise<void> {
        if (toStorageFileName(resolveSandboxPath("/", path)) == null) {
            if (options?.recursive) return; // root always exists
            throw eexistError("mkdir", path);
        }
        this.assertWritable("mkdir", path);
        throw enotsupError("mkdir (subdirectories are not supported in mounted Logseq plugin folders)", path);
    }

    // ---------------- IFileSystem: metadata / links ----------------

    async chmod(path: string, _mode: number): Promise<void> {
        if (!(await this.exists(path))) throw enoentError("chmod", path);
        // no-op: virtual fs has no permission metadata
    }

    async utimes(path: string, _atime: Date, _mtime: Date): Promise<void> {
        if (!(await this.exists(path))) throw enoentError("utimes", path);
        // no-op: storage exposes no timestamps
    }

    async symlink(_target: string, linkPath: string): Promise<void> {
        throw enotsupError("symlink", linkPath);
    }

    async link(_existingPath: string, newPath: string): Promise<void> {
        throw enotsupError("link", newPath);
    }

    async readlink(path: string): Promise<string> {
        throw einvalError("readlink", path);
    }
}

// Default mounts (side effect, per requirement):
JustBashAdapterFS.addLogseqPluginFolder(ToolResultStore.groupName, "read");
```

(The sketch above shows the delegation structure; `storeText`/`readStoredText` will be consolidated during implementation so there is exactly one private read helper and one private write helper — the goal is that no public method contains path math, encoding logic, or error-string building.)

#### `JustBashWrapper.ts` (new)

Singleton over a shared `Bash` instance. just-bash isolates per-`exec` shell state (env/cwd/functions reset between calls) while the filesystem persists — exactly the session semantics wanted here.

```ts
import {Bash, InMemoryFs, MountableFs} from "just-bash";
import {JustBashAdapterFS} from "./JustBashAdapterFS";
import {JUST_BASH_USER_HOME} from "./types";

/**
 * Singleton accessor for the shared just-bash sandbox instance used by chat tools.
 * The sandbox is fully virtual (no host access); python and javascript are disabled.
 */
export class JustBashWrapper {
    private static instance: Bash | null = null;

    static getInstance(): Bash {
        if (JustBashWrapper.instance == null) {
            JustBashWrapper.instance = new Bash({
                fs: new MountableFs({
                    base: new InMemoryFs(),
                    mounts: JustBashAdapterFS.getMountConfigs()
                }),
                cwd: JUST_BASH_USER_HOME,
                python: false,
                javascript: false
            });
        }
        return JustBashWrapper.instance;
    }

    /** Test hook: drop the singleton so mount/storage changes take effect. */
    static resetInstanceForTesting(): void {
        JustBashWrapper.instance = null;
    }
}
```

- Sync getter is sufficient: `Bash`'s constructor is synchronous, and `LogseqPluginStorageManager.init()` has already run at plugin startup (long before any tool executes).
- `MountableFs` constructor accepts initial `mounts` (`MountConfig[]`), so no post-construction `mount()` calls are needed.
- No import cycle: `BashTool` → `JustBashWrapper` → `JustBashAdapterFS` → (`ToolResultStore`, `LogseqPluginStorageManager`, helpers).

### 3.4 `src/chat-app/tools/impl/BashTool.tsx` (new)

Follows the existing tool-class pattern (`GetUserInfoTool`/`WebSearchTool` style: static `NAME`, zod `parameters`, `ChatToolResponse.success/error`, `getErrorMessageFromErrObj`); imports the wrapper via the new module barrel:

```tsx
import {BaseChatToolWithDefaultUI} from "src/chat-app/tools/base/BaseChatToolWithDefaultUI";
import type {ChatToolExecutionContext} from "src/chat-app/tools/base/BaseChatTool";
import {
    type ChatToolErrorResult,
    ChatToolResponse,
    type ChatToolSuccessResult
} from "src/chat-app/tools/base/ChatToolResponse";
import {getErrorMessageFromErrObj} from "src/chat-app/utils/getErrorMessageFromErrObj";
import {JustBashWrapper} from "src/core/just-bash-wrapper";
import {z} from "zod";

const bashToolParameters = z.object({
    command: z.string().describe("The bash command to execute in the sandbox."),
    cwd: z.string().optional().describe(
        "Absolute working directory inside the sandbox for this command. Defaults to /home/user."
    )
});

type BashToolArgs = z.infer<typeof bashToolParameters>;

type BashToolResult =
    | ChatToolSuccessResult<{stdout: string; stderr: string; exitCode: number}>
    | ChatToolErrorResult;

export class BashTool extends BaseChatToolWithDefaultUI<BashToolArgs, BashToolResult> {
    static readonly NAME = "bash";

    readonly name = BashTool.NAME;
    readonly description =
        "Run a bash command in an isolated sandbox shell with a virtual filesystem " +
        "(no access to the host system; python and javascript execution are disabled). " +
        "Files under /home/user persist between commands. Previously stored tool results " +
        "are mounted read-only at /home/user/tool-results.";
    readonly parameters = bashToolParameters;

    async execute(
        {command, cwd}: BashToolArgs,
        context?: ChatToolExecutionContext
    ): Promise<ChatToolResponse<BashToolResult>> {
        try {
            const bash = JustBashWrapper.getInstance();
            const {stdout, stderr, exitCode} = await bash.exec(command, {
                cwd,
                signal: context?.abortSignal
            });
            return ChatToolResponse.success({stdout, stderr, exitCode});
        } catch (err) {
            return ChatToolResponse.error(
                `Failed to execute bash command: ${getErrorMessageFromErrObj(err)}`
            );
        }
    }
}
```

Behavior notes:
- A non-zero exit code is a **success** tool result carrying `exitCode`/`stderr` (the tool itself ran fine; the LLM needs the output to react). Only unexpected exceptions become `ChatToolResponse.error`.
- No output truncation (per user decision).
- `ExecOptions.cwd` is per-exec (just-bash resets cwd between calls), which matches the optional `cwd` param semantics. An invalid `cwd` surfaces as a thrown error → error result.
- `context.abortSignal` is forwarded to `bash.exec` so chat cancellation aborts running commands.
