## 2. Final Requirement After Discussion With User

### 2.1 Clarification Q&A

- **Which prompt files become commands?** Only dedicated `COMMAND_*.md` files. Existing system and skill prompts remain unchanged.
- **What does a missing `user-invocable` mean?** Follow Skill Editor behavior: commands are enabled unless explicitly disabled (`user-invocable: false`).
- **When is a built-in command user-controllable?** Only when `built-in-command-user-controllable: true`; missing or false locks the enabled checkbox.
- **What context is used by native Logseq invocation routes?** A block slash command attaches its callback block. A Logseq Command Center invocation has no attachment. Both render the prompt, obey the thread flag, open chat, and do not send.
- **Was the second flashcard note intended to describe video detection?** Yes. Implement separate flashcard and video block utilities.
- **Fallback labels?** Use `Other Blocks` and `Other Pages`.
- **Can built-in invoke conditions be edited?** No. Built-in source, invoke conditions, and new-thread behavior remain read-only; only the enabled checkbox may be changed when explicitly user-controllable.
- **What happens to an existing composer draft?** Replace the entire draft: clear text and attachments before applying the selected command.
- **When do native registration edits take effect?** Newly added, renamed, enabled/disabled, or rerouted Command Center and slash commands require plugin reload because Logseq exposes no documented unregister API. Context-menu palettes read current storage and update on their next opening.
- **Are command names unique?** Yes, case-insensitively. The name is also the storage filename stem and native Logseq label.
- **How are disabled commands presented?** `user-invocable: false` commands are hidden from palettes and skipped during native registration.

### 2.2 Final Summarized Requirements

1. Add a storage-backed command-file domain parallel to skills, with dedicated parsing, validation, body-only Mustache rendering, built-in initialization, and a `commands` storage group.
2. Use this frontmatter contract:
   - required `name: string`;
   - required non-empty `invoke-condition: CommandInvokeCondition[]`;
   - optional `user-invocable: boolean`, default `true`;
   - optional `command-invoke-in-new-thread: boolean`, default `true`;
   - optional `built-in-command: boolean`;
   - optional `built-in-command-user-controllable: boolean`.
3. Add an immutable built-in `Add as attachment` command with an empty body, all nine block/page context-menu leaf conditions, `command-invoke-in-new-thread: false`, and a locked-enabled state so it remains available and sorts first.
4. Replace both existing `Add to AI Chat` context items with `Invoke AI Command`. Resolve the clicked entity to exactly one context condition, open a searchable command palette, and invoke the selected matching command.
5. Invocation must preflight the command/template/attachment, optionally switch to a new thread, clear the target composer completely, add the context attachment when applicable, set the rendered command body, reveal chat, and never submit automatically.
6. Register enabled commands configured for native Command Center or block slash invocation at startup. Slash invocation attaches its block; Command Center invocation does not attach an entity.
7. Add a Command Editor toolbar item and Skill Editor-style modal. The editor controls `user-invocable` and `invoke-condition`, validates all command files, protects built-ins, and exposes invoke conditions through an accessible hierarchical checkbox popover.
8. Use the existing `cmdk`/shadcn command primitives and `UI.showModal`; do not import `neigebaie/shadcn-ui-tree-view` unchanged. Its animation/context-menu/hover dependencies and mouse-oriented/global-document behavior are excessive for a fixed two-level selection tree.
9. Use the installed public Logseq API `logseq.App.registerCommandPalette` (or its equivalent `registerCommand` palette form) for Command Center registration. The requested `registerSimpleCommand` method is not present in the installed `@logseq/libs` typings.

Keep `"string-array"` command-specific unless extracting a generic frontmatter validator clearly reduces duplication without weakening skill typing. Array validation should report the relevant key/item range, not only the opening delimiter:

```ts
function validateInvokeConditions(value: unknown): CommandFileValidationIssue[] {
    if (!Array.isArray(value) || value.length === 0) {
        return [issueAtKey("invoke-condition", "invoke-condition must contain at least one value")];
    }

    const seen = new Set<string>();
    const issues: CommandFileValidationIssue[] = [];
    for (const condition of value) {
        if (
            typeof condition !== "string" ||
            !COMMAND_INVOKE_CONDITIONS.has(condition as CommandInvokeCondition)
        ) {
            issues.push(issueAtArrayValue(condition, `Unsupported invoke condition: ${String(condition)}`));
            continue;
        }
        if (seen.has(condition)) {
            issues.push(issueAtArrayValue(condition, `Duplicate invoke condition: ${condition}`));
        }
        seen.add(condition);
    }
    return issues;
}
```

### 4.2 Add the command file store

Create:

- `src/core/stores/command-file-store/types.ts` with `CommandFileData` containing normalized defaults plus original `content`.
- `src/core/stores/command-file-store/CommandFileStore.ts` with `groupName = "commands"`, filename derivation, get-one, get-all, save, and delete methods mirroring `SkillFileStore`.

Store complete source as `commands/<name>.md`, list commands sorted by name, log and skip malformed files, and return `null` for an unreadable single file. Keep editor-level built-in deletion/edit protection consistent with the established Skill Editor. Every palette/native callback must re-read storage rather than rely on stale startup objects.

Follow the established store API so callers cannot save or retrieve a command without parser validation:

```ts
export class CommandFileStore {
    static readonly groupName = "commands";

    static getCommandFileName(command: Pick<CommandFileData, "name">): string {
        return `${command.name}.md`;
    }

    static getCommandFileNameFromContent(content: string): string {
        return this.getCommandFileName(parseCommandFile(content));
    }

    static async getCommandFile(fileName: string): Promise<CommandFileData | null> {
        try {
            const source = await LogseqPluginStorageManager.getFileContent(this.groupName, fileName);
            return parseCommandFile(source);
        } catch (error) {
            logger.warn(`Failed to load command file ${fileName}`, error);
            return null;
        }
    }

    static getCommandFileByName(name: string): Promise<CommandFileData | null> {
        return this.getCommandFile(this.getCommandFileName({name}));
    }

    static async saveCommandFile(content: string): Promise<void> {
        const fileName = this.getCommandFileNameFromContent(content);
        await LogseqPluginStorageManager.saveFile(this.groupName, fileName, content);
    }
}
```

Do not introduce Zustand solely for this domain. The editor owns unsaved state locally like Skill Editor; every short-lived context palette reloads storage when opened. This gives immediate behavior after Save without maintaining two sources of truth.

Handle external/manual storage edits deterministically:

- Log and skip malformed files while listing, including their physical filenames.
- Preserve the physical filename as each editor entry's `originalFileName`; saving a valid changed `name` performs delete-then-save rename semantics.
- Reject all logical duplicate names case-insensitively before the first storage mutation.
- Let a valid physical filename/content-name mismatch appear in the editor and repair it on Save.
- Do not silently swallow save failures. As with Skill Editor, report that the current multi-file save is non-transactional if a later operation fails.

### 4.4 Classify invocation contexts exactly once

Add:

Block precedence:

1. Reject/exclude an entity that `LogseqEditor.isPageBlock` identifies as a page.
2. Image asset.
3. PDF asset.
4. Video macro.
5. Flashcard.
6. Other Blocks.

Page precedence:

1. Tag.
2. Property.
3. Journal (`getJournalDayByPageUuid(uuid) !== null`).

This makes every context bucket mutually exclusive. Resolve page-menu names to page entities before classification. Missing entities show an error and abort. A journal query failure should be logged and surfaced rather than silently misclassifying a journal as `Other Pages`.

Keep macro detection pure and independently testable. Read only string block content and tolerate incomplete entities:

```ts
const CARD_TAG_PATTERN = /(^|\s)#card(?=$|\s|[.,;:!?()[\]{}])/iu;
const CLOZE_MACRO_PATTERN = /\{\{\s*cloze(?:\s+|,)[\s\S]*?\}\}/iu;
const VIDEO_MACRO_PATTERN = /\{\{\s*video(?:\s+|,)[\s\S]*?\}\}/iu;

export function isFlashcardBlock(block: Pick<BlockEntity, "content">): boolean {
    const content = typeof block.content === "string" ? block.content : "";
    return CARD_TAG_PATTERN.test(content) || CLOZE_MACRO_PATTERN.test(content);
}

export function isVideoBlock(block: Pick<BlockEntity, "content">): boolean {
    const content = typeof block.content === "string" ? block.content : "";
    return VIDEO_MACRO_PATTERN.test(content);
}
```

The exact regex should be finalized against real DB graph samples, with tests for case, commas/whitespace, multiline macros, and near misses. The classifier returns source, condition, and UUID so downstream code does not infer context again:

```ts
async function classifyBlockContext(uuid: string): Promise<BlockCommandInvocationContext> {
    const entity = await logseq.Editor.getBlock(uuid);
    if (!entity) throw new Error(`Block not found: ${uuid}`);
    if (await LogseqEditor.isPageBlock(entity)) {
        throw new Error("Page entities are excluded from block command contexts.");
    }

    const condition: BlockContextCondition = LogseqEditor.isImageAssetBlock(entity)
        ? "Block Context Menu/Image"
        : LogseqEditor.isPdfAssetBlock(entity)
          ? "Block Context Menu/Pdf"
          : isVideoBlock(entity)
            ? "Block Context Menu/Video"
            : isFlashcardBlock(entity)
              ? "Block Context Menu/Flashcard"
              : "Block Context Menu/Other Blocks";

    return {source: "block-context-menu", condition, uuid};
}

async function classifyPageContext(pageName: string): Promise<PageCommandInvocationContext> {
    const page = await logseq.Editor.getPage(pageName);
    if (!page?.uuid) throw new Error(`Page not found: ${pageName}`);

    let condition: PageContextCondition;
    if (await LogseqEditor.isTagBlock(page)) condition = "Page Context Menu/Tag";
    else if (await LogseqEditor.isPropertyBlock(page)) condition = "Page Context Menu/Property";
    else if ((await getJournalDayByPageUuid(page.uuid)) !== null) {
        condition = "Page Context Menu/Journal";
    } else condition = "Page Context Menu/Other Pages";

    return {source: "page-context-menu", condition, uuid: page.uuid};
}
```

`InvokeAICommand.execute()` enqueues one `invoke-ai-command` item, then calls `OpenAIChatCommand`. Keeping the whole operation in one queue item prevents another invocation from interleaving between thread switch, draft reset, attachment, and text setup.

Update `src/chat-app/hooks/useChatCommandHandler.ts` to execute this transaction in order:

1. Reload by command name and verify it still exists, is enabled, and still contains the invoked condition (stale native callbacks become safe no-ops with a user-facing warning).
2. Render the command body and resolve/create the attachment before destructive composer changes; if preflight fails, preserve the user's existing draft and report the error.
3. If `commandInvokeInNewThread` is true, await `aui.threads().switchToNewThread()`.
4. Call `aui.composer().reset()` on the target composer, clearing its text, attachments, role/run config, and quote. For same-thread commands this resets the current composer; for new-thread commands it runs after switching so the destination draft is cleared.
5. Add the prepared attachment for block/page/slash contexts. Command Center has none.
6. Call `aui.composer().setText(renderedBody)`, including `""` for `Add as attachment`.
7. Never call composer/thread send or append APIs.

Extract the high-level execution from the React subscription when useful for testing. Preflight rendering and attachment creation before changing thread/composer state:

```ts
async function executeAICommandInvocation(
    aui: AssistantClient,
    payload: InvokeAICommandPayload
): Promise<void> {
    const command = await CommandFileStore.getCommandFileByName(payload.commandName);
    if (!command || !command.userInvocable) {
        throw new UserVisibleCommandError(`Command is no longer available: ${payload.commandName}`);
    }
    if (!command.invokeConditions.includes(payload.context.condition)) {
        throw new UserVisibleCommandError("This command is no longer enabled for this route.");
    }

    const [renderedPrompt, attachment] = await Promise.all([
        renderCommandFileTemplate(command.content),
        "uuid" in payload.context
            ? createLogseqAttachmentFromUuid(payload.context.uuid)
            : Promise.resolve(null)
    ]);

    if (command.commandInvokeInNewThread) {
        await aui.threads().switchToNewThread();
    }

    const composer = aui.composer();
    composer.reset();
    if (attachment) await composer.addAttachment(attachment);
    composer.setText(renderedPrompt);
}
```

Do not reset the source thread before switching: “replace entire draft” applies to the target composer. If thread switching or preflight fails, preserve the source draft. If attachment/text application fails after reset, log command/context and show an error; assistant-ui does not provide a general atomic rollback, so leave any partially prepared draft visible for user recovery.

Keep queue FIFO/late-mount behavior, but update `ChatInteropCommandQueue` to select the active handler for each queued item, isolate handler failures so later items still run, and avoid dispatching subsequent items to an unsubscribed stale runtime. Add a test reset hook if needed rather than exposing mutable internals in production.

The loop should resolve a handler before each item and leave the next item queued if no runtime remains:

```ts
private static async flush(): Promise<void> {
    if (this.isFlushing) return;
    this.isFlushing = true;
    try {
        while (this.pendingCommands.length > 0) {
            const handler = this.getCurrentHandler();
            if (!handler) return;

            const command = this.pendingCommands[0];
            try {
                await handler(command);
            } catch (error) {
                logger.error("Failed to execute queued chat command", error);
            } finally {
                if (this.pendingCommands[0] === command) this.pendingCommands.shift();
            }
        }
    } finally {
        this.isFlushing = false;
        if (this.pendingCommands.length > 0 && this.getCurrentHandler()) void this.flush();
    }
}
```

Avoid duplicate reporting: the invocation executor throws typed errors; the runtime subscription logs once and shows expected user-facing failures; the queue catches only otherwise-unhandled handler rejection to preserve progress.
