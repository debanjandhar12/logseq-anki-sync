## 4. Solution

### A. Exact-source recursive-reference pattern in the main skill

Add `internal/RECURSIVE_PAGE_REFERENCE_BACKLINKS.ds`:

```clojure
[:find (pull ?b [:block/uuid :block/title])
 :in $ ?page-name %
 :where
 [?p :block/name ?page-name]
 (connected ?p ?b)
 [?b :block/title]]
```

Add `internal/RECURSIVE_PAGE_REFERENCE_BACKLINKS_RULES.edn`:

```clojure
[[(connected ?from ?to)
  [?to :block/refs ?from]]
 [(connected ?from ?to)
  [?intermediate :block/refs ?from]
  (connected ?intermediate ?to)]]
```

In `SKILL.md`, append a clearly named advanced pattern without renumbering existing sections. Inline both files using the existing include mechanism. Show ordered inputs: a quoted lowercase page name followed by the full rules vector encoded as a single EDN string. A concise JSON payload or explicit encoding explanation must make clear that the rules are not a separate unsupported tool field and not doubly EDN-quoted.

Explain only the new concept:

- `%` denotes the rules input and occupies a position in `:in`; `inputs` must match that order.
- Finds direct and transitive incoming `:block/refs` edges, not an undirected neighborhood and not automatic page-containment edges.
- Node-property references must not be assumed to become `:block/refs`; use a property-specific query for that relationship.
- Cycles/multiple paths can reach the same entity; do not imply paths or depth are returned. A target can be returned if a cycle reaches it; retain positive-length reachability semantics rather than silently excluding it.
- Narrow pulls reduce result size, not traversal cost. Start with a specific target; large connected graphs may still be expensive.
- Unknown target returns no rows. Use the direct backlink query when transitive traversal is unnecessary.

Do not expand the main file with other query bodies. Existing available-resource listing plus an on-demand examples README provides discovery without main-file bloat.

### B. On-demand example queries and parameter contracts

Add these raw query files under `examples/`:

1. `PAGE_MEMBERSHIP.ds`

```clojure
[:find (pull ?b [:block/uuid :block/title])
 :in $ ?page-name
 :where
 [?p :block/name ?page-name]
 [?b :block/page ?p]
 [?b :block/title]]
```

Input: lowercase page name encoded as EDN string. Includes nested blocks owned by the page, not just immediate children. Does not find external backlinks.

2. `PROPERTY_REVERSE_LOOKUP.ds`

```clojure
[:find (pull ?b [:block/uuid :block/title])
 :in $ ?property-ident ?page-name
 :where
 [?p :block/name ?page-name]
 [?b ?property-ident ?p]
 [?b :block/title]]
```

Inputs: discovered node/ref property ident, then quoted lowercase target page name. This intentionally addresses the company-page use case with an unambiguous page lookup rather than arbitrary duplicate display titles. Works with cardinality-one and cardinality-many node properties. Scalar properties require a different shape.

3. `RECURSIVE_CLASS_INHERITANCE.ds`

```clojure
[:find (pull ?b [:block/uuid :block/title])
 :in $ ?tag-title %
 :where
 [?target :block/title ?tag-title]
 (or-join [?b ?target]
   [?b :block/tags ?target]
   (and
     (subclass ?cls ?target)
     [?b :block/tags ?cls]))]
```

Add `examples/RECURSIVE_CLASS_INHERITANCE_RULES.edn`:

```clojure
[[(subclass ?child ?ancestor)
  [?child :logseq.property.class/extends ?ancestor]]
 [(subclass ?child ?ancestor)
  [?child :logseq.property.class/extends ?parent]
  (subclass ?parent ?ancestor)]]
```

Inputs: exact verified class/tag display title, then rules vector EDN string. This follows the successful transcript's `or-join` design and current title-based user-tag convention. Do not use `:db/id` as a datom or fabricate a Tag ident. Direct tags and arbitrary-depth subclasses count; unrelated classes do not. Discover/verify the target first when titles are ambiguous.

4. `STATUS_HISTORY.ds`, only after history validation gate passes:

```clojure
[:find ?history ?status-title ?timestamp
 :in $ ?block-uuid ?status-property
 :where
 [?b :block/uuid ?block-uuid]
 [?prop :db/ident ?status-property]
 [?history :logseq.property.history/property ?prop]
 [?history :logseq.property.history/block ?b]
 [?history :logseq.property.history/ref-value ?status]
 [?history :block/created-at ?timestamp]
 [?status :block/title ?status-title]]
```

Inputs: EDN UUID (`#uuid "..."`), then verified status ident (`:logseq.property/status`). Return history entity ID to retain distinct same-status/same-timestamp events. Rows have meaningful columns; do not flatten. Results are unordered: chronological display requires sorting by column 3 in caller code, not a native `:result-transform`. This demonstrates ref-valued status history, not a general scalar-property history query. `:block/created-at` here is event-record data, not a blanket claim about every DB entity timestamp.

Add `examples/README.md`, a concise resource index with each query's use case, ordered EDN input examples, output shape, rules-companion filename, and limitations. Include a provenance note with transcript dates/line ranges; avoid copying chatter or unverified claims. Explain that new examples are raw tool queries, while the unchanged alias example retains its legacy wrapper. No dependency on transcript being installed in the plugin.
