However, a better alternative exists now: @firecrawl/anydoc-wasm. We need to remove lamma cloud intregation and replace it with @firecrawl/anydoc-wasm. We will rename the lamma cloud store and name it anydoc store. We will completely change how our tool works with pdfs.

First, we will modify the store with better name. Aditionally, instead of using hashes as file name, we need to combine the hash plus page no. Should hash be hash of entire pdf or just that page? - I will leave this decision up to you. First, we will remove Read Pdf tool. Instead, we will add a parse pdf tool. It will accept similar params as before. However, limit will be set to 20 now and using src/constants.ts (something like CHAT_APP_AGENT_ANYDOC_MAX_PAGE_PARSE). The result will be sucess and result text will contain: "Parsed Pages stored in ${JUST_BASH_USER_HOME}/${new store.groupName} as: <comma seperated file list>

Next, we will mount the new store as read only to JustBashAdapterFS.

## 2. Final Requirement After Discussion With User

### Clarification Q&A

- Q: When should the local `parse_pdf` tool be registered after LlamaCloud settings are removed?
  A: Always register it; local parsing needs no provider setting or API key.
- Q: What should each parsed page store?
  A: Plain Markdown named `<pdfHash>-page-<pageNo>.md`.
- Q: What should happen to existing `llama-cloud-parse-results` data?
  A: Leave it orphaned. Do not read, migrate, mount, or delete it.
- Q: Should an existing AnyDoc page file be reused?
  A: Yes. Parse and store only requested pages whose deterministic files do not already exist.

### Final Summarized Requirements

- Remove all LlamaCloud SDK, settings, provider enum, tool behavior, source store code, and model-facing references.
- Add exact dependency `@firecrawl/anydoc-wasm@0.1.7`; retain `pdf-lib` for extracting requested pages.
- Replace model tool `read_pdf` with always-registered `parse_pdf`, preserving `pdfPath` and inclusive 1-based `pageNo: [start, end]` parameters.
- Enforce a 20-page inclusive limit through `CHAT_APP_AGENT_ANYDOC_MAX_PAGE_PARSE` in `src/constants.ts`.
- Hash the complete original PDF once with SHA-256. This is one linear pass over bytes already fetched into memory and is cheaper than separately hashing up to 20 generated page PDFs; PDF splitting and parsing should dominate runtime.
- Store each requested page as plain Markdown at `anydoc-parse-results/<fullPdfHash>-page-<pageNo>.md`. Reuse existing files and parse only misses.
- Return `ChatToolResponse.success({result})`, where `result` is `Parsed Pages stored in /home/user/anydoc-parse-results as: <comma-separated filenames>` in ascending requested-page order.
- Mount `anydoc-parse-results` read-only at `/home/user/anydoc-parse-results`; application code continues writing directly through `LogseqPluginStorageManager`.
- Load and initialize AnyDoc only after the first missing page is encountered. Reuse one initialization across later calls and concurrent requests.
- Initialize and run AnyDoc in the patched window context. Workers cannot be used because Logseq requires every fetch to pass through `LogseqHttpProxy`; accept synchronous main-thread conversion and keep each conversion bounded to one extracted page.
- Extend `LogseqHttpProxy` narrowly to preserve binary `.wasm` responses instead of requesting them as text, then pass the fetched bytes explicitly to AnyDoc's initializer.

## 3. Solution

### Dependencies And Settings Removal

- Update `package.json` and regenerate `pnpm-lock.yaml` with pnpm:
  - Remove `@llamaindex/llama-cloud`.
  - Add exact `@firecrawl/anydoc-wasm@0.1.7` because this new pre-1.0 parser and its emitted WASM asset are runtime-critical.
  - Keep `pdf-lib@1.17.1` for reliable page-range extraction before AnyDoc conversion.
- Remove `ContentParsingProviderEnum` from `src/core/ai-sdk/types.ts`.
- In `src/settings.ts`, remove `contentParsingProvider`, `llamaCloudApiKey`, the PDF parsing settings heading/provider/key schemas, and LlamaCloud key visibility styles/listeners. Persisted historical setting keys require no migration and will simply be ignored.
- Delete `src/core/stores/llama-cloud-parse-result-store/`. Do not perform runtime cleanup of its persisted storage group.

### Page Preparation And Identity

- Add `CHAT_APP_AGENT_ANYDOC_MAX_PAGE_PARSE = 20` to `src/constants.ts` and use it in both schema validation and the tool description/error.
- Add a small SHA-256 helper under `src/core/pdf/` that hashes the fetched original PDF bytes and returns lowercase hexadecimal.
- Simplify `src/core/pdf/PdfPageSplitter.ts`:
  - Keep actual document page-count validation and inclusive page extraction.
  - Return only `{pageNo, bytes}` for each generated one-page PDF.
  - Remove source filename generation and per-page hashes.
  - Continue using `PDFDocument.create({updateMetadata: false})` for deterministic page bytes and stable tests.
- Start the full-document hash and page splitting after fetch; they may run concurrently because both only read the source bytes.

### AnyDoc Store

- Replace the provider-specific store with `src/core/stores/anydoc-parse-result-store/AnyDocParseResultStore.ts`.
- Define `static readonly groupName = "anydoc-parse-results"`.
- Provide focused methods such as:
  - `getFileName(pdfHash, pageNo)` -> `<hash>-page-<pageNo>.md`.
  - `exists(pdfHash, pageNo)` using `LogseqPluginStorageManager.fileExists`.
  - `save(pdfHash, pageNo, markdown)` writing plain text and returning the filename.
- Validate method inputs sufficiently to ensure the flat storage filename cannot contain `/` and page numbers remain positive integers.
- Treat these files as cache plus model-readable output. Existing files are cache hits; no JSON wrapper, Llama items, legacy fallback, or migration is added.

### Lazy AnyDoc Parser And Binary WASM Loading

- Add `src/core/anydoc/AnyDocPdfParser.ts` as the single owner of `@firecrawl/anydoc-wasm` initialization and conversion, with an injectable `PdfMarkdownParser` interface for tool tests.
- Import the package's emitted WASM asset as a Vite URL (for example `@firecrawl/anydoc-wasm/anydoc_wasm_bg.wasm?url`) rather than allowing AnyDoc's default initializer to fetch implicitly.
- On the first `parsePage()` call only:
  1. Fetch that URL through patched `window.fetch`.
  2. Read the response as `ArrayBuffer`.
  3. Call AnyDoc's default initializer with `{module_or_path: wasmBytes}`. The package explicitly accepts `BufferSource`, so this prevents a second internal fetch.
- Hold one module-level initialization promise. Share it across concurrent first calls, reuse it after success, and clear it after rejection so a later request can retry. Merely starting the plugin, opening chat, building the registry, or serving only cached pages must not fetch or initialize WASM.
- After initialization, call synchronous `toMarkdownBytes(pageBytes, "pdf")` in the same window context. This is required because a Worker would not have the mandatory Logseq fetch patch. Keep pages sequential and retain the 20-page bound; document that one active page conversion cannot be interrupted and can briefly occupy the renderer.
- Update `src/logseq/LogseqHttpProxy.ts` so WASM GET requests use Logseq's binary/array-buffer `exper_request` response mode instead of the current hard-coded `returnType: "text"`. Preserve all existing text behavior for ordinary HTTP traffic and reconstruct a `Response` whose body is the returned binary bytes. Isolate response-type selection and binary normalization in small private helpers because Logseq IPC may serialize an `ArrayBuffer` as an array/view-like payload.
- If the host's binary mode returns an unsupported payload shape, fail with a focused WASM-load error rather than attempting to decode text as binary.
- Make parser loading/fetching injectable or resettable for tests so Vitest does not load the real 6.5 MB WASM asset.

### Parse PDF Tool

- Delete `src/chat-app/tools/impl/ReadPdfTool.tsx` and add `src/chat-app/tools/impl/ParsePdfTool.tsx`.
- Define model-facing name `parse_pdf` and preserve the current path validation, query/fragment support, positive integer tuple, ascending inclusive range, and actual document bounds validation.
- Describe that the tool parses at most 20 pages into Markdown files and that the returned files are readable with Bash.
- Execution flow:
  1. Resolve and fetch `pdfPath` through `WindowParentBridge.makeAssetUrl`, forwarding the abort signal.
  2. Hash the original PDF once and split the requested page range.
  3. Build every deterministic requested filename and check the AnyDoc store.
  4. If all files exist, return their names without loading or initializing AnyDoc.
  5. Sequentially parse only missing pages through the shared lazy parser, checking cancellation between pages. Collect parsed Markdown in memory first so a parse failure does not create a partially updated set.
  6. Save all successfully parsed misses as plain Markdown through the store. Storage has no transaction support, so a mid-save backend failure may still leave a subset; surface the filename/page in the error and rely on deterministic retries.
  7. Return all requested filenames, including cache hits, in ascending page order.
- Return only `ChatToolResponse.success({result: text})`, not page Markdown, so large document text is consumed through Bash rather than the generic tool-result truncation mechanism.
- Map AnyDoc codes (`unsupported`, `encrypted`, `malformed`, `resourceLimit`, `missingPart`) to concise page-specific errors; call out image-only/scanned PDFs as unsupported because AnyDoc does not provide OCR. Distinguish parser initialization failures and cancellation, and retain a path-qualified fallback error via `getErrorMessageFromErrObj`.

### Registration, Exports, And Bash Mount

- In `src/chat-app/tools/ToolRegistry.ts`, replace `ReadPdfTool` with `ParsePdfTool`, remove the content-provider condition/import, and register `ParsePdfTool` under `ToolkitEnum.PDF` unconditionally.
- In `src/chat-app/tools/index.ts`, replace the old export with `ParsePdfTool`.
- In `src/core/just-bash-wrapper/JustBashAdapterFS.ts`, register `AnyDocParseResultStore.groupName` with permission `"read"` at module load, alongside `ToolResultStore`. This ensures the mount exists before `JustBashWrapper` snapshots its mount configuration.
- Update `src/chat-app/tools/impl/BashTool.tsx` to tell the model that parsed PDF Markdown is read-only under `/home/user/anydoc-parse-results`, using `JUST_BASH_USER_HOME` and the store's `groupName` rather than duplicating path literals.
